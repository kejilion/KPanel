# Architecture summary — KPanel stable scoped audit run-10

## Product and principals

KPanel is a Linux server administration panel deployed as a Docker app package. The web Panel accepts an administrator session and handles desktop wallpaper and scene-pack APIs. The host-side app manager runs installation/update/removal operations with root authority. A separate root Agent service exposes privileged operations through the Unix socket and token configured and mounted by the app package; Panel calls cross the container-to-host boundary into that service. A local host administrator is a stronger principal than the panel's browser session; the deployed host, reverse proxy, Docker daemon, and release registry state are not observable from source alone. Protected resources include the panel's wallpaper files and index, scene-pack files reached through a capability token, cluster light-store credentials and terminal keys, Agent file/service/system-write operations, host service configuration, and update snapshots.

## Stack and execution limits

The boundary code is Go (Go 1.26.7 source/build configuration), Vue/TypeScript frontend, and Bash lifecycle scripts with Docker/Compose, systemd, and OpenRC integration. The four source reconnaissance agents identified existing Go tests with in-memory/temporary-directory fixtures and httptest; none was run. The packaging lifecycle tests write fixed paths such as /home/docker/kpanel, /etc/systemd/system, /sbin, and /root, so they require a disposable root filesystem. No locally verified OS-enforced profile simultaneously provides no external network, empty allowlisted environment, read-only source/toolchain, scratch-only writes, and resource limits. Target code, tests, fixtures, build steps, browser, and network calls therefore remain unexecuted. Pinned validators alone will run under WSL.

## Entry surfaces and boundaries in scope

- Wallpaper HTTP API: internal/panel/desktop_wallpapers.go is session-gated; write operations additionally check Origin and CSRF. Its multipart path is bounded and passes only fixed metadata, image, and thumb parts to the internal/desktopwallpapers store. The store checks image formats, dimensions, metadata, IDs, quotas, directory permissions, and atomic file/index writes. server.go binds the store to the API and sets response security headers. The web client is a supporting consumer for stored metadata, previews, localStorage copies, and CSS background selection.
- Scene-pack HTTP routes: internal/panel/scene_packs.go sends list, source, install, and delete operations through the session gate, while frame files use a capability-token path and a separate CSP/CORS/cache/gzip response path. Coverage critic added distinct units for the session-gated administration routes and frame capability issuance, binding, revocation, and store authorization; existing units cover cache revalidation and stream admission.
- Light-store persistence: internal/cluster/light_store.go stores cluster state, enrollment credentials, and terminal public keys in private local files. Its affected path includes .previous recovery and the fail-closed behavior when credentials remain without recoverable state. Existing cluster service and atomic-store helpers are supporting callers.
- Root lifecycle/update boundary: packaging/kejilion-app/kpanel.conf validates image/release identity, creates the host-side lifecycle helper, snapshots data/panel and data/agent, switches application images, and handles health/rollback/install/uninstall. It also configures the Panel's Agent Unix-socket/token mounts and the root Agent service definitions, including OpenRC. The changed test scripts model these paths, but their rootfs gate is not a production security boundary. Docker/systemd/OpenRC runtime facts and installed image state are not source-proven.

## Prior evidence and scoped gaps

Coverage is scoped to the checker output: 9 uncovered commits, 10 files, and the new boundary package internal/desktopwallpapers. The prior custom-wallpaper run-10 was left in_progress: its 15 units have no completed checks, reviewed paths, or fingerprints, and it has no findings.json; it supplies starting-point identities only, not coverage. Prior run-7 rejected kpanel.light-store.missing-target-backup-recovery because the old path showed local availability loss without an attacker boundary. Current source changed: openLightStore now recovers a valid .previous and refuses empty-state initialization when credential/key files remain; the root cause must be reviewed afresh, not carried as a vulnerability. The scoped target does not re-review unrelated prior scene iframe or terminal-stream leads unless a changed in-scope path reaches them.

## Companion selection

Selected domains follow concrete changed boundaries: WEB-PROTOCOL-AND-AUTH.md for session/CSRF/cache policy; CLIENT-SIDE.md only for backend-supplied wallpaper metadata and browser storage/render sinks; MEMORY-SAFETY-AND-BINARY.md for newly added JPEG/WebP container walks; RESOURCE-EXHAUSTION-AND-AVAILABILITY.md for bounded uploads, decoding, quotas, and gzip; DATA-ISOLATION-AND-LIFECYCLE.md for local copies, capability files, recovery, snapshots, and restore; SUPPLY-CHAIN-AND-RELEASE.md for image identity and update transitions; CLOUD-AND-DEPLOYMENT.md for the host/container privilege and generated runtime configuration boundary; and DESKTOP-MOBILE-AND-LOCAL-IPC.md for Panel-to-Agent Unix-socket peer authentication and privileged methods. The local IPC companion was previously excluded under an incomplete server-only boundary map; the scoped packaging paths do configure this socket and service boundary.

This is a scoped source audit. The machine result is a high-confidence lead assessment, not a human security review, and it does not establish deployed configuration or whole-product coverage.
