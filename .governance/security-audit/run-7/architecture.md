KPanel is a single-admin host control plane. A browser administrator uses file and terminal functions through an authenticated Panel session. Federated Panels and light nodes communicate over versioned signed/Noise-protected transports; Agents expose file operations behind bearer or federated-controller authorization. Passkeys protect the same administrator identity and sessions.

## Trust boundaries and principal paths

- Browser to Panel: file mutations require a session, Origin and CSRF checks, bounded bodies, and constrained routing; the light-node file proxy accepts an allowlisted route and one host selector (internal/panel/files.go:115, internal/panel/light_file.go:32). Terminal SSE binds a stream to the user and token hash and checks session validity periodically (internal/panel/terminal_stream.go:168, internal/panel/terminal_stream.go:194).
- Panel to federated Panel or light node: the V3 file endpoint is a fixed WebSocket path with envelope and Noise negotiation (internal/cluster/file_stream.go:21, internal/cluster/file_stream_transport.go:222). The panel-file role checks controller activity and files scope for each request, and encrypted uploads require a verified final marker and length (internal/cluster/file_stream_transport.go:311, internal/cluster/file_stream.go:407). V2 relay polls separately verify signatures, replay state and file scope (internal/cluster/service_v2.go:802).
- Panel or broker to Agent file operations: the ordinary Agent handler checks its bearer token before routing (internal/agent/server.go:293); the standalone file handler has no bearer check and relies on its authenticated federated caller (internal/agent/file_handler.go:10). Panel and Agent both bound upload size; the file manager stages uploads and publishes with no-replace semantics (internal/panel/files.go:632, internal/agent/files.go:709).
- Terminal streams and buffers: terminal authorization is checked during stream establishment; revocation closes registered peer sockets. Browser SSE checks stream ownership for terminal IDs. Job subscriptions check a known job prefix and site-ID format; their relationship to a requesting user's authority is a focused review item. Existing local terminal buffer handles are an alternate path through TerminalOutput/Input/Resize/Close and must be checked against host deletion/revocation cleanup (internal/cluster/terminal_v2.go:182).
- Thumbnail derived data: Agent requires thumbnail mode, inline response and a matching resource version; a bounded in-memory LRU is keyed by version and path. Panel enables one-hour private caching for versioned 200/304 thumbnail responses (internal/agent/files.go:439, internal/agent/thumbnail_cache.go:30, internal/panel/files.go:1273). ResourceVersion is metadata-derived rather than a content digest (internal/filemanager/manager.go:1579); impact and identity isolation remain to be tested against source-visible callers and cache semantics.
- Passkey origin lifecycle: the new flow can derive origin from the request host only through direct HTTPS or a configured trusted proxy path, then persist it while origin is unlocked and no credentials exist. Rebind requires session, CSRF, current password and enabled second factor; disable clears Passkeys and sessions atomically. Review covers host/proxy canonicalization, origin locking, concurrent enrollment, backup and restore interaction (internal/auth/passkey.go, internal/panel/passkey.go, internal/store/passkeys.go, internal/store/backup.go).
