# Windows CF scoped audit architecture

## Product, principals, and protected resources

KPanel is a Go control panel with a Vue/TypeScript browser UI. The new Windows light-node path installs a Windows service set and can optionally expose terminal, file, login telemetry, and browser RDP capabilities. Panel operators are authenticated users whose stored role is `admin`; source models do not attach a tenant or owner to light hosts. A panel session can therefore operate on any enrolled host by design. Lower-trust principals relevant here are an unauthenticated web caller, a logged-in account without the right session/CSRF/Origin binding, an unprivileged Windows user, a restricted Windows service identity, a remote peer without the enrolled Noise key, and a release or download source that has not passed the configured signer policy.

Protected assets are enrollment tokens and node keys, the Windows service executable and trust/configuration files, local host files and command execution, RDP credentials and session bytes, plus the center's host and capability records. The terminal and file brokers intentionally run as LocalSystem; telemetry and login services use separate service SIDs and constrained ACLs.

## Stack and source-visible flows

Go implements panel APIs, cluster relays, node services, file handling, and the desktop bridge. The browser uses WebSockets and the packaged IronRDP WASM client. Windows shell access uses inbox Windows PowerShell through ConPTY and a Job Object. The desktop bridge parses a bounded RDCleanPath/RDP negotiation, connects only to IPv4 loopback, requires NLA, and authenticates TLS against the exact LocalMachine RDP certificate DER pin.

The panel's enrollment endpoint creates a short-lived, origin-bound one-use token and returns a PowerShell command (`internal/panel/cluster.go`, `internal/cluster/light_windows_install.go`). The command stages and verifies the installer, which validates release hashes and Authenticode signatures before handing a bounded JSON request to `kejilion-node install --stdin`. A temporary SYSTEM service reads a `SystemOnly` handoff, removes it, validates the binaries, stores trust/configuration with protected DACLs, enrolls with the center, and creates capability-specific long-lived services (`deploy/windows/install.ps1`, `cmd/kejilion-node/service_windows.go`, `internal/windowsnode/security_windows.go`).

Windows telemetry uses the node reporting HMAC; terminal, file, and desktop relays use separate Noise static identities and role/capability checks. The file broker exposes the agent file API through the center and Windows volume-rooted `NtCreateFile` operations (`cmd/kejilion-node/file_broker.go`, `internal/cluster/file_stream_transport.go`, `internal/filemanager/root_windows.go`). The terminal broker drives a SYSTEM ConPTY process after panel session authorization (`internal/panel/terminal.go`, `internal/panel/terminal_input.go`, `cmd/kejilion-node/terminal_broker.go`, `internal/hostpty/process_windows.go`). Browser RDP uses a one-minute, one-use panel session bound to the login cookie hash and user ID, then a dedicated Noise desktop role and an in-process loopback RDP bridge (`internal/panel/desktop_sessions.go`, `internal/cluster/desktop_stream.go`, `internal/desktopbridge/bridge.go`).

## Strongest visible controls and limits

The installer validates elevation, OS/architecture, release host and redirects, checksum, publisher and optional signing-profile OID. The node requires an elevated install command, a protected Program Files executable path, signature verification, a SYSTEM-only token handoff, an 8 KiB strict JSON boundary, and lifecycle serialization. Directory and file helpers validate owner/DACL/reparse status and hold parent handles during protected writes. Telemetry runs under a restricted service SID with only `SeChangeNotifyPrivilege`; privileged brokers enforce LocalSystem at start. The file manager discovers fixed local volumes, rejects UNC paths, reparse points, and non-directory hardlinks, and applies protected destination ACLs. Terminal and desktop connections are host/user/session-bound and capacity-limited; RDP cannot choose its destination and uses NLA plus an exact local certificate pin.

The audit is source-only. The host has no OS-enforced empty environment, external-network isolation, read-only target/toolchain, scratch-only writes, or explicit low resource limits. No target tests, builds, installer, service, browser, emulator, or deployment traffic were run. Windows SCM, local ACLs, RDP listener/certificate contents, proxy routes, configured signing profile, signing secrets, and actual Release state remain owner-observed facts. There is no verified safe scratch-artifact promoter; source-only agent results do not rely on promoted execution artifacts.
