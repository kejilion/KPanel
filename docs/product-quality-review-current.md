## 当前产品性质与核心思想

1. KPanel 仍是面向单管理员、直接管理 Linux 宿主机真实资源的轻量控制面，不是多租户 SaaS。
2. `kejilion.sh`、Docker Engine、Nginx、systemd 和实际文件仍是业务真源；Web、脚本、SSH 与 Compose
   必须能继续管理同一资源，Panel 数据不得形成排他第二真源。
3. Panel 保持无特权，宿主机写操作只经 Unix Socket 上的 Agent 固定动作或登记的脚本协议执行；
   `kejilion.sh` PTY、目标容器内有界控制台与宿主机任意 Shell 必须继续区分。
4. 低配主机资源预算、长任务恢复、真实失败状态、管理员完整能力和脚本/Web 双向互通仍是产品能力。
5. 0.x 阶段继续允许聚焦的小步高频交付；风险越高证据越完整，不按文件数、版本数或等待时长机械加码。

- 轻量节点已支持一次配对后的受限远程终端控制；权限仍按节点能力和固定协议边界隔离，不能把节点终端扩展为宿主机任意 Shell。
- 全局品牌资产已统一到新版 KPanel Logo；文件分享、集群分享等公开/半公开页面继续使用固定资源真源，不改变分享 Token、权限和失效语义。
- 桌面模式网站页面高度、体检窗口窄视口滚动和页面焦点/安全边界已纳入响应式验收；经典页面滚动与桌面窗口内部滚动仍保持分离。
- 系统中心只读端口占用信息可补充 Docker 容器名、镜像和 Compose 归属；本地 Web 服务选择器优先识别 Docker 映射端口，无法确认归属时保留原始监听结果。
- 进程管理增加连续占用热力图，颜色只编码真实占用强度，零值或无效指标不得伪造为使用中；IP 质量卡片合并风险与属性详情，保留降级和字段缺失边界。
- 三级页面、应用终端以及 Apps/Cluster/Terminal 运行时多语言覆盖已扩展到状态、错误、确认、操作和格式化文案；构建基座固定为 Go `1.26.7`、Node.js `24.20.0`。
- 集群通知支持 Telegram 渠道、累计接收/传送规则、主机时区时间和三语消息；通知配置仍复用节点能力协商、签名、后台任务和受限存储边界。
- 网站支持用户主动提供的自定义 TLS 证书材料，并继续复用既有自动签发/有效证书协议；证书格式、密钥匹配和受管脚本入口仍是安全边界。
- 系统中心防火墙界面支持受控的国家/地区入站允许、阻止和清除规则；宿主写入仍只经固定 Agent/`kejilion.sh` 动作，不开放任意规则或 Shell。
- 发布治理已把候选精确 SHA、固定 Linux CI、依赖新鲜度、L3、公开 OCI、`arena-154` 备份与 postdeploy 证据串成单写者流程；`108`/`prod-108` 继续禁止全部 KPanel 操作。

- 桌面工作区已从视觉入口扩展为可持久化的图标、文件/目录快捷方式、批量操作、外部文件拖入、
  跨窗口文件传输和目录窗口复用，新增真实文件状态、并发版本与回滚边界。
- 文件管理器与桌面共享文件旅程；窗口关闭、批量失败、外部拖入和文件摘要一致性成为受影响验收重点。
- 文件和目录下载统一提供短期、不可猜测的下载票据；目录与多选项目由服务端预扫描后生成有界 ZIP，

- 单文件公开分享通过随机 bearer token、内容身份强绑定和 Agent 强校验提供 7 天、30 天或永久链接；

  未完成任务明确标记为中断。操作系统目录拖入复用现有上传链路，并限制文件数、目录数、深度和总量。

  控制字符处理仍需在宿主终端、应用交互终端及多视口间保持一致。
- 桌面提供可配置小插件网格、服务状态卡片及统一的小插件/快捷方式管理；偏好保存在桌面工作区，
  不改变文件、目录和宿主资源的真源边界。
- 系统中心新增磁盘与分区管理，读取宿主真实拓扑，并只通过 opaque 设备标识、整表资源版本、保护规则、
  可信 `kejilion.sh` 固定协议和持久任务开放格式化、检查/修复、挂载/卸载；首版不创建、删除或调整分区表，
  也不编排 LVM、RAID 或 LUKS。高风险动作必须在执行前后重新核对真实设备与挂载状态。
- 文件、Docker、终端和桌面右键菜单共享可见视口与任务栏安全边界，长菜单滚动、键盘导航和焦点恢复成为
  通用交互契约；视频预览不能以 `loadedmetadata`、音轨可播或黑屏假成功代替有效视频画面，无法解码视频轨
  时停止并提供下载/转换恢复提示，KPanel 不因此引入服务端转码。
- 桌面系统入口、窗口标题和任务栏统一使用同一原生图标资产真源；文件/目录快捷方式保留类型、选择、拖动
  和跨面板传输语义，不再叠加无业务含义的重复角标。图标或 favicon 失败必须安全回退，不改变打开目标。
- 系统中心新增轻量日志管理，以宿主 journal、真实 `.service`、认证日志和 `last` 为真源；读取条数、级别、
  服务和刷新均有界，共享脱敏器覆盖日志展示。清理仅允许固定 rotate/vacuum 策略并绑定持久任务身份，
  不接受任意路径、Shell、日志编辑或第二套确认协议，也不承诺由普通 KPanel 备份恢复已清理日志。
- 全站外观已收敛为版本化语义 Token：主题色、界面基调和少量身份点缀生成浅色、深色与跟随系统色板，
  成功/警告/危险状态色不随品牌色改义。自定义意图只保存在当前浏览器并限制为规范化颜色，非法或旧版本
  记录安全回退；桌面、文件、Docker、终端、诊断、集群和分享页面必须继续满足对比度、键盘和焦点契约。
- 发布与治理已采用风险感知 `verify-change`、固定 Linux Runner、后台浏览器作业、依赖新鲜度检测、
  环境用途门禁及独立流程异常指标；治理路径进入 main 前必须有同 SHA 候选 CI，Token 仅在专用检查子进程中短期注入。
  `prod-108`/`108` 禁用全部 KPanel 操作，隔离验证和唯一正式部署默认使用 `arena-154`。

这些变化扩大了桌面、文件、磁盘、日志、主题、公开分享、受限出站下载、集群、国际化、应用市场、
系统调优、Docker、诊断和 AI 业务域，但没有改变 KPanel 的产品性质、业务真源、Panel/Agent 权限边界、低配主机定位或
“不以安全名义削减管理员能力”的核心思想。

## 当前业务域与最小验收入口

| 业务域 | 代码真源 | 风险感知验收重点 |
| --- | --- | --- |
| 身份、Panel/Agent | `internal/auth`、`internal/panel`、`internal/agent` | Session、CSRF/Origin、Unix Socket、离线降级 |
| 系统、网站、应用 | `internal/systemmanage`、`internal/sites`、`internal/appmarket` | 脚本同源、动态目录来源/回退、selector 边界、磁盘/日志真实状态、后台任务、不可逆动作与失败恢复 |
| Docker、文件 | `internal/dockerx`、`internal/filemanager`、`internal/remotedownload` | 外部资源、公开分享/受限出站、路径/归档、资源版本、批量部分失败 |
| 桌面工作区 | `internal/desktopworkspace`、`web/src/components/desktop` | 持久化、窗口/快捷方式互通、并发版本、跨窗口传输 |
| 集群、终端、AI | `internal/cluster`、`internal/terminal`、`internal/ai` | 协议身份、断线恢复、输入输出上限、固定工具 |
| 全局体验 | `web/src/router.ts`、`web/src/views`、`web/src/styles`、`web/src/theme` | 受影响旅程、双视口、语义主题、对比度、焦点、多语言、失败态 |

日常任务先从本表定位受影响域，再执行 `make verify-change`；只有跨权限、协议/数据、部署或发布风险
才升级 L2/L3。当前事实入口的新鲜度由 `scripts/check-business-context-freshness.mjs` 以本地 Git 数据检查，
达到门槛只要求刷新业务事实，不自动推断质量下降，也不触发发布或生产操作。
