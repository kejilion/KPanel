- 提案状态：待独立复核
- 提案日期：2026-08-17
- 负责人：KPanel 协调中心
- 适用业务域：永久规范、项目管理、AI 适配、工作流、策略与治理门禁
- 基线提交：`38e72f131261e6e6421690b519431259c3d6bec0`
- 关联事件：多轮规范复核在修复后继续扩展罕见反例，严重度和停止条件不稳定
- 权限：用户已授权处理全部审计事项、提交、推送并更新 `main`；不授权发布、部署或生产操作

## 观察证据

- 同一治理解析器曾连续扩展到 Unicode、Markdown 和外部 Git 环境组合；各轮没有预先冻结输入空间和
  停止条件，导致“仍能构造反例”被反复解释为“规范仍不可用”。
- 2026-08-17 对 `38e72f1` 的复核中，治理测试和工作流结构均通过，但低概率标题变体、外部 Git 环境
  污染等边界被一度评为高优先级；重新加入正常路径可达性和发生可能性后，严重度明显下降。
- 用户明确要求对规范使用统一尺度，避免修复后继续提高验收难度。
- 已确认问题不是单次命令失败，而是复核方法缺少范围、严重度和停止合同，具有跨会话复发性。

## 原因假设

- 根因：规范定义了产品 L0-L3，却没有定义“规范本身如何验收”；审查者容易把错误成功测试等同于
  阻断，而不同时考虑影响、正常路径可达性和发生可能性。
- 替代解释：系统持续变化确实会产生新缺陷，但这不能解释同一精确基线在无范围变化时被无限扩展反例。
- 可证伪结果：应用固定合同后，仍频繁遗漏正常路径阻断，或为了停止而压低真实安全/生产问题严重度。
- 本改动不改变 `kejilion.sh`、产品能力、Panel/Agent 权限、生产环境或业务数据。

## 产品原则与核心思想对齐

- 保留 Git、CI、验收记录和真实系统资源作为状态真源，不引入会话评分或模型信心。
- 保留安全、权限、数据、生产和发布错误成功的阻断地位；停止条件不能降低现有质量门槛。
- 通过固定范围和受影响重验减少重复全仓扫描，符合低资源、高频小步和风险感知原则。
- 权威定义只进入 `PROJECT_RULES.md`；模板和 `evolve-kpanel` 只引用，不形成第二套规范。

- 精确规范基线：`38e72f1`

  验收与改进模板、依赖/环境策略、全部 9 个工作流、治理脚本/测试、Make/CI 治理路由。
- 非目标：产品业务代码正确性、线上功能、依赖是否为今日最新版本、154/108 状态、正在运行的

- 停止条件：固定证据全部完成；正常路径阻断为零；其他事项分级并绑定影响边界和后续触发条件。
- 范围外发现：只记录后续事项，除非证明属于支持环境/正常路径的安全、权限、数据、生产或发布阻断。
