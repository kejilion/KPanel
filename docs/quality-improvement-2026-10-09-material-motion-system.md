## 观察证据

- 可重复观察：
  1. 桌面模式下活动窗口与非活动窗口的标题栏底色、标题文字色、字号完全相同（浅色和深色主题均如此），
     区别只有边框染色和阴影；换成浅色壁纸后两扇白色窗口几乎无法分辨前后。
  2. `docs/ui-visual-language.md` 3.1 写的是“不叠加无意义的玻璃效果”，但 `d92cec75` 提交说明与
     `VisualRhythm.test.ts` 实际保留了“系统外框和遮罩的半透明是材质”这一例外。白名单只存在于测试里，
     规范正文没有写，后续开发者无法从规范得知哪些表面可以用材质、为什么。
  3. 六个右键菜单（桌面、文件、Docker、终端、集群、桌面子菜单）各自定义表面：底色在 `--surface`
     与 `--surface-raised` 之间不一致，圆角为 10/11/12px 字面量（其中 3 条在视觉债务基线中），
     终端菜单还带自定义阴影和兜底色。
  4. 经典模式透出壁纸时的顶栏写死 `blur(18px) saturate(1.2)`，不在 VisualRhythm 覆盖的文件里。
  5. 动效时长分散为 `.14s`、`.16s`、`.18s`、`.22s`、`.25s`、`180ms`、`220ms` 等字面量；退出与进入使用同一
     曲线和时长；规范 3.4 只有原则，没有令牌、编排和退出规则。
- 精确环境、版本、时间范围和样本量：`origin/main@29f74518`；本地 mock 预览（`scripts/mock-app-market-api.mjs`）；
  内置浏览器与 Playwright Chromium（chromium-1228）1440×900，浅色/深色主题 × 经典/地平线壁纸。
- 原始命令、日志、截图或验收记录：`_codex-evidence/kpanel-desktop-material-20261009/`（候选截图与 `facts.json`）；
  基线计算样式在会话中以 `getComputedStyle` 读取（两窗口标题栏 `background-color` 与 `color` 相同）。
- 已确认事实：见上 1–5；09-02 精简的动机按提交说明原文是“视觉不统一 + 浅色主题无层级 + 遵守规范”，
  不是性能。
- 未确认信息与数据缺口：核显与低端 GPU 的帧率；Safari 与 Firefox 实机。无界面 Chromium 测得各变体均封顶约 32fps、
  3D 场景未加载；本机有头浏览器在默认显示链路下也被钉在约 30fps，二者都不能作为性能证据（已写入规范 3.5.4）。
- 为什么不是一次偶发环境故障：上述均为源码与计算样式的确定性事实，与环境无关。

## 原因假设

- 待验证根因：规范只有“禁止”而没有“材质分层”和“动效令牌”，实现者无法区分装饰性玻璃与材质，
  09-02 的重做因此把可保留的效果和焦点态线索一并去掉；动效缺少令牌导致字面量漂移。
- 可能的替代解释：用户感知的“质感不足”来自壁纸或图标而非窗口外框。预览截图显示焦点态加强后前后窗口
  可一眼区分，支持本假设；壁纸与图标不在本次范围。
- 能证伪本假设的结果：独立复核或用户验收认为焦点态与材质改动后观感无改善，或出现可读性回退。
- 是否涉及 `kejilion.sh`、真实系统资源、Panel/Agent 权限边界或兼容契约：否，纯前端样式与文档。

## 产品原则与核心思想对齐

- 对业务真源和双端互通的影响：无。
- 对轻量、低资源、单管理员控制面的影响：常驻实时模糊面积与改动前相同（仅任务栏，视口 5.1–6.9%）；
  新增模糊只出现在短时浮层；面板改为不模糊的半透明填充。
- 对安全、稳定、性能、体验、数据/迁移的影响：体验提升；材质文字沿用求解器保证对比度的填充；
  减少透明度/高对比/不支持模糊三种降级集中在令牌层。无数据迁移。
- 不应引入的复杂度或第二真源：不新增主题求解器令牌（材质与动效令牌均由现有语义令牌派生）；
  不引入按位置取样壁纸的 JS（列为后续候选，需 GPU 性能证据）。

## 最小改动方案

- 预计修改文件或唯一入口：见“允许修改”。材质令牌在 `themes.css`，降级在 `main.css`，窗口令牌在 `desktop.css` 的 `.desktop`。
- 新增或调整的自动门禁：`VisualRhythm.test.ts` 新增材质白名单（按 chrome/overlay/panel 角色）、令牌化、
  内容不透明、降级、焦点态、动效令牌与“不过渡 backdrop-filter”断言；`visualContract.ts` 把材质滤镜变量视作模糊，
  堵住组件用变量绕过白名单。
- 迁移、兼容和失败恢复：纯 CSS，回滚即恢复；移除 4 条已偿还的视觉债务基线。
- 防止指标投机或规则自我弱化的约束：面积预算写明测量方法和实测值；白名单扩充必须说明层级与模糊理由；
  无界面浏览器帧率明确不可作证。

## 验证与证据层级

- 定向测试：`npx vitest run`（264 文件 / 2442 用例通过）；四次变异检验（窗口正文加材质滤镜、组件内用材质滤镜、
  新增回弹曲线、新增字面量时长）均被测试拦下。
- `make verify-change` / `make verify-l2` / `make verify-release`：L1 `verify-change`（见提交记录）。
- 隔离真机或浏览器证据：本地 mock 预览截图矩阵（深/浅 × 经典/地平线 × 减少透明度、200% 缩放、手机宽度、经典模式
  普通与透出壁纸）；常驻模糊面积 1280×800 6.9% / 1440×900 6.2% / 1920×1080 5.1%。
- GPU 帧率：RTX 4060 / D3D11 有头 Chromium，关闭垂直同步与帧率上限，开/关材质交替成对 4 轮 × 2 壁纸 × 4 场景
  （`gpu-bench-uncapped-repeats-081f515e.json`）：16 组配对中 13 组差值在 ±2.3fps 内，其余 3 组是整机帧节奏
  35↔60fps 翻转，两个方向都出现，与模糊无关。结论：高端独显上材质无可测开销。
- 公开产物证据：不适用。
- 生产部署安全核对：不适用。
- 未验证项：核显与低端 GPU 帧率；Safari（`-webkit-backdrop-filter`）与 Firefox 实机；真实用户设备上的减少透明度设置。
