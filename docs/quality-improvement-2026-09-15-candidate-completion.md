## 观察证据

现行规范把 Git 提交定义为跨智能体事实真源，却仍允许仓库写任务在未提交 dirty worktree 中结束并进入
“待提交授权”。这使完成状态无法由精确提交重建，也增加会话结束、工作树复用和跨工具交接时遗漏差异的风险。
用户要求把开发任务完成条件收紧到候选分支提交。

## 原因假设

根因是本地提交与 SSH 推送、主线、发布共享同一“额外授权”表述，导致可回滚的本地检查点也被推迟。
替代解释是某些任务确实无需修改；因此不能用空提交覆盖只读、无需修改、取消或阻塞状态。

## 基线、目标与观察窗口

- 基线：写任务可以 dirty 状态结束，机器只支持 `--require-clean`。
- 目标：所有实际仓库修改只有形成相对精确基线非空、聚焦的本地候选提交并保持 clean 才能宣布完成；
  本地可安全复现的用户可见改动在提交后提供绑定该提交的 acceptance 预览。
- 防回归：不隐式授权 SSH 推送、`main`、Tag、Release、镜像或生产；不强迫只读/无需修改任务创建空提交。
- 观察窗口：进入主线后的最近 20 个写任务，检查无提交完成声明、空提交和权限越界是否为零。

## 最小改动方案

统一调整 Definition of Done、Codex/Claude 入口和会话协作工作流；为唯一协作状态检查器增加
`--require-candidate`，机器验证非 `main`、clean、精确基线祖先、至少一个候选提交以及非空任务差异。
候选提交后复用现有本地预览入口提供 acceptance 预览；不适用任务记录真实边界。不改变 L0-L3、
测试强度、集成、发布或生产门禁。

### 规范验收合同

- 允许范围：完成定义、权限边界、协作入口、唯一状态检查器及其测试。
- 非目标：自动 SSH 推送、自动合入主线、修改发布通道、清理历史 worktree、产品功能变化。
- 六项矩阵：正确性、一致性、完整性、可执行性、效率与比例性、可演进性。
- 正常路径：用户要求修改 -> 专用 worktree -> 修改与验证 -> 聚焦本地候选提交 -> 完成检查 -> 必要时提供 acceptance 预览 -> 交付。
- 回归集：协作状态测试、治理一致性、工作流校验、变更感知门禁。
- 停止条件：矩阵完成、阻断为零、候选提交可复核；范围外优化进入后续事项。

撤销本治理候选提交即可恢复原完成定义。该回滚不删除任何任务分支或工作树，也不修改已有提交历史。
