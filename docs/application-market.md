# 应用市场生态对齐

## 目录与事实来源

- Agent 每五分钟从固定的 `https://app.kejilion.sh/` 读取并严格校验
  `window.__APPS__`，动态替换内置与第三方展示目录；分类键、响应体积、来源、字段、URL、
  ID、内置编号、数量一致性和重复项仍受固定边界约束。
- 内置与第三方应用复用同一条动态目录、缓存、回退和 `kejilion.sh` 后台任务链路。通过校验的内置
  应用只把受限数字编号作为 selector，第三方应用只把受限 token 作为 selector；两者都固定调用本机
  可信 `kejilion.sh app <selector>`，远程目录不能传入命令行、函数名或脚本路径。
- 既有应用继续优先使用 KPanel 随发行版固定的受管脚本，避免宿主机旧脚本改变现有安装、更新和卸载
  行为。执行内置应用前还会核对脚本是否明确包含对应数字 selector；受管脚本不包含动态新增编号时，
  才回退到 root 持有、不可被组或其他用户写入且协议兼容的宿主机 `/usr/local/bin/k`。因此启用本机制
  后，新增应用只需同步发布兼容的 `kejilion.sh` 与 `app.kejilion.sh` 目录，不再要求为应用编号更新 KPanel。
- 随镜像发布的离线回退目录包含 153 个应用；在线目录校验成功后动态替换内置与第三方展示项。
- 权威目录可为应用提供首次收录日期 `addedAt`（严格 `YYYY-MM-DD`）。KPanel 始终先展示已安装应用，
  再在各安装状态分组内按目录载入时一次性计算的 UTC 自然日差排序：首次收录后的 60 个自然日显示
  “新品”并按收录日期倒序优先呈现，第 61 天恢复内置编号顺序。应用更新、改名或换图标不得刷新日期；历史目录缺少该可选字段时
  保持原排序；未来日期不会被展示为新品，非法日期会使远程目录校验失败并回退最近一次有效目录。
- 上游不可用或来源、字段、分类、数量、URL、ID、内置编号、重复项校验失败时，使用最近一次已校验目录；
  Agent 重启后仍可回退随版本发布的内置快照，应用市场不会因断网不可用。
- 已随版本发布的图标继续使用 `web/public/app-icons`。动态新增且本地快照不存在的内置或第三方
  应用复用同一机制：Agent 只从固定的 `https://app.kejilion.sh/icons/<slug>.webp` 首次抓取图标，
  校验同域 HTTPS、重定向、WebP 类型、128 KiB 体积和图片尺寸后原子缓存到
  `/var/lib/kejilion-panel/app-icons`，Panel 通过登录保护的同源接口返回；抓取或校验失败时使用
  本地通用图标。缓存每 24 小时最多刷新一次，目录最多包含动态目录允许的 500 个受限 slug。
- `scripts/audit-kejilion-apps.mjs` 从指定的 `kejilion.sh` 提取 115 个内置应用的主容器、镜像、
  默认端口和管理类型，生成 `internal/appmarket/legacy-apps.json`。
- Docker Engine 是安装与运行状态的事实来源；`/home/docker/appno.txt` 只作为脚本兼容标记。
  只有标记、没有容器时显示“待核对”，不会伪装成正常运行。

同步随版本发布的回退目录和本地图标：

```bash
node scripts/sync-app-market.mjs
```

重新审计脚本映射：

```bash
node scripts/audit-kejilion-apps.mjs /path/to/kejilion.sh internal/appmarket/legacy-apps.json
```

两条命令都有严格的数量、字段、URL、文件类型、大小和重复项校验。上游内置应用或分类结构发生
变化时，同步会失败，必须先人工复核。运行时远程目录只提供应用标识、受限 selector 与展示元数据；
内置和第三方安装都由本机已更新且支持 KPanel 交互协议的 `kejilion.sh` 解析，KPanel 不接收远程
命令行。若本机脚本尚未包含动态新增项，原生任务会明确失败，不会改用远程命令或另一套安装器。

## 功能矩阵

| 功能 | 全部目录应用 | `kejilion.sh` 标准应用 | 声明式适配应用 |
| --- | --- | --- | --- |
| 搜索、分类、来源与状态筛选 | 是 | 是 | 是 |
| 脚本安装标记、容器状态、端口和镜像 | 视可用产物 | 是 | 是 |
| 后台安装与进度 | 脚本内置编号和第三方固定 token 可用 | 是 | 是 |
| 启动、停止、重启 | 已识别容器按实时状态开放 | 同左 | 是 |
| 镜像更新检查 | 有镜像标签和仓库摘要时 | 同左 | 是 |
| 添加域名 | 有可识别 TCP 端口时 | 同左 | 是 |
| 删除域名 | 按实际反向代理资源 ID | 同左 | 同左 |
| 阻止/放行 IP+端口 | 需要脚本管理协议或可识别端口 | 脚本协议可用时 | 是 |
| 更新、卸载 | 已可靠识别容器且存在脚本协议或声明式适配器 | 脚本协议可用时 | 是 |
| 脚本恢复终端 | 仅安装标记存在但未发现容器时 | 固定应用编号/token | 不适用 |

当前审计快照中的 115 个脚本内置应用，以及官方目录中由固定 token 提供配置的第三方应用，
都可以从 KPanel 发起后台交互安装。99 个采用 `docker_app`/`docker_app_plus` 的内置应用由脚本
自动进入安装动作；宝塔、1Panel、哪吒、邮局、雷池、FRP、OpenClaw 等专属流程则完整显示原生
交互向导，由管理员继续选择和输入。KPanel 只提交审计快照中的数字编号或远程目录严格校验后的
固定 token，不接收命令、函数名或脚本路径。

专属流程以脚本退出状态表示交互过程是否正常结束，结束后 KPanel 重新读取 Docker 和兼容标记；
管理员在原生菜单中选择返回时不会伪造安装产物，应用仍保持“未安装”。只有脚本可识别的容器或
安装标记才会改变市场中的安装状态。

首批声明式适配应用：

- LibreSpeed：`speedtest`，默认 `8028 -> 8080/tcp`
- IT-Tools：`it-tools`，默认 `8064 -> 80/tcp`
- DOS 游戏：`dosgame`，默认 `8076 -> 262/tcp`

这三项与脚本当前镜像、容器名和端口一致，是首批内置声明式适配器。脚本或管理员后续修改
镜像、挂载、特权、网络、Capability 或设备不会取消其管理权限；更新与访问模式切换只要求
仍能识别该应用约定的端口。

## 双向兼容

KPanel 安装成功后原子更新：

- `/home/docker/appno.txt`
- `/home/docker/<container>_port.conf`

因此脚本菜单会显示已安装，脚本读取端口时也能获得相同值。写兼容文件失败时，KPanel 会删除刚创建
的容器并报告已回滚；容器回滚也失败时进入“需要人工检查”，不伪报成功。

脚本安装或修改应用后，KPanel 下一次请求会重新读取 Docker 与兼容文件。应用配置、marker、
容器名、Compose label 与工作目录共同用于发现；任何单一 KPanel 专属标识都不构成管理授权。
若容器可由脚本内置规格或受信任的第三方应用配置精确识别，但旧安装缺少 `appno.txt` 标记，
更新、卸载或访问策略任务会先核对固定 selector 与当前完整容器 ID，再由 `kejilion.sh` 补齐标记
并执行原生动作。停止状态不会取消详情、更新和卸载能力；从“运行中”筛选页停止应用后，页面自动
回到“已安装”筛选，应用卡片与详情入口保持可见。

## 后台安装、更新与卸载事务

Panel 登录后以一小时为最短间隔，复用应用清单和镜像摘要检查接口，仅检查固定的
`thirdparty-kpanel` 应用。发现新镜像时，左侧底部版本区域显示更新提示；点击后进入应用市场的
KPanel 详情并打开原有更新确认，不创建新的更新 API、命令或任务实现。更新仍由同一应用任务锁、
`kejilion.sh app kpanel` 固定选择器、systemd 后台任务、完成凭据、健康复核和回滚链路执行。
KPanel 自更新完成后页面自动重新加载，以获取新版本前端资源；Panel/Agent 暂时重启或 Registry
检查失败时不影响导航，也不把失败误报为“已是最新”。

自更新在拉取镜像、改写配置、停止 Agent 或重建正式容器前，先用当前不可变镜像和当前 Docker 网络
启动一个立即退出的临时 healthcheck 容器，真实验证本机端口发布规则仍可编程。若 Docker 的
`DOCKER` iptables 链等网络状态异常，更新在切换前失败并保持当前服务与文件不变，同时提示管理员
先修复 Docker；更新器不会擅自重启影响整台宿主机其他容器的 Docker daemon。

该提示的流量路径为“浏览器 → 既有 Panel 应用 API → Agent Docker Unix Socket → 当前镜像
Registry”；没有新增外联地址、宿主机权限或可写路径。应用清单仍受现有目录上限约束，每次检测只
追加一个固定应用的摘要查询，并用单请求和一小时最短间隔限制并发与资源占用。

应用安装请求先持久化到 `/var/lib/kejilion-panel/app-jobs`，再返回任务 ID。页面每两秒读取一次
进度，离开应用市场或刷新浏览器不会中断任务；任务详情只向已登录会话返回最近的受限日志。
首版为避免多个 Compose 安装器争用端口、软件包管理器和 `/home/docker/appno.txt`，同一时间只
执行一个应用安装任务。

对采用 `docker_app`、`docker_app_plus` 或单端口声明式适配器的应用，安装端口在面板提交任务前
输入。面板先通过 `GET /api/v1/apps/{id}/install-port?port=<1-65535>` 同时检查 Docker 已发布
端口和宿主机 TCP/UDP 监听端口；任务创建前再次检查，声明式容器创建前再做最后一次检查。被占用
时返回占用端口及可识别的容器名，不启动安装任务。无法安全识别单一安装端口的专属流程继续在
原生交互终端中询问，不猜测或改写脚本业务。

声明式安装器接受：

- 固定应用 ID、容器名、镜像和容器端口；
- 用户选择的 `1-65535` 宿主机端口；
- `direct` 或 `domain_only` 两种访问模式。

脚本应用统一由独立的 systemd 临时服务和宿主机 PTY 在后台执行，只接受经过正则校验的数字
编号或应用 token，以及固定的 `install`、`update`、`uninstall`、`direct_access` 动作。安装
标记存在但 Docker 中找不到运行产物时，额外开放固定 selector 的 `manage` 恢复动作；正常发现到
容器的应用不显示“脚本管理”，继续使用面板的启动、停止、更新、卸载与访问策略入口。新版
KPanel 不再设置 `KJ_APP_NONINTERACTIVE=1`，而是使用
`KJ_APP_INTERACTIVE=1 KJ_APP_ACTION=<固定动作>` 调用
`kejilion.sh app <selector>`。统一应用管理函数将动作映射到原菜单的 `1/2/3/7/8`；专属流程
保留自身原生菜单。标准单端口安装任务额外传入经过两端校验的 `KJ_APP_PORT`，脚本仍会在实际
创建容器前检查端口并复用原安装函数；域名、账号、密码、配置文件等后续问题仍由原来的 `read`
和安装函数处理。SSH 直接运行脚本时没有 `KJ_APP_PORT`，原端口输入顺序和交互行为不变。最终
Docker/Compose、数据目录、默认凭据与兼容标记均与 SSH 端同源。

浏览器每次读取最多 64 KiB 原始终端输出。无输出时请求在 Agent 最多等待 1 秒，Agent 每 25ms
检查一次输出、结束或输入状态变化，变化后立即返回，不再依赖浏览器固定 350ms 轮询。普通连续
键入在最长 12ms 的固定窗口内合并，回车、方向键和控制键立即发送；粘贴内容按 UTF-8 字符边界
拆成不超过 2 KiB 的片段，再写入任务专属的 `0600` FIFO。FIFO 短暂繁忙时 Agent 最多等待
500ms，不会把一次短写误判为完整输入。

运行中的交互任务可由管理员在横幅或任务详情中手动结束。该动作经过 Origin、CSRF 和会话校验，
写入审计后由 Agent 请求 systemd 优雅停止任务单元；取消标记和最终状态持久化到任务目录，Agent
重启后仍可完成锁释放。结束动作只适用于交互任务，不开放给声明式安装、更新等不可安全中断的
后台事务；已经由脚本完成的步骤不会自动回滚，结束后面板重新读取真实容器、域名和访问策略状态。

安装、更新等任务意图正常审计，但终端键盘内容、长度和分段本身均不写入审计。PTY、FIFO 和任务由
systemd 持有，因此刷新页面、
关闭弹窗或 Panel/Agent 重启不会终止正在运行的脚本，重新打开任务会从受限的原始终端记录回放。
每个终端记录最多 8 MiB，历史任务仍受总数清理限制。Web 容器没有 Docker Socket，也不能提交
任意命令；Agent 始终只执行已校验的 `kejilion.sh app <selector>`。

更新或卸载提交期间若容器资源版本恰好变化，页面会刷新一次真实清单并使用新版本重试；首次请求在
冲突校验阶段尚未创建任务，因此不会重复执行。真实存在的后台任务冲突仍单独返回，不与资源版本
变化共用错误文案。

脚本未更新、文件可被非 root 用户修改、用户尚未在终端运行 `k` 接受许可协议，或系统没有
systemd 时，交互任务保持不可用。KPanel 不代表用户自动接受脚本许可协议。旧版 KPanel 使用的
非交互入口继续保留在脚本中用于版本兼容，但新版 KPanel 不再调用。

## 域名与直接访问

添加域名调用网站管理的固定反向代理事务，目标只能是 `http://127.0.0.1:<已识别端口>`。Nginx
配置必须通过 `nginx -t`，然后才 reload；失败时恢复原配置。

删除域名按实际反向代理资源 ID 和资源版本执行，并且只移除 Nginx 入口；静态站、PHP 站和
数据目录不通过应用域名入口删除。

标准脚本应用通过 `kejilion.sh` 交互任务执行原生阻止/放行流程。声明式应用以当前容器
运行信息重建端口绑定，把宿主机监听地址在公网地址与回环地址之间切换；宿主机 Nginx 仍可通过
回环地址访问。

## 继续扩展适配器

新增可写应用前必须逐项确认：

1. 当前 `kejilion.sh` 的镜像、端口、环境变量、挂载、网络与重启策略。
2. 数据目录兼容、升级迁移、密钥处理和失败回滚方式。
3. 远程目录只提供展示元数据；执行参数必须来自本机脚本或随版本发布的结构化适配器。
4. 安装、更新、卸载、端口冲突、断网、Agent 重启和外部并发修改测试全部通过。
5. 目录和运行规格分离：`app.kejilion.sh` 只提供展示元数据，不能注入命令；容器是否带
   特权或自定义配置不影响管理员后续管理权限。
