# KPanel 终端与文件传输 v3（本机与集群）

- 状态：v3 核心已进入 `v1.23.0`；本文的 `terminal-input-v1` 扩展为当前本地候选，验证结论以本轮实际证据为准
- 基线：`origin/main@71d50138f9da73999fcaa6046f9b4a860151d2f0`（v1.21.0）
- 范围：本机与远端（完整 KPanel、轻量节点）的交互终端、批量执行、应用/建站/体检/环境任务终端，
  以及文件管理的浏览、缩略图、上传与下载
- 风险等级：L3（跨节点协议角色、信任边界、终端与文件契约变化）
- 相关契约：[多主机终端](multi-host-terminal.md)、[集群监控与联邦协议](cluster-monitoring.md)、
  [文件管理器设计](file-manager-design.md)、[架构](architecture.md)

## 1. 摘要

终端和文件管理慢的主因是传输模型，而不是语言、框架或加密算法：

- 面板之间每次按键、每次输出轮询、每个 32 KiB 文件块都是一次独立 HTTP 请求并重新执行 Noise IK 握手；
- 浏览器到面板靠"收到响应再发下一次"的长轮询，明文 HTTP/1.1 下每个终端占一条连接；
- 缩略图每次都在 Agent 上完整解码重算，上传按文件串行。

本实现保留 Go、Vue、xterm.js、Noise 静态身份、scope 权限模型、Agent Unix Socket API 和"不新增监听端口"，
只替换传输方式：

1. **面板之间**：目标声明 `panel-stream-v3` 后，终端每会话一条、文件请求复用少量已认证连接，
   全部承载在既有 `GET /api/v2/federation/files/stream` 上；失败逐主机回退 v2。
2. **轻量节点**：root `terminal-broker` 在轮询中继旁再保持一条终端流控制连接，会话由节点回拨的流式连接推送。
3. **浏览器到面板**：每个标签页一条 SSE 推送全部终端输出（主机、批量、任务终端）；主机交互终端与应用、建站、
   体检、环境任务终端的输入，在双方声明 `terminal-input-v1` 时使用有界 WebSocket 流水发送，旧目标和批量执行
   保留 POST。
4. **文件**：缩略图先处理 `If-None-Match`、进程内 LRU 缓存、版本绑定的浏览器私有缓存；上传按上传闸门并发 2 路。
5. **批量执行**：随机结束标记由 shell 打印真实退出码，命令一结束即完成。

## 2. 问题与处理

### 主机交互终端输入扩展（`terminal-input-v1`）

本机、完整 Panel 与轻量 root broker 使用相同输入契约。浏览器连接既有 Panel 监听地址上的
`GET /api/v1/terminal-sessions/{id}/input-stream`，子协议为 `kpanel-terminal-input-v1`；Session 与 Origin
先验证，5 秒内首帧 `{type:"auth",csrf:"...",stream:"32位十六进制"}` 再验证 CSRF，凭据不进入 URL。每会话仅 1 条连接，受既有
16 个全局 / 4 个用户会话配额约束；每秒及每次输入发送前复核 Session、会话属主、关闭状态。

通过首帧后先向 PTY owner 发送 `seq=0`、无数据的 writer claim，绑定成功才返回 ready；同 stream 重连幂等，
其他 stream 和后续裸输入均拒绝。能力协商本身不 claim，因此未进入交互输入流的批量执行仍可使用原 POST。
输入以随机 128 位 `stream`、从 1 连续递增的 `seq` 与 UTF-8 字节标识。单帧 2048 字节，窗口 32 帧，
浏览器总待发送/待确认数据最多 1 MiB；超限整次输入拒绝并显示提示。浏览器可在等待前帧 ACK 时继续发满窗口，
中心同样先按顺序写入 Noise socket、再独立等待目标确认，避免把串行 POST 改成串行 WebSocket ACK。
实际 PTY owner 串行写入、保存最近 32 帧摘要，仅完整写入才确认；同序同载荷重复返回确认，同序不同载荷、跳号、
旧窗口外重放和另一个 stream 均拒绝。部分写入或写入错误冻结该输入流，要求新开终端，不能重放可能已经执行的字节。

输出继续复用 SSE 的 offset 补读、1 MiB 环形缓冲和 xterm 解析背压。浏览器连接断开后保留原 stream、seq 和未确认
字节，复接后按序重发；可靠远端会话使用相同 2 分钟复接窗口，不降级成不具备去重的 v2 输入。关闭立即停止新输入，
可能已到达 PTY 的输入不能撤回；调整尺寸不改变输入序号。输入 ACK 仅证明写入 PTY，不证明命令执行成功。

兼容协商在新建 Noise socket 上、任何 PTY open 之前发送无副作用探测，旧目标关闭空连接后重开原协议；
新目标仅在新请求显式声明协议后扩展 ready，旧中心不会收到未知 JSON 字段。Agent 通过 Unix Socket 专用能力动作
确认支持。浏览器先通过带 CSRF 的 `POST /api/v1/terminal-sessions/{id}/input-transport` 查询该会话协议，只有显式
空协议才使用旧 POST；旧 POST 结果不确定时停止输入，不能自动重放。可靠 stream claim 后 PTY 拒绝裸 POST 混写。
升级保留原身份、密钥、配对与 scope，不要求已获终端授权的节点重新配对，也不会自动为旧遥测配对扩权。

本扩展不增加监听端口、Shell 参数或权限。任务终端使用同一输入契约，差异见下一小节。回滚/进程重启会丢失内存会话及
去重状态，旧 session ID 必须报不存在；浏览器不能用新会话继续发送未确认旧输入。

页面挂载时预热输入连接，首键不再承担完整协商链。仅支持 HTTP/SSE 的反向代理可回退
`POST /api/v1/terminal-sessions/{id}/input-batch`：先以相同 stream 完成 seq=0 claim，每次最多 32 帧、
64 KiB 数据、96 KiB JSON；同一终端最多一个批次或一个 WebSocket，二者共享会话入口配额。
批内按序发送，再等待全部 owner ACK；响应丢失只重发相同批次，不能改序号或改为裸输入。后备每帧重新校验
Session/owner/关闭状态，20 秒服务端超时、23 秒客户端取消。健康空闲 WebSocket 复接不会累积为永久失败。

目标流使用最多 32 项的独立有序输入 worker，控制帧读取不被 PTY 写入阻塞。关闭取消未派发输入并关闭 PTY，
Agent 的 terminal resize / close 可绕过正在等待输入的全局 mutation 锁；备份仍通过 Manager.Busy 拒绝活动终端。
PTY 输入闸门支持 context 取消，实际阻塞的 PTY write 不持状态锁，仍可由 close/生命周期回收解除。
注销后每帧拒绝新输入，闲置连接约 1 秒内复核关闭；已经授权并在派发中的字节可能完成，不能承诺撤回。

没人输入时输入 socket 没有任何流量，而反向代理会按空闲连接切断它：nginx 在上游 60 秒没有数据时关闭（默认值，
KPanel 生成的站点反代模板没有调大 `proxy_read_timeout`），Cloudflare 约 100 秒。因此 Panel 对主机与任务终端的
输入 socket 每 20 秒发一次 WebSocket ping，浏览器自动应答，代理把它算作流量；不应答的页面约 20–40 秒内被回收，
不再长期占住"每会话 1 条"的名额。连接仍可能因网络或 Panel 重启断开：空闲时浏览器静默重连，只有已输入的字节在等
连接时才提示"正在重连"。Panel 自身的 `ReadTimeout`/`WriteTimeout` 不影响输入 socket：`net/http` 在交出劫持的
连接时清除了这两个截止时间，有用例固定这一点。

### 任务终端输入（同一契约，Agent 持有序号状态）

应用、建站、体检和环境任务终端只在本机运行，链路是浏览器 → Panel → 本机 Agent → 任务输入 FIFO。浏览器端点为
`/api/v1/job-terminals/{kind}/{id}/{input-transport,input-stream,input-batch}`，`kind` 取 `app`、`site`、
`diagnostic`、`environment`；Agent 端为 `POST /v1/job-terminals/{kind}/{id}/input-sequenced` 与
`POST /v1/job-terminals/capabilities/input-protocol`。Session、Origin、CSRF、首帧、2048 字节帧、32 帧窗口、
12 ms 合并与 HTTP 批量回退均与主机终端一致，Panel 侧由同一套处理器按"输入目标"驱动。

任务的读端是独立的作业进程，不是 Agent 拥有的 PTY，所以序号状态放在 Agent 内存里：每任务一个 `InputSequencer`，
有序受理、按哈希窗口回答重放、仅完整写入后才确认、可能部分写入后冻结。**ACK 只证明字节已写入任务的输入 FIFO
（内核管道缓冲），不证明作业进程已读取、更不证明命令已执行**，比主机终端"写入 PTY"弱一级。`hostpty.WriteInput`
区分"没有任何字节进入 FIFO"（`ErrNotWritten`：没有读端、FIFO 被占满；可安全重试，不冻结）与"已有字节被接收"
（`ErrPartialWrite`：冻结，绝不重放）；不超过 PIPE_BUF（4096）的 2048 字节帧在 Linux 上整帧原子写入，因此失败
几乎总是前者。服务把该错误保留在其冲突错误之下，归类时先看 FIFO 结果再看服务错误类，已结束任务返回
`terminal_closed`，无法识别的错误一律按"不确定"冻结。

任务比打开它的页面活得久，因此与主机终端有五处不同：

- 新 stream 的 claim 接管旧写入者而不是被拒绝，刷新后的页面可以继续输入；旧 stream 之后的帧得到
  `terminal_input_sequence`，不会与新 stream 交错。冻结的 stream 同样只能由新 stream 接管。
- Panel 不采用"每会话 1 条连接"：刷新页面时旧 socket 可能仍在排空。改为每任务最多 3 条、全局最多 64 条，批量请求
  共用该额度；与主机终端相同的 20 秒 ping 回收不应答的页面，不会长期占住名额。
- 每次 claim 返回该 Agent 状态的 `epoch`（随机 128 位），随 `ready` 与批量认领回复下发。浏览器遇到不同 epoch 说明
  Agent 状态因重启而丢失：存在未确认帧时不重放并报告"无法确认"，没有未确认帧时以新 stream 重新开始。Agent 对未经
  claim 的任务的数据帧一律拒绝，状态不会因数据帧凭空重建。
- claim 之前先探测任务仍在接受输入，不为不存在或已结束的任务建立状态；状态上限 1024 项，达到上限时回收闲置超过
  24 小时的项，任务结束后在下一次输入时删除。
- 认领之后旧的 `/input` 路由拒绝裸写入（409），保证每个字节都经过有序、可确认的流。

浏览器端沿用任务终端既有的"输入开放"闸门：输入开放时预热连接，流属于一次任务的一次开放期，关闭或换任务即丢弃；
失败后下一次按键开新 stream，由其接管。不再发送 NUL（旧路由本来就拒绝它）。协商返回空协议（Agent 尚未升级）时
使用旧路由并传文本而不是 base64；该路径的 POST 结果不确定时停止输入，不再把失败块放回队列重发——旧行为会把
可能已经写入的字节再发一遍。

## 3. 实测

`KPANEL_TRANSPORT_BENCH=1 go test -run TransportV2V3 -v ./internal/cluster/`（Linux 门禁镜像，真实 TLS +
配对 + Agent 文件处理器，回环链路注入单向延迟、不限带宽）：

| 往返延迟 | 列目录 v2 → v3 | 8 MiB 下载 | 8 MiB 上传 | 终端回显 |
|---|---|---|---|---|
| 50 ms | 207 → 51 ms | 0.59 → 80.6 MiB/s | 0.59 → 70.3 MiB/s | 103 → 55 ms |
| 150 ms | 607 → 151 ms | 0.20 → 38.7 MiB/s | 0.20 → 39.1 MiB/s | 304 → 154 ms |

- v2 吞吐符合"每 RTT 约 32 KiB"；v3 在真实链路上将受带宽限制，回环数字不代表公网带宽。
- 列目录 v3 为 1 个 RTT（连接池已热）；首次请求需要建立连接（TCP + TLS + 升级 + Noise）。
- 浏览器侧 SSE 与缩略图缓存的收益尚未在真实浏览器中量化，列为发布前验收项（第 9 节）。

### 任务终端输入：逐批 POST → 流水（`terminal-input-v1`）

`KPANEL_JOB_INPUT_BENCH=1 go test -run JobInputLegacyVersusStreamed -v -timeout 30m ./internal/panel/`
（Linux 门禁镜像，真实 Panel 处理器与认证，假 Agent 记录任务收到字节的时刻；浏览器模型按组件行为复刻：
旧为 12 ms 合并后每次一个请求并等待响应，新为同样合并后 32 帧窗口不等待发送；回环链路经延迟代理注入单向延迟、
不限带宽）。耗时单位 ms，"旧 → 新"：

| 往返延迟 | 空闲单键 | 连续输入 p50（每 40 ms 一键） | 连续输入 p95 | 8 KiB 粘贴 | 64 KiB 粘贴 | 64 KiB（HTTP 批量回退） |
|---|---|---|---|---|---|---|
| 0 | 6 → 4 | 15 → 14 | 16 → 15 | 4 → 2 | 16 → 3 | 3 |
| 50 | 54 → 55 | 54 → 40 | 81 → 41 | 216 → 55 | 1706 → 66 | 116 |
| 150 | 156 → 155 | 153 → 84 | 225 → 90 | 616 → 156 | 4928 → 159 | 319 |

| 往返延迟 | 75 个按键（请求 / 线上字节） | 64 KiB 粘贴（请求 / 线上字节） |
|---|---|---|
| 0 | 75 / 128,775 → 75 帧 / 9,282 | 32 / 120,512 → 32 帧 / 91,310（批量 2 / 93,136） |
| 50 | 55 / 94,455 → 75 帧 / 9,282 | 同上 |
| 150 | 20 / 34,395 → 75 帧 / 9,282 | 同上 |

- 空闲单键不变（仍是 1 个往返）：收益只出现在输入快于一个往返的时候。连续输入不再等上一个响应，150 ms 往返下
  中位数 153 → 84 ms（约 −45%），p95 225 → 90 ms；大块粘贴从 N × 往返变为约 1 个往返（64 KiB 约 31 倍）。
  所有粘贴场景都校验了任务收到的字节数与发送一致。
- 旧路径靠"等响应期间积累再一起发"来减少请求数（150 ms 下 75 键只发 20 个请求），代价就是上面的等待；新路径
  每键一帧，每帧连同确认往返约 120 字节，75 键共 9,282 B（不含一次性的升级与认领）；旧路径每个请求往返约 1.7 KB
  （请求头含 Cookie 与浏览器常见头，加响应头）。大块粘贴因 base64 与 JSON 封装，线上字节只减少约 24%，不是主要收益。
- 不预热的首键需要协商、升级、认领、帧确认约 4 个往返（50 ms → 223 ms，150 ms → 622 ms），且未计 WebSocket 自身的
  TCP/TLS 建连，真实值更高；因此组件在输入开放时就预热连接，预热后首键与旧路径同为 1 个往返。
- 局限：回环加固定延迟，没有丢包、抖动、TLS、CDN 与浏览器渲染；假 Agent 不含真实 FIFO 与作业进程读取时间；
  客户端是 Go 复刻而不是真实浏览器；两次独立运行在 50 ms 与 150 ms 下的偏差不超过 5%，0 ms 行只有个位数毫秒，
  仅作参照。真实浏览器与仅支持 HTTP/SSE 的反向代理下的实测列入发布前验收项。原始数据保存在仓库外的证据目录
  `terminal-job-duplex-input/`。

## 4. 方案选择

| 方案 | 结论 |
|---|---|
| A 现状调优（批量带回事件、调限流） | 只保留不冲突的部分（独立 v2 文件连接池、429 背压） |
| B 每请求一条 WebSocket（v1.16.0 做法） | 仅用于轻量节点既有文件流；短请求建连成本 4–5 个 RTT，不适合做默认 |
| **C 连接即流 + 可复用文件连接** | **采用**：每终端会话一条流式连接，文件请求在少量已认证连接上顺序复用 |
| 长会话 + 自研/yamux 多路复用 | 放弃：C 已达到同等延迟，且每个终端独占 TCP 连接，传文件不会阻塞终端；不引入新依赖和帧层 |
| SSH 隧道、QUIC、gRPC | 不采用（语义错位、需 UDP 端口或依赖过重） |
| 浏览器 WebSocket | v1.23.0 输出使用 SSE、输入 POST；本轮主机与任务终端输入采用 WebSocket，并以同序去重 POST 批次兼容代理 |

v1.16.0 让普通 Panel 使用文件 WebSocket，并在升级后遇到 404/405/426 时回退，但 v1.15 的目标已存在该端点、
只在升级后拒绝 panel 角色，因此这种组合下不会回退，而是直接失败——这很可能是 `40d6fa67` 恢复 POST relay
的原因（原因未入库）。v3 因此不做任何探测，只在目标显式声明能力后才使用，并对升级前后的任何建连失败回退。

## 5. 实现

### 5.1 面板之间（`internal/cluster`）

- 能力：目标在 v2 摘要响应头声明 `panel-stream-v3`（未认证提示，伪造只会导致握手失败后回退）；
  中心在摘要轮询中记录，删除主机或撤权时清除。
- 角色：`panel-file`（`cluster.files.read`）、`panel-terminal`（`cluster.terminal.open`），仅限已激活控制端；
  建连时校验 scope，`panel-file` 每个请求前再次校验控制端状态与 scope。
- 文件：同一连接顺序承载请求；中心每主机最多 2 条空闲连接（空闲 20 秒、最长 10 分钟）；
  提前拒绝或上传未完成的连接不复用；复用连接在收到响应前失败时，仅无正文的 GET/HEAD 在新连接上重试一次。
- 终端：目标推送带偏移的输出（3 ms 合并）；输入、调整尺寸、关闭需确认；中心以 `terminal.Buffer`
  镜像输出，保持与本地会话一致的偏移、截断和退出语义；断线后按偏移重新附着，6 秒内无法恢复则同一
  会话继续走 v2（PTY owner 与 v2 相同）。
- 回退：任何在发出请求记录之前的失败都回退 v2，并在 2 分钟内不再尝试；已发出的写操作不重放。
- 审计：每条文件连接一条记录（含请求数），每条终端流一条记录；不记录内容。

### 5.2 轻量节点（`cmd/kejilion-node`、`internal/cluster`）

- root `terminal-broker` 并行运行轮询中继与 `RunTerminalStream`；后者保持 `light-terminal-control`
  控制连接，中心为新会话请求回拨 `light-terminal-data`，节点在数据连接上服务终端协议。
- 终端控制与文件控制分别登记，互不替换；每节点最多 4 个并发回拨。
- 会话与轮询中继共用同一 PTY owner，受同一 4 会话上限约束；2 分钟内没有中心重新附着即关闭 PTY。
- 旧中心在认证阶段拒绝该角色时，broker 按 1 分钟起、最长 30 分钟退避；轮询中继始终可用。

### 5.3 浏览器到面板（`internal/panel`、`web/src`）

- `GET /api/v1/terminal-stream`：SSE，首个事件返回随机 stream ID；每用户最多 8 条、全局 32 条。
- `POST /api/v1/terminal-stream/subscriptions`：带 Origin/CSRF，按会话令牌绑定 stream；订阅主机终端
  （仅限本人会话）或任务终端（固定四类、ID 格式校验）；每条最多 16 个订阅。
- 服务端泵沿用各自后端的长轮询（本机 Agent、v3 镜像、v2、轻量中继、任务终端），4 ms 合并；
  保留 15 秒心跳；输出前最多每秒复核一次会话，发现注销、改密码或 Passkey 撤销后发送
  `auth.expired` 并结束，不再写出已排队输出；无输出的撤销会话由心跳清理。
  到达会话过期时间时主动结束，包括空闲流；写超时 20 秒，已写入传输层的字节无法撤回。
- 前端 `TerminalStreamClient` 每标签页一个；EventSource 不可用、5 秒内未就绪、连续失败或订阅被拒时
  回退各组件原有的长轮询；浏览器重连后按最新偏移重新订阅。
- 批量执行通过 `terminalOutputReader` 顺序读取推送或轮询输出。

### 5.4 文件

- Agent：`If-None-Match` 命中直接 304；否则查进程内 LRU（按路径与 `resourceVersion`，8 MiB，单项 512 KiB，
  不落盘）；都未命中才进入生成闸门。
- 面板：带 `version` 的缩略图仅在 200/304 时返回 `private, max-age=3600`，其余文件响应保持 `no-store`。
- 前端：多选上传与目录拖入并发 2 路，与 Agent 上传闸门一致（第 3 个会被 429 拒绝）。

### 5.5 批量执行

命令包装为 `{ 命令⏎}; printf '\n__KPANEL_DONE_<随机 128 位>_%s__\n' "$?"` 在同一行输入：
标记由 shell 在命令结束后打印，交互程序读不到；回显行只含字面 `%s`，命令输出无法伪造随机值。
读到标记立即关闭会话并按退出码判定，显示时去掉包装与标记行；标记未出现时沿用提示符稳定判定。

## 6. 安全

| 变化 | 控制 |
|---|---|
| 新流式角色 | 仅限已激活控制端；建连校验 scope，文件请求逐个复核；撤权时关闭该身份全部连接 |
| 能力提示未认证 | 伪造只会握手失败后回退；删除只会变慢；Noise IK 静态密钥认证不变 |
| 长连接 | 沿用 8 秒握手超时、未认证 64 / 已认证 128 连接上限；每身份上限由 10 调整为 16 以容纳终端与文件连接 |
| 终端流 | 输入 ≤16 KiB、尺寸有界；未知帧即断开；owner 与 v2 相同，不扩大可访问会话 |
| SSE | 订阅走 CSRF POST 并绑定会话令牌；URL 不含会话 ID；输出前最多每秒复核会话，空闲撤销在下一次心跳收口，到期计时器关闭空闲过期连接 |
| 缩略图缓存 | 仅版本绑定的缩略图、`private`、1 小时；Agent 缓存不落盘、按版本失效 |
| 批量结束标记 | 每次随机 128 位；只接受数值退出码 |

审计策略不变：不记录终端输入输出、文件内容或密钥。

## 8. 兼容与回滚

- 新中心 × 旧目标：无能力声明，继续 v2。旧中心 × 新目标：忽略响应头，继续 v2。
- 新节点 × 旧中心：终端流角色在认证阶段被拒，broker 退避，轮询中继照常。
- 浏览器不支持或代理缓冲 SSE：自动回退长轮询。
- 回滚到旧版本不需要数据迁移；流式连接与 SSE 订阅都只在内存中。
