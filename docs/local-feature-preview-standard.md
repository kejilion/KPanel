# KPanel 本地功能预览标准

## 1. 目标与边界

涉及本地可安全复现的用户可见页面、交互、文案、布局或状态反馈时，功能会话必须在形成候选提交后提供
一致、可操作、可追溯、可停止的验收预览，让用户在合入前真实体验受影响旅程。
本标准解决端口冲突、候选不明、只给截图、mock 与真实数据混淆、缺少操作说明和预览残留；不替代
L0-L3、CI、隔离真机、公开产物或生产部署安全核对。

纯后端、文档、测试/构建基础设施或只能依赖宿主机、Docker、脚本、跨节点、重启等登记隔离环境验证的
任务，可以将本地预览标记为“不适用”，但必须写明没有本地可见旅程，或本地预览不能真实证明的能力
边界；不得为了满足形式要求启动空白页面、无关旧页面或把 mock 冒充真机。

权威机器入口为 `scripts/local-feature-preview.mjs`，执行适配为
`.codex-workflows/local-feature-preview.workflow.yaml`。其他文档只引用，不复制命令清单。
界面字号、视觉层级、主题和可读性以 [`ui-visual-language.md`](ui-visual-language.md) 为准；本预览标准只定义
预览交付和证据分层。

## 2. 三层预览

| 层级 | 数据与运行时 | 适用范围 | 可以证明 | 不能证明 |
| --- | --- | --- | --- | --- |
| UI Mock | 本地 Vite + 明确模拟 API | 布局、交互、文案、状态呈现 | 受影响 UI 旅程可操作 | 真实接口、权限、宿主机、Docker、脚本 |
| Local Integration | 本地 Vite + 回环候选 Panel/API | 前后端契约、本地真实状态 | 当前本地候选接口闭环 | 隔离发行版、公开镜像、生产现场 |
| Isolated Real Host | 本地浏览器 + 登记隔离环境 | 系统、Docker、脚本、重启、兼容 | 声明环境中的真实闭环 | 未测试发行版和生产普遍性 |

选择最低但足够的层级。纯 UI 不机械启动真机；依赖宿主机真实状态时不能用 mock 获得“已验证”。远程层
必须先通过 `environment-policy.json`，长时间浏览器任务使用 `background-browser-validation`。

## 3. 草稿与验收预览

- `draft`：允许 dirty worktree，适合实现中确认方向；必须声明尚未冻结，并记录 working tree fingerprint。
- `acceptance`：只允许已经通过任务候选完成检查的 clean checkpoint，证据绑定精确 commit、环境和参数；
  候选变化后证据立即失效，必须重新提交并重做受影响预览。

验收预览可在未推送的本地候选提交上运行；提供预览不授权 SSH 推送、主线或任何发布状态。

### 3.1 风险画像

每个预览只选择一个验收画像，避免把完整视觉矩阵机械套到所有修改：

| 画像 | 适用范围 | 最小证据 |
| --- | --- | --- |
| `interaction` | 文案、普通表单、确定性操作或非布局逻辑 | 受影响入口、成功旅程、一个失败/空状态、实际受影响视口和键盘/控制台 |
| `visual` | 字号、间距、主题、响应式、图标或布局 | `interaction` 加 100%/200% 缩放、受影响浅/深主题、最小计算字号和窄/宽视口 |
| `visual-composition` | 多种实体、选中/加载等状态、徽章/浮层/固定栏会同时出现，或修复过视觉逃逸 | `visual` 加“实体 × 状态 × 共存层”的受影响组合；至少形成一个真实共存场景和对应自动回归 |

只覆盖实际改变且能够同时出现的组合，不做全量笛卡尔积。`125%` 在紧凑布局、固定高度、像素取整、
断点或历史缩放缺陷受影响时加入；其余任务不因模板存在机械多跑。已经发生过“单项都正确、组合后异常”
的旅程必须使用 `visual-composition`，不能用分散截图替代共存状态。

## 4. 强制交付内容

每个适用的可见功能任务在候选提交后至少交付：状态、等级、数据模式、验收画像、功能入口、branch/commit/clean 状态、访问 URL、
3–7 个“操作步骤 => 预期结果”、受影响体验维度、最小计算字号及用途、未验证边界、证据目录和停止方式（精确停止命令）。启动器必须把验收画像和步骤写入 manifest，Mock 与 dirty 状态必须放在首句，
不得埋在报告末尾。

为兼容规范升级前已经启动的会话，`draft` 可暂时省略步骤，但 manifest 必须标记“兼容草稿”，且不能交付
为验收结果；`acceptance` 始终强制提供 3–7 个步骤。新任务不得利用兼容分支规避预览卡。

预览 URL 必须绑定 `127.0.0.1`，端口自动选择或由任务显式独占；禁止 `0.0.0.0`、公网地址和为抢占端口
关闭其他会话。预览不保存或交付密码、Token、Cookie、恢复码和真实生产数据。

## 5. 体验验收最小矩阵

按受影响范围选择，不要求无关页面机械全跑：

1. 核心成功旅程可以从明确入口完成，结果可回读；
2. 至少一个真实加载、空或失败状态，错误可理解且可恢复；
3. 按风险画像覆盖受影响视口与缩放；`visual`/`visual-composition` 至少覆盖 100% 和 200%，仅在紧凑布局、断点、像素取整或历史缺陷相关时增加 125%，无关键遮挡或横向溢出；
4. 键盘可达、焦点可见，弹窗关闭后焦点合理返回；
5. 受影响浅/深色及中英文/其他语言没有明显退化；
6. 浏览器控制台无本次引入的未处理错误；
7. 写操作只在授权数据和环境执行，完成后验证真实状态与失败恢复。

`visual-composition` 还必须列出本轮改变的实体变体、状态和共存层，只跑能同时出现的受影响组合。
例如文件/目录图形、选中态和右上角传输徽章若可同时出现，应在同一浏览器场景断言，而不是分别证明。

UI Mock 的“真实失败状态”指 mock API 确实返回失败/空数据，不是口头推测；涉及真实资源的失败恢复仍须
在 Local Integration 或 Isolated Real Host 验证。

## 6. 生命周期与并行规则

- 一个 preview ID 对应一个 worktree、source identity、manifest、日志目录和进程集合。
- acceptance 预览的 source identity 必须等于当前候选提交；候选提交改变即失效，不得继续交付旧 URL
  作为当前验收入口。
- 启动器自动分配回环端口；同一 scope 已有活动预览时不得覆盖其证据目录。
- `status` 是本地预览状态真源；浏览器标签仍打开不代表服务健康。
- 启动会话负责预览进程。交付时若保持 ready 供用户验收，必须同时给出 manifest、停止命令和责任人；
  用户验收结束或会话交接后再由明确责任方停止，不得交付后立即关闭导致用户无法体验。
- 停止只允许处理 manifest 中且命令行仍含 ownership marker 的 PID，防止 PID 复用误杀。
- 运行态证据位于 `.codex-tmp/previews` 或指定非跟踪目录，不进入 Git。

## 7. 统一结论语言

- “模拟数据预览可用”：只表示 UI Mock 旅程完成。
- “本地集成预览可用”：表示当前回环候选接口旅程完成。
- “隔离真机已验证”：必须同时写出环境、候选、命令和恢复结果。
- “功能已验收”：必须满足任务 L0-L3、受影响旅程和 Definition of Done，不能只由预览启动成功推出。

预览失败时报告失败阶段、日志路径和是否已清理；不得只更换端口重启后隐藏首轮失败。

## 8. 回滚

本标准不修改产品运行数据。停止预览使用 manifest 返回的精确命令；规范候选如造成明显额外负担，可回滚
本规范、工作流、启动器和 mock 端口参数提交，原有 `npm run dev` 仍保持可用。
