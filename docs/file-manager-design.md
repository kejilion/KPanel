## 1. 业务定位

文件管理是 KPanel 对宿主机文件系统的日常文件工作台，入口位于左侧“体检”上方。
它服务于网站文件、应用数据、备份和普通用户目录，不替代 SSH，也不接受任意 Shell。

产品原则：

- 已登录管理员可以管理 `/` 下的普通文件，不以“是否由 KPanel 创建”限制操作。
- KPanel 自身运行目录、凭据和任务状态始终隐藏且不可读写。
- 默认使用专业列表视图；目录快捷入口、批量选择、右键菜单和快速预览保持一屏可用。
- 大文件传输采用流式代理，不把完整内容载入 Panel 或 Agent 内存。
- 写入后重新读取真实文件状态，不维护第二套文件事实。
- 显式下载是可靠兜底：单个普通文件使用短时 download ticket；单个目录或批量选择由用户明确触发，
  先封存精确选择和版本到短时 archive ticket，再下载受限 ZIP。Chromium 私有 `DownloadURL` 只作为
  尽力而为的操作系统拖出渐进增强。

## 2. 首版范围

### 文件操作

- 浏览目录、搜索当前目录、排序。
- 新建文件夹、上传、下载。
- 从公开 HTTP/HTTPS 地址流式下载单个文件到当前目录；可指定名称，同名自动追加序号且不覆盖。
- 重命名、复制、移动和移入回收站。
- 批量复制、移动、下载和移入回收站。
- 回收站查看、恢复、选择性彻底删除与清空；恢复不覆盖原路径中的同名项目。
- 批量压缩为 TAR.GZ、ZIP 或 TAR；默认推荐 TAR.GZ。
- 将 TAR.GZ、TGZ、ZIP 或 TAR 解压到新文件夹；不覆盖已有目录或文件。
- 查看并修改 POSIX 权限。
- 显示名称、类型、大小、权限、所有者、修改时间和资源版本。

### 查看与编辑

- 文本与代码：纯文本、Shell、Go、JavaScript/TypeScript、Vue、HTML/CSS、JSON、YAML、
  TOML、INI、Nginx、日志、Markdown。
- 图片：PNG、JPEG、GIF、WebP。
- 文档：PDF。
- 媒体：浏览器支持的音频和视频。
- 压缩包：ZIP、TAR、TAR.GZ/TGZ 可直接打开只读目录、进入子目录和搜索；勾选成员后保留包内相对路径解压，也可整包解压或继续下载。目录响应未明确通告归档管理能力时，不探测新路由、不显示包内浏览、批量解压和后台任务；压缩与单包解压继续使用既有同步 `/files/actions`。已通告能力后的任务读取故障只显示真实错误并有限重试，不回退或自动重放写操作。
- 编辑器使用懒加载的轻量 textarea + 行号、Tab 缩进、快捷保存和冲突检测，不引入大型 IDE 依赖。

基础首版不包含跨主机传输、Git 客户端、终端或数据库文件解析；后续跨 KPanel 复制和公开 URL
远程下载均以固定协议独立加入。Git 客户端和数据库文件解析仍不在当前范围，也不得通过任意 Shell
临时补位。远程下载不支持 BT/magnet、批量 URL、自定义 Header/Cookie/代理、私网来源、自动解压、
断点续传或自动重试。后台任务允许关闭或刷新文件页面后继续，但不把完整 URL 持久化，因此 Panel
进程重启后不会自动续传或重试。

## 3. 信任边界与质量记录

```text
浏览器
  -> Panel Session + Origin + CSRF
  -> Panel 流式代理 / 公开 URL 受限 GET
  -> Unix Socket + Agent Token
  -> Agent 固定文件动作
  -> /（排除保护目录与内核虚拟写入口）
```

| 项目 | 设计 |
| --- | --- |
| 流量路径 | 浏览器仅访问 Panel；Panel 通过现有 Unix Socket 调用 Agent |
| 不可信输入 | 虚拟路径、文件名、批量来源、目标目录、权限、上传内容、文本内容、Range、远程 URL、重定向和响应头 |
| 权限与可写范围 | `os.Root` 固定根 `/`；保护 KPanel 凭据/状态目录及回收站，`/proc`、`/sys`、`/dev` 只读；回收站固定在 Agent 实际状态目录内 |
| Agent 服务边界 | systemd 保持文件管理根目录可写并对 Panel 状态单独设置 `ReadOnlyPaths`；OpenRC 使用 root:group、`no_new_privs`、严格 umask 和受保护配置，但没有等价 mount namespace；写入仅授予 root Agent，Panel 容器不挂载宿主机根目录 |
| 最坏输入/输出 | JSON 64 KiB；远程 URL 4 KiB、响应头 64 KiB；文本编辑 2 MiB；新版接收会话及 URL 下载普通文件 10 GiB，旧一次性上传兼容路径 512 MiB；列表单页 500 项、最多扫描 20,000 项；回收站最多 10,000 项、单次显示 500 项；批量 100 项 |
| 最大并发 | 上传 2、远程下载 2、下载 4，超限立即返回 `429`；远程下载最终还受 Agent 上传总闸门约束；复制、移动、压缩、解压及回收站操作串行执行；复制和归档预算按整批累计 10,000 项/10 GiB |
| 超时、取消与重试 | 普通 API 保留短超时；文件流使用 45 秒上游正文空闲超时和 2 小时硬上限；压缩/解压及远程下载可由页面主动取消；取消清理尚未提交的临时产物，若与原子提交重叠则刷新目录确认；新版接收会话来源最多重开 3 次，分块与提交最多尝试 3 次，始终只保留已持久确认的前缀；旧一次性写入不自动重放 |
| 真实状态 | `Lstat`、打开后 `Stat`、目录内容和文件元数据 |
| Linux 路径身份 | 共用文件根逐段查验并固定父目录身份，文件打开由目录描述符执行且拒绝末级链接；编辑、复制、移动、发布、元数据更新与清理共用此边界；非 Linux 实现仅用于本地工具 |
| 失败与回滚 | 上传/编辑使用同目录临时文件、`fsync` 和原子替换，并保留权限、所有者与 Linux 扩展属性；复制失败清理目标临时产物；回收站元数据原子写入，恢复与彻底删除逐项报告结果 |
| 性能预算 | 文件页面懒加载；不增加首屏包；普通流式拷贝使用 64 KiB 缓冲，新版接收会话使用 8 MiB 校验块；目录搜索在 Agent 有界执行并按 500 项分页；多选上传与目录拖入按 Agent 上传闸门并发 2 路；缩略图带 `resourceVersion` 的 URL 只对 200/304 返回 `private, max-age=3600`，Agent 先处理 `If-None-Match` 再进入生成闸门，并在进程内按路径与版本缓存最多 8 MiB（不落盘），其余文件响应保持 `no-store`；远端完整 KPanel 声明 `panel-stream-v3` 时文件请求走可复用的 Noise 流式连接，见 [终端与文件传输 v3](terminal-file-transport-v3.md) |
| 网络入侵风险 | 路径穿越、符号链接逃逸、CSRF、超大请求、恶意 MIME、SSRF、DNS rebinding、重定向绕过、签名 URL 泄漏、资源耗尽 |

### 3.1 Windows Chromium 下载兼容边界

- Windows 实机先复现了 KPanel HTTPS 目标 `FILE_BLOCKED` / 0 B；后续同目标严格 A/B 中，来自
  `127.0.0.1` 的 `text/plain` 与 `application/octet-stream` 曾同时成功，随后同一发起 origin 的全部
  载荷又失败。新标签页恢复原文件名仍失败，`no-referrer` 也失败；仅把发起 origin 改为 `localhost`
  后四种载荷又全部成功。故这不是固定 MIME、文件名、载荷顺序或目标内容问题，而是下游安全分类会随
  initiator、tab、referrer、navigation 等页面环境变化；现有证据不能唯一归因具体安全组件。
- Chromium 源码确认拖出下载保持 `content_initiated=false`，不进入 automatic download limiter；该
  limiter 的拒绝也不会生成已观察到的 History `FILE_BLOCKED` 项。Google Transparency 当前公开状态未
  报告 `kpanel.kejilion.eu.org` 威胁，但该站点状态不等于某次 download protection verdict。
- 页面只能得知 HTML 拖拽生命周期，无法取得 Chromium 下载器或 Windows Explorer 的最终落盘结果；
  `dragend`、`dropEffect` 和是否发出网络请求都不能作为文件已保存的成功回调，也不能据此自动重试。
- 候选保留 `DownloadURL` 作为渐进增强：受支持 Chromium 场景可尝试把文件拖到 Explorer，但产品不
  承诺落盘，也不得写成已修复 `kpanel.kejilion.eu.org` 的客户端拦截。失败时始终引导用户使用显式入口。
- 可靠兜底是用户显式点击下载：单个普通文件先由已认证请求创建短时 download ticket；单个目录或
  批量选择由同源、Session、CSRF 保护的 POST 创建 archive ticket，服务端封存精确来源、版本和 ZIP 名，
  浏览器只取得不含路径和选择集的 5 分钟短 URL。页面只报告 ticket/URL 构造和下载启动阶段错误，不把
  浏览器或操作系统最终落盘状态误报为成功。
- ticket 消费时 Panel 通过内部 `POST /v1/files/archive?name=...` 把选择 JSON 放在 body 中；旧 GET query
  仅为同步 `DownloadURL` 兼容保留，避免显式批量下载再次撞上 Agent 的 16 KiB 请求头上限。
- 页面内、跨窗口和跨 KPanel 的拖拽载荷及后端重新鉴权不依赖操作系统原生拖出；浏览器拒绝
  `DownloadURL` 时，这些路径继续可用。
- 不得把伪装扩展名或 MIME、删除 CSP/`nosniff` 等安全响应头、延长 URL 凭据或切换下载域名描述为
  修复。`127.0.0.1` / `localhost` 对照改变的是发起 origin，不证明更换下载域有效；组织管理设备继续
  遵循既有安全策略，KPanel 不提供绕过或弱化方案。
- Windows 现场证据、KodBox 对照和复现命令统一记录在
  [`windows-file-download-compatibility.md`](windows-file-download-compatibility.md)。

### 3.2 归档安全与兼容契约

原生缩略图和静态图片预览先读取受既有源文件字节上限约束的内存快照，尺寸、像素预算、元数据及完整解码使用同一份不可变内容，避免源文件原地变化绕过检查。

- Agent 直接使用 Go 标准库流式处理，不调用宿主机 Shell、`tar`、`zip` 或第三方常驻服务。
- 压缩和解压均固定目标目录句柄，在同文件系统最近的 Agent 所有且不可由 group/other 写入的祖先目录内建立私有隐藏暂存目录，使用 `fsync` 和不覆盖原子改名；目标目录仍允许业务用户写入。发布前后复核目标及产物身份，失败或取消仅清理身份相符的暂存对象；没有可用受保护祖先目录时返回冲突，不转为跨文件系统发布。
- 新建内容继续继承所选目标目录的默认 ACL，而非暂存祖先的默认 ACL；只向私有暂存目录复制默认 ACL，外层访问权限保持私有。
- 单次最多选择 100 项，累计最多 10,000 个条目、10 GiB 原始/解压数据；固定 64 KiB 缓冲，
  不把完整压缩包或文件载入内存。
- 实际展开对象也最多 10,000 个，包含隐含父目录；重复父目录只计一次，显式目录稍后出现不重复计费。
- 单个目录或批量选择的显式 ZIP 下载复用相同遍历、版本、并发和容量预算；写出首字节前完整预扫描
  symlink、特殊文件、条目数和字节预算，并再次复核顶层版本。不同目录的同名顶层来源按 Windows
  大小写不敏感规则稳定追加 ` (2)` 等后缀；重复同一路径仍拒绝。
- 请求取消或预扫描后的并发源变化会停止流；失败归档不写入服务器文件系统，也不生成完整 ZIP 中央目录。
- `walkArchive` 在递归进入每个子项前重新过滤 protected descendant 与 `.kpanel-*` 内部临时组件；
  定向测试确认允许祖先目录中的正常文件保留，保护后代及内部文件/目录不会进入 ZIP。
- 解压拒绝绝对路径、`..`、反斜杠路径、重复条目、符号链接、硬链接、设备文件和特殊文件，
  不能通过压缩包逃逸目标目录或覆盖现有内容。
- ZIP 在构造中央目录对象前先读取尾部目录记录并拒绝超过条目上限的归档，避免恶意中央目录先行
  消耗大量内存；实际解压字节仍按流量预算再次检查。
- 处理前后复核源文件资源版本及 inode；保留普通文件和显式目录的权限与修改时间。
- 单目录压缩时归档其内容，解压到默认同名文件夹后不会产生 `目录/目录` 双层嵌套；多选时保留
  每个来源的顶层名称。

#### 当前候选：包内浏览与后台归档任务

相同归档改动曾进入 `v1.11.0` 标签，但该版本在生产升级前按用户决定整体撤回，生产始终运行
`v1.10.0`；主线随后以 `d5fe5b3` 恢复 1.10.0 文件树，并以 `4f4e6ab` 记录撤回。撤回不表示已观测到
归档生产故障，也不表示该能力仍存在于当前稳定版；旧版本的 CI、L3 和实机证据仅作历史参考，当前候选
仍须按新的精确提交复验。详见 [`release-v1.11.0-acceptance.md`](release-v1.11.0-acceptance.md)。

- 复用 `Panel → Agent → filemanager`；轻量节点和跨面板文件转发只扩展固定的 `archive-contents`、
  `archive-jobs` 路由。写入继续经过 Session、Origin、CSRF 和现有文件权限；不增加 Shell 或第三方依赖。
  `scriptLinkageState=not-required`（无需发布脚本（不适用））。
- 支持状态由已成功读取的目录响应通过可选 `archiveManagementAvailable` 明确通告；旧 Agent 缺少字段时
  自然进入兼容模式。任务列表读取状态与能力状态分离，避免临时 503 或目录刚显示时误走同步写入。
- 界面复用文件列表、右键、多选工具栏、标准弹窗和语义颜色。默认目标为当前目录，解压默认新建同名目录；
  已有结果不覆盖、不合并。批量解压每个包各建目录，逐项保留成功与失败结果。包内单页超过 100 项时
  不提供整页全选，逐项选择达到 100 项后锁定其他条目；切换目录、搜索或翻页会清空选择。
- 包内页每页最多 500 项；ZIP 先核实中央目录实际位置、长度和条目数，再冻结不超过 8 MiB 的目录及
  最多 64 KiB 的尾注后交给标准库，避免伪造声明或源文件并发变化放大分配。拒绝加密、分卷及 ZIP64
  目录；普通 ZIP、TAR、TAR.GZ/TGZ 和标准 TAR 的 `./` 根目录可读。浏览不等同于整包 CRC 完整性校验。
- TAR 浏览消耗有界顺序流，最多 2 分钟；每个 Agent 仅缓存一份、5 分钟、最多 8 MiB 的成员索引，包含
  隐式目录，按文件资源版本失效。浏览和选择解压仍校验未选择成员的路径、类型和总预算。
- Agent 最多保留 50 个任务、7 天历史；最多接收 4 个活动任务，单个执行，2 小时硬截止，整批累计
  10,000 项/10 GiB。显示已处理的条目与数据预算，不预测剩余时间或生成百分比。文件读取可继续，写入
  保持原串行保护；排队等待支持取消。仅活动任务轮询；首次临时读取失败最多自动重试 3 次，随后可手动刷新。
- 关闭窗口或断开请求不取消已接收任务；重新打开同一主机的文件管理可从该主机 Agent 恢复状态。本机归档
  任务还会汇入当前 Panel 的“任务中心”；通过 `hostId` 发往轻量节点或远端 Panel 的任务，只由发起端对应
  主机的文件管理窗口读取，不汇入发起端 Panel 的 `/api/v1/jobs`。目标为另一 Panel 时，其自身任务中心仍可
  按本机 Agent 来源展示该任务。停止后保留已完成结果；仅存在未完成来源时提供重试，并重新读取源版本、
  核对目标和名称、保留成员选择。
- 在受保护的 Agent 文件状态目录原子保存有界任务日志（最多 2 MiB）；固定目录句柄、拒绝链接与损坏日志。
  重启把未完成状态标为中断，不自动重放写入；只有日志中的目标父目录、实际暂存父目录和暂存对象身份同时匹配时才清理，保留已提交结果。旧日志缺少对象身份、路径已替换或身份不明时保留对象并提示核对。
  状态保存失败不报告完成。取消与原子提交重叠时提示核对目标目录。
- 当前范围不含密码、RAR/7z/XZ/Zstd、分卷、覆盖合并、包内直接编辑及重打包。新增失败注入和恢复测试为
  本地隔离文件系统验证；Mock 预览仅证明交互和布局，不代表远程实机或 L3 发布验收。

### 3.4 远程下载安全与生命周期契约

接收会话的正文暂存仍位于目标目录；文件与目录提交复用归档的受保护同文件系统祖先，在私有目录中发布已校验对象。日志绑定实际发布暂存父目录及对象身份，重启对账、取消与清理都使用该位置。旧日志只核对原记录位置，不猜测或删除另一个祖先目录中的同名对象。

```text
Browser POST JSON（URL 只在 body）
  -> 非 root Panel 专用下载客户端
     -> 公开 HTTP/HTTPS 固定 GET
     -> DNS 全部地址 fail-closed 校验并直拨 IP
     -> 最多 5 次重定向，每跳复核，拒绝 HTTPS -> HTTP
  -> Agent /v1/files/transfer/sessions（创建、顺序校验分块、持久确认、提交）
  -> 同目录暂存、fsync、no-replace 原子发布
  -> 旧 Agent 不支持接收会话时兼容 /v1/files/upload
```

- HTTP URL 最多 4096 字节，只接受绝对 HTTP/HTTPS；拒绝 userinfo、fragment、控制字符、反斜杠、
  IPv6 zone、模糊数字主机、单标签主机和非法端口。
- DNS 返回的每个地址都必须是公开 global-unicast；任一结果为 loopback、RFC1918/ULA、link-local、
  multicast、unspecified、CGNAT、文档/基准保留段、IPv4-mapped、NAT64、6to4 或 Teredo 时整次拒绝。
  实际连接只拨已校验 IP，保留原 Host 与 TLS SNI，避免第二次系统解析造成 rebinding。
- 客户端不读取环境代理，不接受自定义方法、Header、Cookie、Authorization、Host、请求体、私网
  allowlist 或跳过 TLS。固定 `Accept-Encoding: identity`，拒绝压缩响应；跨域重定向清除 Referer，
  避免源 URL 的查询签名泄漏。
- 首次 GET 接受完整 `200 OK`；持有强 ETag 和完整长度时，重连允许经过精确范围、ETag 和最终 URL
  校验的 `206`。忽略 Range 或缺少强验证器时，重读并核对已确认前缀；来源变化即停止。上游错误
  正文不落盘、不回显，压缩响应和其他 `2xx` 仍拒绝。新版普通文件上限为 10 GiB，旧上传兼容路径
  为 512 MiB；已知超限提前拒绝，未知长度在流中按路径限额中止。DNS 与最多 8 个候选 IP 共用一次
  连接阶段时限，TLS、响应头、正文空闲和总时长也均有界。
- 保存名称优先级为管理员明确名称、有效 Content-Disposition、`download`；不从 URL 路径推断名称，
  避免路径型签名令牌进入文件名、状态或审计。每个候选只可作为 255 字节以内 basename，不得决定
  目录。已有同名文件时在下载前生成 ` (1)` 等后缀，
  最终提交仍使用 no-replace 处理竞态，绝不静默覆盖。
- 默认 UI 创建后台任务，状态为 `queued -> connecting -> transferring -> confirming -> complete|error`；
  用户停止后为 `cancelled`。已知总量显示真实进度，未知总量只显示已接收字节，不伪造百分比。
  新版会话的 `confirming` 表示分块已确认，正在验证完整内容并提交；旧上传路径则核对上传返回结果。关闭、
  刷新或离开文件页面只停止浏览器轮询，Panel worker 继续；旧的请求作用域 NDJSON POST 保留兼容。
- Panel 任务索引只持久化脱敏 origin、目标目录、安全名称、字节数、状态、结果与时间。完整 URL 只在
  worker 内存中存活，不进入索引，所以 Panel 重启会把遗留 active 状态保守标记为 `interrupted`，不自动
  重放 GET。用户必须先刷新目标目录确认原子提交结果，再重新输入 URL；这避免在提交后、状态落盘前崩溃
  的窗口重复保存文件。
- 下载并发仍与同步兼容接口共享 2 个槽位；后台 running + queued 最多 10 个，任务历史最多 100 条，
  terminal 状态保留 7 天并允许用户清理。索引使用私有目录、`0600` 文件、大小上限和原子替换；损坏时
  后台任务 fail-closed 为不可用，旧同步接口不依赖该索引。
- 停止会取消上游读取并清理尚未提交的隐藏暂存文件；若停止或进程退出恰逢原子提交窗口，界面必须
  提示刷新真实目录确认。目录不会出现半文件，但任务状态不能替代目录事实。
- 审计仅记录 `scheme://host[:port]`、目标目录、安全文件名、字节数和结果码；完整 URL、路径、查询串、
  重定向链、响应正文及底层 `url.Error` 不进入审计、状态、Toast 或服务端错误。

### 3.5 智能下载与 BT 来源适配

- HTTP 默认智能模式，可在提交前关闭。文件至少 64 MiB，服务器明确声明 `Accept-Ranges: bytes`，且
  有完整长度与强 ETag 才可试探。每完成 16 MiB 持久确认评估一次；来源耗时显著高于目标写入且剩余
  工作足够时试两路，每路 2 MiB 有界分片。至少 15% 的端到端窗口收益才保留，无收益回到单路；每任务
  最多一次试探。全局附加分段缓冲最多 8 MiB，不重复叠加通用预取。切换只发生在 Agent 已确认偏移，
  所有分片复用现有 URL、DNS、TLS、Range、ETag 校验；忽略 Range 时验证完整重读前缀，不能混拼。
- 同一输入支持公开 HTTP/HTTPS、以 `.torrent` 结尾的网址、导入 `.torrent` 文件及 btih 磁力。
  API 对无 `.torrent` 后缀的种子网址可显式传 `sourceKind: "torrent"`。候选仅支持 BitTorrent v1，
  不支持 v2/hybrid；metadata 最多 512 KiB、512 个文件、32 层路径、10 GiB 总量、8 MiB 单 piece。
- BT 引擎固定 `github.com/anacrolix/torrent v1.61.1-0.20260911233437-76452a2c8a2f`，运行在无特权 Panel，按需创建、任务结束关闭。
  HTTP tracker 走原专用客户端；UDP 和 DHT 通过公网过滤套接字，DHT 只接受最近查询端点的有界响应。
  不监听 peer、不映射端口、不上传正文或完成后做种。仅下载限制会影响部分需要互惠的 swarm/私有站点。
  全程禁用 PEX；私有任务须提供 `.torrent`，以便在发现节点前禁用 DHT。磁力在元数据确定前可能查询
  DHT；获知 private 标记后立即停止并提示导入种子，不下载正文或重新拨号，不承诺私有磁力隐私。
- 磁力 info 在原始 bencode 长度/深度检查后受控组装，piece 0 在完整 SHA1、路径与容量验证通过前不交给
  库解码；工作循环在库锁外设置已验证 info。拒绝 xs/as/webseed/显式 peer/DHT 节点等旁路来源。
- BT 与 HTTP、跨主机共用任务准入、取消、历史和 Agent receive，BT 额外的单任务资源额度先于公共
  两个传输槽位申请，等待 BT 额度不占用 HTTP 槽。HTTP 自适应衡量来源+目标；BT 自适应只衡量来源
  校验速度与暂存写压力，连接上限从 4 试到 8/16，收益不足回退，堆占用过高时收缩。无可用节点时无法
  凭空加速，2 分钟无已校验进展失败。关闭智能模式仍保留协议本身的分片与最多 4 个 peer。
- 来源获取时 `sourceBytes` 是已校验片段总量，`loadedBytes` 仍为目标持久确认字节（此时为零）。随后
  单文件或确定性 TAR 进入同一接收层，失败重读已验证前缀，完成后一次原子发布；界面明确分阶段。
  保存名称适用于单文件或整包目录，目标路径永远由文件管理与 Agent 校验，不由种子决定。
- BT 只支持统一后台任务入口，关闭页面继续，取消清理，重启标记中断并清除来源暂存，不新增暂停/续跑
  队列。缓存、空间峰值和回滚索引规则见 [存储策略](storage-strategy.md)。

## 4. 路径和隔离

API 使用以 `/` 开头的虚拟路径，与宿主机绝对路径一一对应；页面默认定位 `/home`。

每次操作执行：

1. 拒绝 NUL、反斜杠、过长路径、空组件、`.` 和 `..`。
2. 所有读取、写入、重命名、复制和回收操作都通过 Go `os.Root` 根句柄执行，
   即使路径组件在检查后被并发替换，也不能通过符号链接跳转。
3. 对已有路径的每级组件执行 `Lstat`，拒绝跟随符号链接。
4. 检查最终路径不位于保护目录；会移动、改名或改变权限的操作同时拒绝保护目录的祖先，
   避免通过父目录移动、改权或删除间接影响 KPanel 凭据和状态目录。
5. 打开后再次 `Stat`，避免把链接替换竞态解释为普通文件；不覆盖式重命名在 Linux
   使用 `renameat2(RENAME_NOREPLACE)` 原子完成。

符号链接可以作为目录条目显示，但不可进入、预览、下载、编辑、复制或移动到根外。

## 5. API

除远程 URL 抓取只存在于无特权 Panel 外，Agent 与 Panel 使用相同资源路径，Panel 增加 `/api` 前缀：

```text
GET  /v1/files?path=/docker&limit=200&offset=0&search=log
GET  /v1/files/trash
GET  /v1/files/content?path=/docker/app/file&disposition=inline
GET  /v1/files/content?path=/docker/app/file&disposition=inline&mode=text
PUT  /v1/files/content?path=/docker/app/file
POST /v1/files/upload?path=/docker/app&name=file
POST /v1/files/actions
POST /v1/files/archive-contents
GET  /v1/files/archive-jobs[?id=<job-id>]
POST /v1/files/archive-jobs
POST /api/v1/files/remote-downloads
GET  /api/v1/files/remote-downloads
GET  /api/v1/files/remote-downloads/{id}
POST /api/v1/files/remote-downloads/{id}/cancel
DELETE /api/v1/files/remote-downloads/{id}
```

浏览器选择远端主机时，仅 Panel 的 `/api/v1/files/...` 形式附加 `hostId`；发起端验证 Session，写请求
另验证 Origin/CSRF，然后通过固定文件 relay 转发，目标 Agent 仍只接收不含 `hostId` 的
`/v1/files/...` 路径。`/api/v1/jobs` 不接受 `hostId`，只汇总当前 Panel 直连 Agent 的任务来源。

远程下载请求固定为 JSON：

```json
{
  "url": "https://downloads.example.com/archive.tar.zst?signature=...",
  "targetDirectory": "/home/downloads",
  "name": "archive.tar.zst",
  "background": true
}
```

`name` 可省略，接口不接受 `overwrite`。`background: true` 成功返回 `202` 和脱敏任务；省略该字段时
保留流式 `application/x-ndjson` 兼容响应。URL 不进入 path、query、Agent 请求、任务索引或 Jobs API。
创建、停止和清理属于写操作，必须通过 Origin、Session、CSRF 与审计；读取任务要求 Session。预流式
校验失败使用 RFC 7807，连接后的业务失败使用稳定 `code`，前端不得显示底层含 URL 的错误字符串。

`POST /files/actions` 仅接受固定动作：

```text
mkdir
rename
copy
move
compress
extract
trash
chmod
trash_restore
trash_delete
trash_empty
```

批量操作最多 100 个来源。编辑、回收、恢复和彻底删除请求携带资源版本；资源变化返回 `409`。
复制、跨文件系统移动和回收站操作共享整批累计预算，不能通过一次请求携带多个来源绕过容量限制。
批量操作逐项返回成功与失败结果；部分成功使用 `207 Multi-Status`，页面始终重新读取目录，
避免把已完成的文件变更误报为整体失败。
编辑器读取必须显式使用 `mode=text`，Agent 会复核当前大小、UTF-8 编码和 NUL 字节；
图片、PDF 和音视频仍使用 Range 流式读取。

目录列表单页稳定排序，前端合并分页后重新排序；单页最多 500 项，`offset` 用于加载后续页，`search` 在 Agent
侧最多扫描 20,000 个可见条目。达到扫描边界时 API 返回 `scanTruncated`，前端明确提示，
不把未扫描内容误报为“没有匹配项”。

常驻 Agent 暂不直接设置 `MemoryMax` 或 `CPUQuota`：应用、建站和诊断任务可能由 Agent
派生到独立 systemd unit 或 OpenRC 进程组，给常驻服务增加硬配额会改变既有任务行为。当前先在文件 API
入口实施体积、并发、目录扫描和累计复制预算；若后续增加常驻服务资源配额，必须先完成
子任务 cgroup 完全隔离和多发行版实机验收。

## 6. 前端交互

- 左侧导航：文件位于 Docker 与体检之间。
- 顶部命令栏“图库”以图库方式打开当前文件夹（根目录 `/` 打开图库位置），设计见 [图库设计](media-gallery-design.md)。
- 默认列表：目录优先，列出大小、权限、所有者和修改时间。
- 双击目录进入，双击文件打开查看器。
- 成功进入目录后才把 Agent 确认的规范路径写入浏览器历史；前进、后退和刷新按 URL 中的
  `path` 恢复目录，失败或被后续导航取消的读取不新增历史记录，也不能覆盖较新的目录状态。
- 右键菜单与顶部/批量工具栏调用同一动作定义，避免能力不一致。
- 顶部命令栏直接显示“远程下载”。弹窗只包含下载地址、可选保存名称和当前目录快照；提交后立即
  清空 URL 输入并关闭弹窗。轻量任务列表显示脱敏来源、安全名称、目标目录、阶段、真实字节进度，
  active 任务可停止，terminal 任务可清理。页面进入时重新读取任务，存在 active 状态时才轮询；页面
  卸载只停止轮询，不取消服务端任务。完成当前可见目录的任务后刷新目录。
- 界面明确说明关闭页面后继续、Panel 重启时任务会标记中断且不会自动重试、完整 URL 不保存。停止、
  中断或错误与原子提交重叠时结果可能已保存，需要先刷新目标目录确认。
- 批量工具栏提供“压缩”；受支持的压缩包右键提供“解压到文件夹”。格式默认 TAR.GZ，用户可选
  ZIP 或 TAR；执行中明确显示运行状态并可停止，不把关闭页面误报为成功。
- 代码查看器使用等宽字体、行号和语法类型提示；编辑保存时执行资源版本冲突检查。
- 可编辑判定由后端内置的文本扩展名、点文件（如 `.gitignore`、`.bashrc`）、`.env.*`/`Dockerfile.*` 等文件名前缀和
  `.bak`/`.orig`/`.example` 等备份模板后缀决定，不依赖宿主机 `/etc/mime.types`；`text/*` 与常见结构化文本 MIME 仅作补充。
  无扩展名文件与点文件不在列表阶段读取内容，由文本读取接口拒绝非 UTF-8 或含 NUL 的内容，保持目录列表 O(1)。
  前端对常用语言按需加载语法高亮（CodeMirror 语言包或 legacy-modes），未知类型按纯文本编辑。
  AI/MCP 文本读取不以可编辑判定授权，另经敏感文件名规则过滤（私钥、凭据点文件、shell 历史及其 `.bak`/`.orig`/`~` 等备份副本）。
- 文本编辑器在同一窗口提供目录列表与最多 12 个文件标签；目录按需分页，最多保留 500 项，更多内容通过服务端搜索定位。
- 编辑器标签与操作合为单层顶栏；窄屏把查找和换行收进更多操作。目录进入/上级仅在读取成功后通过文件管理的窗口路由记入历史，浏览器前进/后退同步目录且保留标签草稿；失败、过期响应与历史恢复不新增历史。
  桌面侧栏展开时占满左侧整列（含顶栏高度），标签与操作栏被挤到侧栏右侧，可收起；窄窗口与手机使用可关闭抽屉；标签支持左右方向键、Home/End 和 Delete，关闭未保存标签或窗口需确认。
  每个文件的草稿、光标、撤销记录、滚动与换行偏好只保存在当前内存会话，刷新离开提示未保存，不写浏览器存储。
  仅可见窗格中的标签挂载 CodeMirror，其他标签保留不可变编辑状态；每次按键不复制完整文本，保存仍绑定原主机、路径与资源版本。
  保存中可切换标签，期间的新输入继续标记未保存；保存失败保留草稿与错误，不能用旧响应覆盖当前标签或清除较新的修改。
- 编辑器与终端共用分屏模型：单屏、左右、上下与四宫格，每个已打开文件最多出现在一个窗格；新文件先填空窗格，
  否则替换当前窗格，分隔条可拖动或用方向键调整。保存、查找、跳转到行、换行与执行只作用于当前窗格；空窗格
  经目录列表选择文件。编辑区窄于 700px、手机视口或窗格放不下两份可读代码时只显示当前文件并隐藏分屏入口。
- 查找栏实时标出全部匹配并显示“当前/总数”（超过 1000 处只显示下限），支持正则、大小写和全字；Ctrl+G 或点击
  状态栏行列跳转到“行”或“行:列”；Ctrl+D 追加下一处相同内容、Alt 拖动列选择，状态栏显示选中字符与光标数。
- 图片、PDF、音视频通过同源受控 URL 预览；视频只有在浏览器实际解码出非零尺寸画面后才标记为可播放，
  避免把“音轨可播、视频轨不兼容”误报为成功，并提供原文件下载及 H.264 + AAC MP4 转换提示；
  HTML、SVG 等主动内容只按纯文本显示或下载。
- 单个普通文件可创建轻量公开分享，同时获得分享页和文件直链；图片直链可供外站嵌入，但不建设独立图床入口。
  分享授权、公开字段、资源限制和回滚边界见 [`file-sharing.md`](file-sharing.md)。
- 普通文件列表中的删除固定进入 KPanel 回收站；彻底删除和清空只在回收站管理界面中提供并要求二次确认。
- 回收站显示原路径和删除时间，可批量恢复、彻底删除或清空；旧版无元数据项目仅允许彻底删除。
- 经典模式双栏：文件区宽度不小于 1200px 时命令栏显示“双栏”，打开后并排出现第二个完整文件管理栏，
  两栏各自选择主机、目录、视图和操作，等同两个桌面文件窗口：同主机拖放默认移动、按住 Ctrl/Option
  复制，跨主机拖放沿用跨主机复制，剪贴板按主机共享。主栏继续使用页面 URL、前进/后退和深链接；
  第二栏使用与桌面窗口相同的独立内存路由，目录和主机只记入浏览器本地偏好
  `kpanel:files:split:v1`（不含打开的文件），离开文件管理的跳转交还页面路由，切换目录不滚动页面。
  键盘快捷键只作用于最近点击或聚焦的一栏，并以边框高亮。文件区变窄到 880px 以下时已打开的两栏
  上下排列而不卸载，避免中断上传与传输。双栏时两栏都显示“关闭此栏”，像关闭两个窗口之一：关闭第二栏
  直接移除它；主栏拥有页面 URL，关闭主栏时改为把主栏导航到第二栏的目录和主机再移除第二栏。关闭前执行
  与关闭桌面窗口相同的未保存编辑确认；将被移除或改换主机的栏有上传、复制、移动等进行中操作时拒绝关闭并提示。
  桌面模式不变，继续使用多个文件窗口和左右吸附分屏。

## 7. 验收

### 多窗口主机上下文

- 文件请求只读取显式 `hostId`，省略或空值固定表示当前 Panel 本机；不得以模块全局选择状态路由请求。
- 每个文件窗口持有自己的主机上下文，并在窗口路由保存 `hostId + path`。本机桌面快捷方式不能复用同路径的远端窗口。
- 上传、目录递归上传和跨主机批量复制在开始时捕获目标主机与路径；其他窗口切换或关闭不得改变后续请求目标。
- 剪贴板与目录变更通知绑定主机，只有同主机窗口共享复制/移动与路径重映射。同页面跨主机拖拽复用现有跨主机复制协议，不能按本机路径执行移动。
- 主机从清单消失、离线或撤权时保留原目标，由现有 API 返回失败；不回落本机、不重放写操作。旧主机的延迟预览响应不能更新新主机窗口。
- 自动组合回归使用真实 `api.ts` 与两个 `FilesView` 实例，mock 仅覆盖网络/上传传输。真实双节点、断线及撤权仍由隔离环境验收，不能由该测试推定通过。

- 单元测试：路径穿越、保护目录及其祖先、归档递归保护后代/内部临时组件、符号链接、慢速传输、
  上传/下载并发、目录分页与服务端搜索、超限上传/编辑、资源冲突、目标不覆盖、整批累计复制预算，以及三种归档格式、
  解压穿越/链接/特殊文件、归档膨胀、取消清理和修改时间保留。
- 远程下载网络测试：URL 语法、公开 IPv4/IPv6、全部受限地址、混合 DNS、固定 IP 拨号、重定向
  上限/私网跳转/HTTPS 降级、Referer 清除、环境代理无效、TLS、响应编码、非 2xx、已知与未知
  长度超限、正文空闲与取消；完整 URL 和上游正文不得出现在响应或审计中。
- Panel 测试：未登录、Origin、CSRF、未知路由、同步流式兼容、后台请求脱离、列表/读取、停止/清理、
  Panel 关闭、索引损坏与 Agent 不可用；持久化状态、API 和审计均不得泄漏 URL 路径或查询签名。
- 前端测试：导航顺序、目录前进/后退/刷新、失败与并发导航、列表、批量选择、右键菜单、
  查看器分类和保存冲突；远程下载目录快照、已知/未知进度、关页继续、重新进入恢复展示、停止、清理、
  中断说明、错误、成功刷新和 URL 不持久化。
- 归档候选测试：包内分页/搜索、100 项选择边界、选择解压、任务排队/取消/恢复、真实 ZIP64 sentinel、
  旧节点能力协商与临时 503 不降级；远端任务不得误入发起端本机任务中心。真实双节点、旧节点组合及
  断线恢复仍须在隔离环境验收，不能由 Mock 或旧 `v1.11.0` 证据推定通过。
- 构建：Go 全量测试、前端测试与生产构建、生态规则检查、Linux Agent 构建。
- Linux 真机：重启 Agent 后必须通过 `/proc/<MainPID>/mountinfo` 或 `nsenter` 核对进程的实际
  根挂载为 `rw`，不能只读取 `systemctl show`；随后通过 Agent Unix Socket 文件 API 分别在
  `/etc` 和 `/var/local` 创建并清理唯一测试目录，同时确认 Panel 状态目录的 API 返回保护错误且
  进程挂载仍为 `ro`，最后比对 Panel 健康状态和全部业务容器 ID/状态基线。

## 10. 轻量 Office 预览与基础编辑（候选）

- 自研 Go 标准库 OOXML 解析与 Vue 原生工作区，按需加载，无额外 Office 服务、编辑引擎或依赖。

  `GET /v1/files/content?path=...&mode=office` 返回有界结构化正文与 SHA-256 内容版本，绝不返回 HTML，
  不获取外部关系。Word 显示正文、简单表格与部分内嵌位图；Excel 显示已有单元格及缓存公式结果；
  PPT 显示普通文本框与部分内嵌位图，布局为近似值。

  ID 在服务端根据原文件解析重建，拒绝未知/重复目标、公式及其数组/数据表覆盖范围、字段及其他复杂内容；每次最多 256 处修改，
  每处最多 64 KiB。Word/PPT 仅修改已有纯文本段落，暂不新增换行；Excel 仅修改已有普通单元格，
  不新增公式、行列或格式。签名文件仅支持预览。
- 保存只补丁修改被选中文本节点/单元格，其他 ZIP 成员通过原始压缩数据复制；保留未知结构与文件权限。
  写入临时文件并原子替换，提交前复核目标身份、资源版本与内容哈希。Excel 保存后标记下次完整重算，
  面板仍显示缓存公式值；需用 Excel 重算。界面保留失败草稿，并通过重新读取确认保存结果。
  未保存或保存中的编辑提供刷新/关页保护；保存前重新验证编辑后文件仍满足相同预览预算。
- 保留现有 Session、CSRF、节点固定路由、审计、保护目录和只读目录边界；匿名分享不接受 Office 模式。
  Office 沿用归档的有界中央目录读取器，在标准 ZIP 解析前验证并冻结最多 2048 个成员的索引，保留包注释。

  150000、展示项（含图片）最多 10000、工作表/幻灯片最多 128；累计展示文字最多 2 MiB、预览 JSON
  最多 16 MiB（预留元数据空间）；拒绝路径穿越、重复成员、加密成员、DTD 与实体。

## 11. 同名文件与文件夹的统一处理（设计稿，2026-11-14）

### 11.1 现有边界与市场复核

本方案属于 KPanel 原生文件管理契约，复用 Agent 固定文件动作、资源版本、接收会话、归档暂存
与既有任务索引，不调用任意 Shell，不增加常驻服务或文件系统的影子数据库。现有入口存在
上传询问覆盖、外部拖入/跨主机接收自动改名、普通复制/移动拒绝同名、恢复不覆盖、解压新建
目录等不同规则；这些是待统一的差距，不能只替换一个弹窗后就宣称全部统一。

以下为截至 2026-11-14 对官方文档/公开源码的复核，不代表逐一安装实测全部产品、版本或入口。
滚动文档和 `master` 源码以该日观察为限；依据不充分处只记录能确认的事实。

| 类别与来源 | 已核实的行为 | 对 KPanel 的取舍 |
| --- | --- | --- |
| [OpenSSH scp](https://man.openbsd.org/scp)、[sftp](https://man.openbsd.org/sftp)、[客户端实现](https://github.com/openssh/openssh-portable/blob/master/sftp-client.c) | 当前 scp 默认走 SFTP；OpenSSH SFTP 普通上传以截断方式写同名文件，续传是另一种模式 | 协议本身不提供统一的三选弹窗；Web 管理端应明确取得覆盖选择，不把续传当作内容合并 |

### 11.2 对用户承诺的行为

所有导入入口默认在遇到冲突时询问；未冲突的项目直接处理。冲突按目标文件系统的实际名称
与对象身份判定，不在浏览器中统一转小写、去空格或改 Unicode 后猜测是否同名。

| 来源与目标 | 覆盖/合并 | 保留两份 | 跳过 |
| --- | --- | --- | --- |
| 普通文件 → 同名普通文件 | 使用来源的完整内容替换目标，名字不变；不拼接内容 | 原目标不动，新到文件改名，如 `photo (1).png` | 本项不写入，继续后续项目 |
| 文件夹 → 同名文件夹 | 按用户已选语义执行“合并文件夹”：保留目标独有内容，同名子文件按文件策略处理 | 给来源最外层文件夹改名，整棵子树进入新名字，不拆散到已有目录 | 跳过这棵来源子树，不继续写它的子项 |
| 文件 ↔ 文件夹，或目标是链接/特殊对象 | 首版不提供跨类型覆盖或跟随链接写入；提示实际类型 | 在不触及旧目标的另一个合法名称下创建受支持的来源对象 | 本项/来源子树不处理 |

目录按钮明确写“合并文件夹”，并显示“保留目标独有内容；同名子文件另按文件策略处理”。
合并不是删除旧目录后重建，也不重设已有目录的权限/所有者。普通文件覆盖沿用现有原子替换
与目标权限、所有者、扩展属性保留契约；新建项目继续使用对应入口的既有元数据规则。
没有经验证的备份机制时，不显示“可撤销覆盖”的承诺。

同一路径复制允许选择“保留两份”；同一路径移动报告“位置未变化”，不删除或重写。
复制/移动目录到自身子目录拒绝执行；硬链接等同一对象不能通过覆盖自己清空数据。
重命名只有单项决策，保留两份表示采用新生成的目标名称；新建空文件/空目录也不得因同名
直接清空现有内容。编辑器保存仍以已打开版本为依据，版本过期走编辑冲突流程，不继承导入任务的选择。

### 11.3 批量选择与弹窗

一次上传、一次粘贴、一次拖放或一次用户确认的批量动作构成一个 `batchId`。任务绑定来源快照、
目标主机和目录，之后切换页面、目录或主机不改变目的地。每个任务分别保存：

- `filePolicy`：`ask | overwrite | keep-both | skip`。
- `directoryPolicy`：`ask | merge | keep-both | skip`。

默认都是 `ask`。文件弹窗复选项为“对此任务剩余的同名文件使用此选择”；目录弹窗为
“对此任务剩余的同名文件夹使用此选择”。文件的“跳过全部”不会跳过整棵目录，目录的“合并全部”
也不会自动覆盖子文件。若已有文件策略则合并时直接采用；没有则在第一个子文件冲突时再问。
类型不匹配、同一对象及确认后目标发生变化不继承普通覆盖策略，必须显示对应原因。
不把选择存成全局偏好，不影响其他窗口、其他任务或下一次粘贴。

弹窗显示操作、来源/目标主机与完整路径、名称、类型、大小、修改时间；取不到的信息显示未知，
不以 `0` 或当前时间代替。长路径可换行/复制，来源与目标标签不能只靠颜色区分；保持键盘可操作、
焦点圈定和关闭后焦点返回。桌面内嵌文件窗口与独立文件页共用弹窗，不把桌面窗口容器误判为
阻止粘贴的模态对话框。输入框、编辑器中的 `Ctrl+V` 继续输入内容。

“跳过”只处理当前冲突；“取消剩余”停止本任务尚未提交的项目，已完成的结果保留。弹窗右上角关闭
和 Esc 的效果明确为取消本任务剩余内容，不暗中选择覆盖或保留两份。等待决定显示“等待处理同名项”，
不持续占用传输并发槽、打开的网络正文或文件句柄。多个任务的弹窗顺序排队并显示所属任务；
一个任务的取消和“应用到后续”不能影响另一任务。

例如：已有 `site/index.html` 和 `site/local.env`，来源含 `site/index.html`、`site/logo.png`。
选择合并后，`local.env` 保留、`logo.png` 新增；同名文件选覆盖则替换 `index.html`，选保留两份则
得到 `index (1).html`，选跳过则原 `index.html` 保留。记住文件策略后，后续同名子文件采取相同行为。

### 11.4 服务端裁决、竞争与部分完成

浏览器负责呈现选择，服务端负责路径、名称分配、对象身份与最终提交。实现共用冲突计划/提交逻辑，
上传、复制/移动、恢复、归档和远程来源只提供各自的来源适配器，不能各写一个自动改名算法。
前端预检仅用于提前提示；真正提交必须包含来源版本、目标版本或“不应存在”的条件。

- 普通覆盖绑定用户看到的目标 `resourceVersion` 和对象身份；写完同文件系统暂存后再次查验并原子发布，
  失败不能先删旧目标，磁盘不足不能留下半个正式文件。
- 新建和保留两份采用不覆盖提交。服务端分配 ` (1)`、` (2)` 等名称并返回最终结果；
  保留常见复合扩展名（如 `backup (1).tar.gz`），点文件不把整个名字当扩展名；目录名不拆扩展名。
  按目标平台的长度、非法字符等限制有界截短；副本序号最多尝试 999 次，耗尽显式报错。
  并发抢占候选名时，在仍为“保留两份”的授权内继续找名，不转为覆盖。
- 普通 `already_exists`、`target_version_changed`、`source_version_changed`、`type_mismatch` 与权限/配额/网络
  错误使用结构化错误码，不匹配翻译文案。目标变化后重新呈现新目标，即使已选批量覆盖也不能沿用
  对旧版本的同意；来源变化暂停该项并要求重新读取，不把目标询问当成来源变更的确认。
- 目录合并按有界快照遍历，分页不完整时拒绝继续猜测；不能边移动边使用会因删除而错位的偏移分页。
  固定父目录身份并对每个子项重新查验，不能仅比对目录 mtime，因为任务自身也会改变它。
- 同批次中多个来源指向同一最终名称时按固定来源顺序裁决，同一目标的提交串行；不重叠目标可并发。
  去重包含关系重叠的选择，避免父目录与其子文件重复处理。预算按整批累计，不能通过拆成多次请求绕过。
- 移动只在目标提交并确认来源版本仍一致后删除该来源；跳过、失败、取消或新出现的来源都留在原处。
  合并后仅用“删除空目录”的专用动作清理来源目录，不能递归删除剩余项目。
- 整批合并允许部分完成，不承诺目录级事务回滚。每项保存真实结果；请求超时先查完成凭据/任务状态，
  不盲重放覆盖、移动或恢复。取消与提交重叠时先对账，再显示“已完成”或“已取消”。

结果至少区分 `completed`、`skipped`、`failed`、`cancelled` 和 `waiting_input`；内部项还可为
`pending/running`。进度字节不代替成功数，不把跳过计成上传成功，也不将整个合并目录重复计为成功文件。
跳过整目录时可以显示“跳过 1 个文件夹（含子项）”，未知子项数量不编造。移动失败后的残留来源另列明细。
“全部完成”只在所有已选项目都得到明确结果时显示；存在未完成项应显示部分完成及原因。

### 11.5 前台与后台任务的生命周期

本地剪贴板/拖入文件依赖浏览器提供正文，属于前台来源；关页/浏览器退出会中断未传完的内容，
必须如实提示，不能把保存了文件名当成可离线续传。已确认的接收会话继续遵循原有有限恢复规则。

服务器复制/移动、跨主机传输、恢复、解压/压缩及远程下载若以后台任务执行，策略、决定修订号和
有限待决冲突摘要须保存在相应现有任务状态里；页面关掉后不丢失，也不依靠浏览器完成“最后一步合并”。
没有待决冲突可继续运行；遇到 `ask` 或目标版本变化则进入 `waiting_input`，释放传输资源，重进页面可处理。
多个页面同时决定时，服务端按任务修订号只接受一个决定，过期页面刷新状态；任务不存在/已取消不能写入。

继续复用有界存储，不为本功能引入数据库或另一份文件清单真源。通用任务索引维持现有 100 项、
256 KiB、保留 7 天的边界；每任务至多保存当前一个待决摘要和两种策略，大目录仍按有界游标推进，
不能把整棵树塞进索引。达到数量/序列化容量限制时拒绝新任务，不截断活动决定；其他任务存储继续
遵循自身已有上限，新增字段必须纳入容量测试。身份相关执行检查点由执行端保存，Panel 仅保存任务索引。
新增状态使用版本化兼容格式并保留旧索引供回滚，不让旧读取器把 `waiting_input` 当完成或坏数据覆盖。

等待输入最多 24 小时且沿用更短的来源/暂存有效期；到期终止未完成部分，仅清理可证明归属的暂存，
不删除正式目标或保留来源。损坏状态保留原件并禁用对应恢复；策略持久化失败不能继续执行依赖该决定的
破坏性写入。程序重启沿用现有“活动任务标记中断、不自动重放”规则，不因记住覆盖策略而自动续跑。
远程下载不保存完整 URL；正文无法重建时显示需重新发起，不能宣称重启后自动恢复。

资源限制沿用来源本身的契约：上传并发 2；外部目录导入最多 500 文件、256 目录、深度 32、总计 10 GiB；
复制/归档整批 10,000 项/10 GiB。统一策略不能扩大既有限额或以无限扫描/哈希预检阻塞普通上传。
等待冲突仍占用任务名额，但不占用实际传输工作槽；任务准入继续受各模块已有上限约束。

### 11.6 入口覆盖、兼容和实施顺序

统一的范围与首版交付顺序如下；前一阶段完成不能代表整套能力完成：

| 顺序 | 入口 | 必须解决的差异 |
| --- | --- | --- |
| 1 | 上传按钮、系统 `Ctrl+V`、外部文件/目录拖放；独立文件页、桌面与桌面内嵌文件窗口 | 同一批次策略、名称分配、版本绑定、来源中断与真实结果统计 |
| 2 | 本机复制/剪切粘贴、拖动复制/移动、批量操作 | 目录合并、固定遍历顺序、累计预算、移动部分完成后保留来源 |
| 3 | 跨主机/KPanel 接收、后台远程下载（含实际响应给出的文件名） | 在最终名称确定后裁决；持久化等待决定，不靠浏览器临时串联 |
| 4 | 回收站恢复、解压到已有目录、压缩产物同名；新建与重命名 | 复用同一策略；跳过恢复仍留回收站，只有确认恢复成功才移除对应记录 |

解压中的路径穿越、重复成员、链接与特殊文件、解压预算等继续按归档校验拒绝；“覆盖”不能绕过
归档合法性检查。归档先校验/暂存后逐项发布，目录合并非整批原子；目标已有子项冲突才走本节。
远程来源文件名一经确定即冻结并验证，不能用 URL 尾段猜名后提前获得对另一个实际名称的覆盖同意。

能力协商须明确目标节点是否支持版本绑定覆盖、目录合并与后台等待决定；新旧 Panel/Agent 混用时，
不支持的选项不可用并说明原因。不把严格覆盖静默降级为旧版无版本覆盖，也不把“询问”降级成自动改名。
旧 API 调用保持既有默认语义，新契约显式启用；所有入口完成迁移后再清理旧分支，不能为统一界面破坏旧客户端。

首版不引入自动“只覆盖较新”、同名即判重复、文本内容合并、镜像删除、强制跨类型替换或覆盖历史备份。
这些若后续增加，须有独立的语义、预算和验收，不能藏在三选项背后。当前开发草稿仅覆盖部分前台入口，
服务端统一分配名称、后台持久化决策及其余入口尚需实现；本节不作为实现或上线证据。

### 11.7 验收与回滚

至少覆盖以下有可观察结果的旅程，前端 mock 验证与真实 Linux 文件系统验证分别记录：

1. 三个前台入口上传同名文件，分别覆盖、保留两份、跳过；图片 `Ctrl+V` 在桌面内嵌窗口生效，输入框不劫持。
2. 两批任务并发，文件/目录策略互不串用；取消一个不影响另一个；复选项只影响本批后续同类冲突。
3. 多层目录合并保留目标独有文件；保留两份重命名整棵来源；跳过目录不写子项；分页合并不漏项。
4. 移动中混合成功、跳过、失败、取消，来源剩余内容和剪切板均与真实结果一致；空目录清理不删新出现的文件。
5. 确认后目标被另一个进程修改/替换/删除、来源变化、并发抢名、同批重复目标、同路径/硬链接和大小写差异。
6. 权限错误、磁盘满、配额/预算超限、网络中断、提交响应丢失、取消与提交重叠；旧目标和未知对象不误删。
7. 复合扩展名、点文件、超长 UTF-8 名称、跨类型碰撞与符号链接；名称耗尽显式失败。
8. 后台任务关页后等待决定、双页面同时决定、24 小时过期、状态损坏/写入失败、进程重启和旧节点兼容。
9. 恢复/解压/压缩与远程响应文件名触发相同策略；非法归档不因选择覆盖而获准；结果数和落盘内容一致。

代码候选须通过对应 L2 门禁、独立复核、适用安全审查与可见交互预览后才宣称开发完成；发布另行授权。
以候选精确基线为代码回滚点，新状态格式保留旧索引；已完成的覆盖、移动和合并不随程序回滚而撤销，
不能把 Git 回滚当成用户文件恢复。没有创建/验证备份就不能声称可恢复被覆盖内容。
