# 审计存储

- 状态：候选（分支 `perf/audit-storage-20260919`），尚未进入发布。
- 触发：`docs/development-quality-standard.md` §5.2。审计原先保存在 `panel-state.json` 的 `audit`
  数组，保留上限 10,000 条；记录数超过 5,000 的评审线，满载写入 P95 也超过 50 ms。
- 结论：审计迁到同目录下独立的 SQLite 文件，其他状态继续保存在 `panel-state.json`。

## 1. §5.2 评审

测量环境：arena-154（8 核），发布门禁镜像 `kpanel-release-gate:go1.26.7-node24`。每种方案在独立
进程中写满 10,000 条结构接近真实的审计事件，再追加 200 条；共跑 3 轮，各轮结果一致。内存读取
`/proc/self/status`，实际落盘量读取 `/proc/self/io`。

| 指标 | 现状：整份 JSON | JSONL 追加文件 | SQLite（WAL） |
|---|---|---|---|
| 追加一条审计 P95 | 158–165 ms | 1.9–2.1 ms | 1.25–1.36 ms |
| 追加最大值 | 约 176 ms | 51–60 ms（整理文件时） | 4.6–43 ms |
| 其他状态写入（如建会话）P95 | 153–165 ms | 不再受审计影响 | 不再受审计影响 |
| 读取一页（50 条）P95 | 12 ms（每次全量排序） | 约 0（全部常驻内存） | 0.6 ms（索引） |
| 每条追加的实际落盘量 | 4.73 MB | 4.8 KB | 26 KB |
| 启动加载（恢复时间） | 88–126 ms | 84–94 ms | 2–3 ms |
| 常驻 / 峰值 RSS | 30–34 / 67–70 MB | 34–36 / 34–36 MB | 16 / 18 MB |
| 二进制体积 | 基线 | 不变 | 不变（paneld 已为 AI 链接 `modernc.org/sqlite`） |

另外一个代价：现状下任何状态写入都会克隆并重写整份状态，包括 1 万条审计。所以登录、建会话、
改分享等操作，都和写审计一样慢。

选择 SQLite 的理由：

- 与现状相比，各项指标均为改善，没有任何一项回退，所以不触发 §5.2 的"回退超过 20% 需说明"。
- 与 JSONL 相比，SQLite 不需要把全部审计常驻内存，分页走索引，也没有整理文件时的延迟尖峰。
- 代价是每条落盘量是 JSONL 的约 5 倍，但只有现状的约 1/180。

候选实现复测（同一环境，3 轮）：从旧状态文件迁移 1 万条审计用时 0.51–0.64 s，之后重新打开
1–2 ms；追加审计 P95 为 1.2–1.6 ms；建会话 P95 为 2.6–4.2 ms（原约 160 ms）；迁移后状态文件为
259 字节，审计库约 4.6 MB。

未覆盖：没有测 1 核低配主机，也没有统计生产环境的真实审计条数。

## 2. 设计

- **文件与权限**
  - 文件位于状态文件同目录，命名为 `<状态文件名>-audit.db`，默认即
    `/var/lib/kejilion-panel/panel-state-audit.db`，运行中另有 `-wal`、`-shm` 文件。
  - 先以 `0600` 创建文件，再交给 SQLite 打开。
  - 审计库和状态文件在同一把进程锁下打开。
- **固定上限**
  - 连接：单连接，写入串行。
  - 持久性：`synchronous=FULL`，每条审计在所审计的操作报告成功前落盘。
  - WAL：`journal_size_limit` 4 MiB。
  - 单次查询：最多 200 条。
  - 单条记录：64 KiB，超过时 `change` 被替换为截断标记，不让被审计的操作失败。
  - 保留：最近 10,000 条，由同一事务在写入时删除最旧的记录。
  - 单次事务：10 秒上限。
- **顺序与分页**
  - 列表按写入顺序从新到旧排列。旧实现按 `occurredAt` 排序，两者只在系统时钟回拨时不同。
  - 游标是上一页最后一条的事件 ID。未知游标从最新一条重新开始，与旧行为一致。
- **写入不占状态锁**：审计写入不再持有 `panel-state.json` 的读写锁，写审计时会话校验等读操作不再排队。
- **失败即拒绝**
  - 审计库无法写入时返回审计不可用，需要先记录意向的操作照旧拒绝执行。
  - 审计库文件被删除或替换后，写入会被拒绝，而不是继续写进一个已删除的文件。
- **迁移**
  - 启动时发现 `panel-state.json` 仍有 `audit` 记录，先按事件 ID 去重导入审计库，再从状态文件中移除。
  - 两步之间中断时，下次启动会重做导入，不重复也不丢失。
- **密码恢复**
  - 审计库是独立文件，无法和状态文件原子提交。恢复流程改为先写恢复审计，再提交凭据变更。
  - 凭据提交失败时，追加一条 `failure` 结果的审计记录（ID 后缀 `:failed`）。
  - 这样不会出现凭据已改但没有审计记录的情况。

## 3. 运维影响

- **升级**：无需操作。首次启动自动迁移，`panel-state.json` 变小，数据目录多出审计库文件。
- **备份**
  - KPanel 备份本来就不导出审计，恢复时保留本机审计；主机级备份排除 `/var/lib/kejilion-panel`。两者均不变。
  - 手工拷贝数据目录前须先停止 `paneld`，运行中拷贝 SQLite 文件可能得到不一致的副本。
- **降级**
  - 旧版本不读取审计库，审计页只显示降级后新写入的记录。
  - 历史仍保存在审计库中，再次升级时会按事件 ID 合并降级期间写入的记录。
- **磁盘**：满载时审计库约 4.6 MB，WAL 不超过 4 MiB，状态文件同步缩小约 4.7 MB。
