## 观察证据、假设与替代解释

10-30 调整后的四份验收按各自口径合计 85 次流程异常/无效证据拦截；不代表 85 个独立产品缺陷或浪费时长。
RC1/RC5 重复出现 Go PATH 缺失、工作目录/跨 Shell 准备错误。RC3 首次 terminal 导航失败后关闭浏览器，
没有保存原请求状态、DOM 状态或 URL；一次只读复核通过仍未证明根因已修复。
原始独立诊断保存在仓库外 `kpanel-v129-rc3/terminal-failure-independent-review.json`。

本机 Windows + Node 24.17.0、Git for Windows，在 clean 精确基线上：从 web 调用仓库相对脚本失败；
Go 1.27.3 已安装但不在默认 PATH 时，原生与 Bash 预检均失败。原件存本任务仓库外证据目录。
假设：唯一入口使用自身仓库根目录，显式 GOROOT 在原生/Bash 间一致传播，可消除这两类确定性准备错误；
失败前保留有界路由、状态和页面标记能补充定位信息。网络、首次启动和产品缺陷是替代解释，
本修复不解决它们；工具未安装或未选择时仍失败，不扫描缓存、自动下载或推断正确版本。

## 方案、兼容与固定验收合同

保留现状会继续依赖临时 PATH 和失败后猜测；另建启动器或监工会增加入口。选择修复现有唯一入口：

- 仓库相对 SCRIPT 从启动器所在仓库解析，子进程 cwd 固定该根目录；显式绝对 SCRIPT 和后续参数保留。
- GOROOT 必须是包含 Go 可执行文件的绝对路径；只在子进程环境前置其 bin，清除 Git 覆盖变量，
  不改系统 PATH、Git 配置或工具版本；没有显式 GOROOT 时沿用 PATH。
- 公开浏览器保存最近 128 条脱敏事件、最多 32 个待完成请求、最多 4 页的固定 DOM 标记计数；
  页面采集并行、各最多 2 秒。无 header、Cookie、body、console、DOM 文本、输入或终端输出采集，
  不增加请求、导航、重载或成功判定；在关闭浏览器前尽力采集，采集失败不取代原失败。
- 新回归进入现有治理门禁。仅该测试基础设施文件进入治理/语法路径，强制 L2/L3 规则不变。

精确基线为上述 SHA；允许范围仅为上列入口、对应测试、verify-change/verify-governance 注册及本提案。
冻结矩阵为 PROJECT_RULES.md 5.3 的正确性、一致性、完整性、可执行性、效率与比例性、可演进性。
正常路径：writer 预检 → 修复/非空候选 → 双臂 OCR 与非作者复核 → 对应 verify-change → 本地 clean 交付。
回归集：嵌套目录/带空格路径/参数与非零退出码、原生和 Bash Go 环境、失败导航前关闭顺序、状态保留、
事件/页面/时限上限和敏感信息排除，以及现有完整治理套件。断言不变由差异复核核对。
本轮停止条件：固定矩阵完成、阻断为零、回归/完整治理通过、精确 clean 候选；范围外发现只记录后续。
