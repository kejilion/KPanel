# Docker 镜像更新检查

普通容器通过 `POST /api/v1/docker/containers/{id}/check_update` 检查，携带当前
`resourceVersion`；复用 Panel 登录、Origin、CSRF、审计与 Agent 固定路由。
此接口只读取 Docker Engine，不 pull、不重建，不创建后台任务。

应用市场与 Docker 页统一调用 `dockerx.Client.CheckContainerImageUpdate`：由共享检查器读取
最新容器快照，检查期间发生资源冲突时最多重读一次。浏览器仍须提供 `resourceVersion`，但
只读检查不会仅因列表版本过旧而失败，响应版本属于实际检查的快照；前端不得把该版本回填
到启停、删除或更新等写操作。所有写操作仍要求精确资源版本匹配。
共享检查器的两次尝试合计最多 20 秒、占用同一个并发名额；只有快照冲突重试，网络、权限、
限流或摘要不可比不叠加重试。应用市场的查找也包含在 20 秒内，服务层和页面不再各自刷新重试。
两个入口共用 Agent 状态/失败分类、前端结果类型及校验、固定失败说明；固定版本不能显示为“最新”。

- 本地身份始终使用容器 inspect 的 `Image`，而不是可能已被重新拉取的 `Config.Image` 标签。
- 远端保留用户的 repository/tag；受管容器使用镜像 ID 创建时，复用已有镜像标签元数据。
- 本地 `RepoDigests` 必须属于规范化后的同一仓库；相同摘要为 `current`，表示该标签未发现更新。
- containerd 存储在标签移动后可能清空旧镜像的 `RepoDigests`；仅在该列表为空、inspect 返回的 ID
  与运行镜像一致且 `Descriptor` 为有效 manifest/index 时，使用该内容摘要，并继续核对仓库中的摘要层级与平台。
- 不同摘要先通过 Engine distribution 元数据确认层级可比；单平台 manifest 还需平台一致。
  多平台 index 与平台 manifest 不能直接比较。缺失类型、摘要或平台、仓库拒绝、超时、限流均无法确认。
- 本地 inspect ID 与运行镜像一致、Descriptor 摘要属于已确认的本地摘要且类型为 index 时，
  直接使用本地类型证据，省去远端旧摘要查询，避免旧索引被仓库清理后检查失败。单平台 manifest
  仍需远端平台证据；缺失证据不会转为“无更新”。
- `available` 表示该标签的可比较镜像摘要改变，不表示上游最高版本，也不跨标签寻找版本。
- digest 或镜像 ID 固定引用为 `fixed`。Go 检查器保留专用错误标记，两个 HTTP 入口统一返回
  `fixed` 状态；应用市场明确显示“固定版本”，面板自身更新提示将其视为无法判断。
- 检查完成前再次核对容器身份及资源版本；重读后仍变化则返回冲突，旧结果不可作为当前状态。

所有共享消费者合计最多两个并行检查，无排队，单次总时限 20 秒；继续复用既有有界 Docker
响应及 Docker Hub 加速回退。打开容器页后自动检查前 200 个容器，每秒最多启动一个请求、
最多两个同时在途，不预建无界请求队列。普通 Docker 页面只保留最多 200 个内存结果，30 分钟
过期再检测；普通失败同样冷却 30 分钟，服务器检查繁忙冷却 30 秒，用户也可手动重试。
刷新列表保留身份未变的结果；资源变化立即丢弃旧结果并取消读取。浏览器隐藏、切换标签或
桌面窗口失活取消在途请求并暂停自动检查，恢复时只检查缺失或过期项。页面卸载释放请求、
定时器和缓存；超出自动检查预算的容器可以在详情中手动检查。无持久化检查库、常驻服务、
自动升级或新增私库凭据存储。

首屏仅突出“有镜像更新”（警告色），不弹 Toast、不逐行展示检查时间或失败说明。
“检查详情”展开无更新（成功色）、固定版本、等待、检查中及无法确认（次要文字色）；
颜色同时配合文字语义。失败按摘要缺失、层级/平台不可比、仓库权限、标签/摘要移除、
限流、超时、检查繁忙和资源冲突分类；UI 只使用固定类别说明，不展示原始仓库错误。
截图中的通用失败提示不足以判断具体主机原因；网络或权限失败仍需修复实际环境。

更新操作继续通过原应用市场或 Compose 的确认、资源版本与后台任务执行；镜像页 pull 只更新本地标签，
不会自动重建使用该标签的现有容器。没有新增通用容器重建协议，也不要求新的 `kejilion.sh` 契约。
