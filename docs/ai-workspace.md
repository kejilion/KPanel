# KPanel AI 工作台

## 范围与架构

AI 工作台位于 `/ai` 与 `/ai/s/{sessionId}`，由 `paneld` 内的原生 Go Runtime 驱动。它不安装 Hermes、Eino、Sidecar、本地模型或向量数据库，也不提供宿主机通用 Shell、通用 HTTP/Web、语音和多 Agent。

数据流为：

```text
Vue 三栏工作台 ── REST/SSE ── paneld AgentRuntime
                                  ├─ OpenAI-compatible / Anthropic / Gemini
                                  ├─ /var/lib/kejilion-panel/ai.db
                                  └─ 固定 KPanel Tool Registry ── Unix Socket ── kejilion-agent
```

身份、Origin、CSRF 与现有 KPanel API 完全一致。AI 数据独立保存到 `ai.db`；宿主机资源仍由 Agent 实时读取，不写入 AI 数据库。

## Provider 与网络

- 模型目录全局最多 5000 条，Provider 最多 128 个，与配置备份上限一致。多次同步及并发新增共用持久化事务配额；达到上限后仍可更新已有模型配置。同步保留已有模型 ID、名称、上下文窗口、工具能力、启用与默认设置，继续沿用 vision 默认启用和 reasoning 能力推断。旧库超限或字段超长时，列表与同步在 SQLite 中先校验，再有界读取并明确报错，不自动删除模型；可明确删除多余 Provider（模型超限不阻断 Provider 列表）或恢复有界配置备份。
- Provider 将收到的 API Key 复制到重定向 URL 后触发的网络错误，也在共享请求出口按当前 Key 及 URL 编码形式脱敏，保留网络错误类型、超时与取消语义。
- 固定协议：`openai_compatible`、`anthropic`、`gemini`。
- `openai_compatible` 必须明确选择 `apiMode`：`responses` 使用 `POST /v1/responses` 语义事件，`chat_completions` 使用 `POST /v1/chat/completions` 数据分片。历史 Provider 自动迁移为 `chat_completions`，避免升级后改变行为；OpenAI 官方预设默认使用 `responses`，其他兼容预设默认保守使用 `chat_completions`。
- Responses 模式使用 KPanel 持久化的完整会话上下文，并设置 `store=false`。工具调用使用 `function_call` / `function_call_output`；带工具调用的响应会将 Provider 返回的完整 output item 序列按原顺序保存在内部上下文，并仅向生成它的同一 Provider/模型原样回放。升级前只保存了加密 reasoning item 的旧会话，会先回放 reasoning，再重建同一批 assistant 可见内容和函数调用。原生 output item 不通过 REST、SSE、日志或审计暴露。
- Responses 首次请求保持标准 OpenAI 载荷；若兼容 Provider 在尚未输出任何内容时明确返回 `messages[n]: missing field id`，Runtime 只重试一次带稳定消息 ID 的兼容载荷，并在当前进程内记住该端点能力。已产生文字或工具调用后禁止回放，其他 4xx 不触发方言猜测。
- Chat Completions 会捕获 Provider 实际返回的 `reasoning_content`、`reasoning_text` 或 `reasoning`，仅随对应工具调用保存在内部上下文；同一模型响应产生的可见内容、多个工具调用和 reasoning 会重建为一条完整 assistant 批次，不跨模型响应复用 reasoning。标准后续请求不主动猜测方言；只有端点在未输出内容时明确要求补充某一 reasoning 字段，Runtime 才以已保存的原文和指定字段重试并记住当前端点/模型方言。若旧工具历史没有保存原始推理内容，Runtime 不伪造空 reasoning 字段，而将已有工具结果降级为标注为不可信的历史数据后重试。该兼容链路由实际响应和端点错误驱动，不依赖 DeepSeek 型号名称；型号推断只控制原生思考强度参数。隐藏推理不进入 REST、SSE、日志或审计。
- Anthropic 工具调用会将完整 assistant content block 序列及其中的 `thinking` / `redacted_thinking` 签名绑定到原 Provider/模型，包含新版 Claude 在多个工具之间产生的交错 thinking，并在续轮按原顺序回放；同一响应的多个 `tool_result` 合并到下一条 user 消息。Gemini 会保存每个 `functionCall` 实际返回的 ID 和 `thoughtSignature`，仅向生成它的原 Provider/模型对应调用回放，并将带原始 ID 的并行 `functionResponse` 合并到同一 user 内容。两类原生上下文均不通过 REST、SSE、日志或审计暴露；切换模型时不携带旧模型的签名上下文。
- Responses 的 HTTP SSE 与 Realtime WebSocket 是不同接口；v1 不接入 `/v1/realtime`、音频或语音会话。
- Responses 回放的原生工具批次若因审批、冲突或中断缺少部分结果，请求中为缺失项明确标记 `tool_output_unavailable` / `unknown`，提示先核对当前资源状态；保留已有真实结果，不推断执行成功或失败，不自动重放工具或改写历史。旧会话继续时使用同一兼容路径。
- 公网 Provider 必须使用 HTTPS；拒绝 URL userinfo、query、fragment，以及每次 DNS 解析得到的回环、私网、链路本地、组播、未指定和保留地址。
- 内网/本地 Provider 必须显式选择 `private`；只有此模式允许 HTTP。
- 重定向最多三次；跨源重定向移除 `Authorization`、`X-Api-Key` 与 `X-Goog-Api-Key`。
- Compose 同时连接固定 `panel-internal` 与普通 `panel-egress`。容器仍为 UID 65532、只读根文件系统、`cap_drop: ALL`、`no-new-privileges`、256 MiB。
- Provider 只能访问模型 API；模型自身只能调用固定 KPanel 工具，没有通用联网工具。
- Ollama/LM Studio 预设通过 `host.docker.internal` 访问宿主机；本地服务需监听 Docker 网关可达地址，且保存前仍需显式确认内网模式。

## 用户交互

- 首次进入先展示三步引导：选择 API、验证连接、启用模型。新增 API 默认执行“保存 → 测试 → 同步模型”；后两步失败时保留已加密保存的连接，允许修正后单独重试。
- 再次同步模型时，已有的显式 reasoning 能力不会被降级；代码已识别的新思考模型会从旧的 false 能力向上升级，因此升级 KPanel 后无需删除并重新添加 API。
- 点击“新建会话”会直接使用管理员设置的默认模型；没有显式默认值时使用第一个可用模型。会话标题由第一条用户消息自动生成，仍可手工重命名。
- 模型选择器位于输入框右下角，实时包含所有已启用 Provider 的已启用模型。运行中允许切换，但当前 Run 使用启动时快照，新选择明确标记为“下一轮”并只影响后续 Run。
- 思考强度位于模型选择器旁，提供 `low`、`medium`、`high`。Run 固定启动时快照；模型声明原生 reasoning 能力时映射为 OpenAI `reasoning.effort`/`reasoning_effort`、Anthropic `output_config.effort`、Gemini 2.5 `thinkingConfig.thinkingBudget` 或 Gemini 3 `thinkingConfig.thinkingLevel`，否则只使用通用规划强度提示。界面不暴露隐藏思维链，只展示可审计工具过程。
- 会话列表提供搜索、置顶、重命名、归档、恢复和删除；当前与已归档会话有独立视图，移动端通过抽屉管理。
- 历史存储在 SQLite 内由触发器统一记账并原子限额：最多 10,000 个会话、100,000 条消息，且会话与消息文本/附件载荷合计不超过 512 MiB。超过预算时拒绝新增或扩大的记录，不自动删除既有历史；用户可主动删除旧会话后继续使用。该载荷预算不等同于 SQLite 文件的精确物理字节数。
- 对话在首个模型分片到达前显示规划/重连状态；助手可见说明与紧凑工具行按真实发生时间穿插在同一个助手回合中，工具参数和结果按需展开。最终回答底部依次展示复制、模型和输出时间，代码块提供独立复制按钮。
- 流式文字使用浏览器帧内轻量缓冲，避免大分片突跳；只有用户停留在底部附近时自动跟随。用户上滚后停止抢夺滚动位置，并显示“回到最新”。
- 输入框随内容自动增高，运行中仍可追加要求。支持最多 4 个附件：PNG/JPEG/WebP/GIF 图片使用模型原生多模态输入，UTF-8 文本、日志、代码和配置文件按“不可信附件”进入上下文。单图 4 MiB、单文本 512 KiB、总计 8 MiB；拒绝 SVG、可执行文件和其他二进制格式。
- OpenAI-compatible Chat 端点若在尚未输出内容时明确拒绝 `image_url` 且只接受文本，Runtime 只把旧回合图片降为带文件名的不可用占位后重试并记住当前端点/模型能力；当前 Run 及其 Retry 来源链的必保图片绝不静默丢弃，而是明确要求切换支持图像输入的模型或兼容中转。接受多模态的中转和模型仍使用原生图片载荷。

## 密钥与数据

- SQLite 使用 WAL、外键、5 秒 `busy_timeout` 和事务迁移。
- API Key 由 XChaCha20-Poly1305 加密，主密钥为 `/var/lib/kejilion-panel/ai-secrets.key`，Linux 权限 `0600`。
- 数据库存在密文但主密钥丢失时，AI 模块失败关闭；KPanel 其他功能继续提供服务。不得自动生成新密钥覆盖。
- Runtime 与后台学习在共享模型输出入口识别当前 Provider 已知的认证 Key：可见助手文字跨任意分片隐藏完整 Key，普通文字使用线性匹配并即时输出；JSON 字符串在闭合验证前有界缓冲，按标准 JSON 转义和嵌套编码逐层检查后才可输出，避免可逆编码绕过。单次投影共享 64 MiB 工作量、262144 个语义节点和 32 层处理栈上限；命中凭据后编码的结果仍受原回复上限约束；若短 Key 与默认 `[REDACTED]` 标记重合，改用字符集不相交的 `(hidden)`，避免重复投影及重启迁移膨胀。工具参数（含 JSON 转义值）或学习结果包含该 Key 时明确失败，不改写后执行。工具调用 ID、名称、参数及公开预览使用同一请求投影预算识别编码后的已知 Key，命中即拒绝，不改写执行标识。旧工具公开预览在既有私有态事务及擦除流程中修正；若可归属当前 Provider 的旧 ID／名称含已知 Key，启动明确失败并保留原身份、私有态与审批，须恢复配套的无泄露数据库及密钥备份，不自动修改 ID、删除工具或执行旧调用。已轮换或无法归属的未知历史凭据不在此已知 Key 保证内。普通回复中其他密码与用户原始聊天不作泛化过滤。启动以相同已知凭据投影逐行修正可归属该 Provider 且含字面 Key 或转义符的旧助手副本和派生摘要，SQL 复制前先核算每行 2 MiB 上限，失败保留原数据并拒绝启动 AI；复用 Schema 11 的事务及 WAL/VACUUM 擦除；旧工具参数仍保留加密原文，命中时隐藏全部参数预览并拒绝执行。
- API 只返回 `apiKeySet` 和末四位；不超过四个字符的 Key 使用固定 `[REDACTED]` 提示，空 Key 无提示。启动先验证现有密文，再修正旧提示副本，并复用 Schema 11 的 WAL/VACUUM 擦除；再次降级写入旧提示时仍重新修正与擦除，缺失或错误密钥时拒绝启动且不改提示。普通用户聊天保持原文。工具参数与原生 Provider 上下文作为同一私有状态由 SecretBox 加密，附加认证数据绑定会话、Run、调用 ID 和工具名；REST/SSE 只返回有界安全预览，不序列化原始 arguments 或 Provider 数据。正文、Compose 和命令参数不进入持久化参数预览；仅待审批状态的认证响应临时生成经过结构化/文本脱敏的 `approvalPreview`，供管理员审阅具体写入或命令，超长内容明确标记截断。调用离开待审批状态后不再序列化这份详情。
- Schema 11 在启动事务中迁移旧明文工具记录，并对旧工具结果预览及 role=tool 消息应用相同结构化脱敏，保留原始参数、原生上下文、待审批/已完成状态、身份和时间；不会执行待审批调用或重放已完成操作。事务提交后执行 WAL 截断检查点、VACUUM 和再次截断，完成后才写迁移完成标记；迁移/擦除失败拒绝启动 AI，重启继续清理，不能静默丢弃历史。缺失或错误的密钥、损坏或身份不匹配的私有状态均失败关闭。
- Schema 12 将学习提案（含完整 Payload）、记忆、当前流程与全部历史版本的标题、正文、条件和步骤统一放入同一 SecretBox 私有状态，认证数据绑定表、管理员与记录 ID，流程版本还绑定所属流程 ID。旧明文字段只保留空值或不可执行占位；读取、版本修订及回滚先解密，展示投影不作为执行参数或审批依据。启动先校验全部既有学习密文，再事务迁移旧记录并沿 Schema 11 的 WAL/VACUUM 擦除流程完成；失败关闭、回滚及中断后重试不改变原审批状态、版本或时间。密钥存在性判断覆盖只含学习记录的数据库，配置备份不导出学习记录，恢复配置保留目标机器已有学习状态。
- 学习提案、记忆、流程及全部版本共用持久化预算：全库最多 2,048 条／32 MiB，单管理员最多 1,024 条／16 MiB；记录字节计入密文、旧明文字段及有界元数据。单条新私有状态最多 4 MiB（含密文封装），JSON 编码前先核算转义后的体积。新增提案、审批生成产物及修订／回滚在 SQLite 写事务内共用额度，超限整次回滚，不能留下半次审批或半个版本。
- 提案、记忆、流程各自的管理员列表最多 512 条／8 MiB，包含已退役记录，与前端及后台提示词共用同一完整读取契约；不静默截断，也不把退役记录改成删除。查询在同一 SQLite 快照内先核算长度，再复制和解密。启动先检查旧明文与密文的累计额度，迁移逐条预留编码后的增长；超限保留原数据并拒绝启动 AI，其余面板功能不受影响。达到额度后停止新增及自动学习，现有容量内的启停、退役和拒绝提案仍可进行；修订／回滚产生新版本，仍须有剩余额度。恢复须暂停写入并备份 `ai.db` 与配套 `ai-secrets.key`，再按明确保留决定离线整理或恢复容量内的数据库备份；配置备份不含学习记录，不能用恢复 Provider 配置释放此额度，不自动清除学习历史。
- 学习产物的 REST/SSE 序列化和模型上下文使用独立安全投影：参数按 JSON 解码识别凭据字段，隐藏正文、Compose、命令与数据体（字段名大小写一致处理），保留非敏感结构供合法流程复用；标题、条件及记忆文字应用现有有界文本/JSON 脱敏。任意未标记自由文本中的秘密无法保证自动识别；加密存储不等于允许向模型或界面披露凭据，也不构成任意秘密检测保证。学习产物不会赋予执行批准，自动启用仍由服务端注册工具、确认策略及 dry-run 校验决定，忽略模型自报批准字段。
- 擦除只覆盖当前 SQLite 主文件与 WAL 中已迁移的工具及学习原文；文件系统快照、存储介质历史块和升级前外部备份不能由 SQLite 追溯擦除，应按原有凭据备份权限与保留规则处理。用户主动提交的普通聊天与附件保持原有内容语义，不以启发式删除历史冒充全部秘密清除。旧程序不具备学习私有状态读取能力；新增旧格式记录可在再次升级时迁移，若降级程序修改已加密记录的旧字段造成双份冲突，新程序拒绝启动 AI，须使用配套升级前备份恢复，不能把占位内容当作可执行流程或静默覆盖修改。
- 上下文估算超过模型窗口 70% 时，将旧消息压缩为最多 8 KiB 的持久摘要并保留最近消息。
- 附件正文随消息保存在权限为 `0600` 的 `ai.db`，REST/SSE 历史响应只返回名称、类型、分类和大小，不回传原始附件数据；删除会话会一并删除附件。图片与文本体积纳入上下文压缩估算。
- 历史分页先排序并选择有界消息 ID，再逐行读取附件，避免把大附件带入 SQLite 临时排序；展示逐行解析至多 12 MiB 的编码记录、流式校验附件大小，不累计解码正文；旧摘要与后台学习只取所需文字。数据库仍会读取编码记录，资源验收包含解析临时内存和文件缓存。
- 历史文字页在 SQLite 内按内容的累计 UTF-8 字节计费，驱动复制前限制为 2 MiB（JSON 最坏转义约 12 MiB，另有有界元数据）；不足条数时仍返回可靠的下一页游标。单条内容超过预算明确报错，不静默截断。此展示预算不改变上下文独立的窗口、摘要或附件准入策略。
- 每次模型请求至多加载 8 MiB 原始附件。当前 Run 及 Retry 来源链中所有用户附件必须完整纳入现有 200 条及模型窗口选择，超限时本轮明确失败，原消息和附件保留，且不推进本次摘要游标；可新建会话分批发送，每批结束后再继续。剩余预算用于最近历史的完整附件组，被省略的旧附件在本次模型上下文中明确说明。同一读取快照的用户消息计数用于完成检查，读取后新增输入进入下一轮处理。
- Schema 10 为 `runs` 增加 `retry_of`：`NULL` 表示旧版本留下的未知来源，空串表示新版独立输入，非空表示同用户、同会话的直接 Retry 父任务。关系只在创建时写入，不改历史消息归属或旧任务状态；读取最多检查 64 个任务，缺失、循环、跨会话或超深链明确失败。来源未知且会话有用户附件时不能安全还原重试输入，明确失败并保留数据；历史展示和新版独立输入仍可用，全会话无用户附件时仍可处理文字。
- 迁移沿现有事务执行，不回填旧来源。兼容性验证须覆盖旧二进制读取新增列后的数据库、写入新任务再升级：旧版本未声明 `retry_of` 的写入保持 `NULL`，不能冒充已知独立输入。旧版本不具备本次附件预算与 OOM 防护；正式降级与恢复仍按发布备份、停止写入及回滚流程执行，不以字段兼容测试代替生产恢复验收。

## 运行与审批

- 单条消息 16 KiB、工具结果与单调用参数各 64 KiB、工具名与调用 ID 各 256 字节、12 个模型步骤、20 次工具调用。所有 Provider 共用事件/流预算：单 SSE 事件 2 MiB（包含多行 data）、单次流累计 8 MiB（包括注释、隐藏上下文与替换事件），追加与解析之前检查。每次请求的可见输出及后台学习收集各最多 1 MiB；原生上下文、参数分片、名称分片和工具数量也在保留前校验。终止事件立即结束读取，取消与消费者错误继续向上传递。
- 单会话一个 Run，全局两个并行 Run；模型请求超时 180 秒，SSE 心跳 15 秒。SSE 每次输出及心跳均重新认证原登录会话并匹配身份，注销、密码修改或传输边界切换撤销会话后停止输出，空闲流至多在下一次心跳退出。
- SSE 文字继续逐片实时发送；SQLite 草稿采用独立的有界准入，每个模型步骤（含该步骤的传输重试）至多 8 次、累计完整前缀至多 2 MiB，首次达到 1 KiB 或经过 2 秒后可保存，此后至少间隔 2 秒。额度耗尽后继续实时输出，但不再更新该步骤草稿；12 个步骤的草稿合计至多 96 次／24 MiB，另为每步骤保留一次不超过 1 MiB 的最终写入，总计至多 108 次／36 MiB，与 Provider 分片数和速度无关。已保存的相同正文不重复写入。该额度仅描述 SQL 正文载荷，不代表物理磁盘 IO 上限。
- 活跃模型步骤另有进程内可见前缀，复用 Runtime 已接受且已过滤当前 Provider 凭据的文字及同一草稿 ID、会话和模型归属；全局最多两个草稿、每个最多 1 MiB，不缓存原始 Provider、工具私有态或事件历史。附件元数据先在流锁外以 30 秒期限预读，按不可变消息 ID 缓存并释放预读正文；SSE 再在同一锁边界内以至多 2 秒的本地读取期限刷新最新文字页、当前前缀和订阅，新消息 ID 在该期限内单独补齐元数据，不作乐观重试，网络写入在解锁后进行；当前草稿替换同 ID 持久版本，与最新完整历史共用原有 50 条／2 MiB 文字页预算，必要时移出最旧整条历史，当前草稿不截断。完整快照的可选 `streamingMessageId` 标明流式草稿，前端清除旧动画队列并继续该前缀；终态快照停止重连。每订阅仍只有 32 个事件位置，满时关闭慢订阅以触发原生 EventSource 重连取快照，不能静默丢失完成状态；取消由 Runtime 在有期限的最终保存后发出终态。消息完成、失败、取消及步骤退出释放临时前缀；进程重启只恢复持久前缀。若连失败状态也无法保存，新的快照和模型步骤明确失败关闭至重启恢复，不保留无界终态副本，也不伪报成功。
- 正常结束、Provider 失败及取消时，均用独立的 5 秒期限保存本步骤已接受的完整可见文字；仅在完整正文提交成功后发送 `message.completed`，失败或取消的部分回复不发送完成事件。草稿或最终保存失败会终止请求并以 `message_store_failed` 明确失败，不重试 Provider、不继续执行工具、不发送成功事件；Run 完成状态保存失败同样明确失败。失败／取消状态更新各有 5 秒期限，状态也无法保存时返回组合错误并发送失败事件，数据库中原有活动状态会在下次启动转为 `interrupted`。
- 401 不重试；429/502/503/504 仅在尚未输出内容时重试两次。流式输出开始后不重放。
- 每个会话可选择 `manual`（手动审批）或 `auto`（安全自动审批），默认 `manual`。Run 启动时固定模式快照，执行中切换只影响下一轮。
- `manual` 下所有非只读工具逐次确认；`auto` 只放行固定 Schema 分类的常规应用、网站、容器、文件覆盖/回收站、Nginx 安全重载和缓存清理。
- `auto` 下的文件覆盖只自动执行 `/home/web`（证书目录除外）和 `/home/docker`（Compose 定义与 `.env*` 除外）内的站点与应用文件；其余仍可写入的路径，例如 cron、Shell 启动文件、服务钩子、Compose 定义或证书，会以 root 执行或改变服务信任，因此进入 `pending_approval`，由管理员确认后执行。
- 删除/卸载、标准级系统清理、系统核心设置、Docker 维护与备份迁移、容器 exec、交互式任务输入以及无法识别或无法解析的动作始终进入 `pending_approval`；分类失败时默认要求确认。
- 工具名与 Agent 路径是固定映射。Provider 侧使用不含组合关键字的扁平对象 Schema，让模型根据动作、真实状态和用户意图自主选择一般参数；Panel 只保留鉴权、审批、固定动作路由、严格结构化输入和审计边界，不重复限制每个动作的业务参数。Agent 根据 Docker 的真实状态校验底层技术前置条件、`resourceVersion` 和命令安全，并把失败作为可纠正结果返回模型。不存在任意路径或任意宿主机命令入口。
- 删除或修改现有容器、镜像、网络、卷前，必须先调用对应只读工具并使用同一资源最新的 id/name 与 `resourceVersion`。备份恢复/迁移先读 `host_docker_backups`，daemon 镜像源/IPv6 变更先读 `host_docker_environment`；`image_prune` 只处理悬空镜像，不能替代精确 `image_remove`。
- Agent 返回 `docker_task_invalid` 时按可纠正参数错误反馈给模型；资源不存在按真实状态冲突处理并要求重新读取。只有不属于参数或状态变化的 4xx 业务拒绝才作为操作边界处理。
- Agent 返回带安全问题码的可预期 4xx 业务拒绝时，Runtime 将“操作未完成”和问题码作为工具结果交给模型重新规划；401、请求超时、限流、无结构问题码的协议错误、5xx 与网络故障仍终止 Run。Agent `detail` 永不进入模型上下文。
- 相同工具和规范化参数在同一 Run 内失败两次后，第三次调用在到达 Agent 前熔断；单个 Run 最多容许 6 次可恢复工具失败，超过后以明确的重规划上限结束，避免消耗完通用步骤上限。
- 无业务参数的只读工具仍要求 `{}`；为兼容部分 OpenAI-compatible 模型生成的 `{"_":true/false}`，Panel 仅对这组只读工具丢弃布尔占位字段。写工具、有业务参数的读工具、非布尔 `_` 和其他未知字段继续严格拒绝。
- 工具结果以“不可信数据”标签返回模型，不能修改核心提示词、Schema、鉴权、审计或确认策略。
- Panel 重启会把模型请求中的 Run 标记为 `interrupted`；未执行审批保留，Agent 已提交的后台任务按原有任务恢复机制继续。
- 突然退出只能恢复最后一次已提交的草稿，尚在 SSE 中的尾部可能丢失；达到草稿额度后最后检查点可能早于最近实时输出。不会将旧草稿当作完整最终回复或自动重放工具；Retry 保留原任务与已提交草稿，在新任务下生成独立回复。主动取消和正常的 Provider 失败会先尝试上述有期限的最终保存，不能把实时输出等同于已持久化历史。

## 运维闭环与边界

自动模式下，`/home/docker` 的文件改写还会查询 Agent 的原生 Compose 发现结果，覆盖 `.env` 的 `COMPOSE_FILE` 和容器标签声明的自定义文件名，并递归检查受管目录，识别嵌套的已停止项目及旁支文件引用。分类遍历最多读取 512 个目录条目；超限、路径含链接或发现不可用时转为人工审批，不把不完整扫描当作普通文件。活动 Compose 来源仍需人工审批；完整扫描识别的普通应用配置保持原策略。旧 Agent、Docker 或分类查询不可用时也不自动放行。此查询不会执行 Compose 或重新部署服务。

AI 使用同一条轻量工作链处理常见实质任务，而不是按“修 Nginx”“清磁盘”等语句复制业务逻辑：

```text
读取真实状态 → 定位原因 → 选择最小且可回滚的注册操作 → 按会话策略审批 → 执行 → 再读真实状态验收
```

- Nginx：尾读 `/home/web/log/nginx` 日志，读取相关配置；已登记站点优先复用站点变更服务。任何直接配置修改后必须执行固定 `nginx -t`，只有通过才允许固定 `nginx -s reload`。
- CPU：结合系统概览、宿主机进程 CPU/内存双排行和 Docker 容器指标定位来源；不读取进程命令行，也不提供任意 PID kill。
- 磁盘：从系统概览逐级进入固定根目录热点分析，再选择缓存清理、需确认的标准清理/Docker prune，或带 `resourceVersion` 的可恢复回收站操作，最后复查空闲空间。
- 迁移：先盘点应用与容器并创建备份；只有用户提供明确目标且已有可信 SSH 配置时，才调用现有 `backup_migrate` 后台任务。迁移始终需要审批，不接收或推断目标凭据。

磁盘分析只允许 `/`、`/home`、`/home/docker`、`/home/web`、`/opt`、`/root`、`/srv`、`/tmp`、`/usr`、`/var`、`/var/lib/docker`、`/var/log`，不跨文件系统、不跟随符号链接，最多四个扫描线程、20 万条目录项、8 秒且同一时刻只运行一个。进程读取最多扫描 8192 个 PID，并仅返回 PID、PPID、名称、状态、UID、CPU、RSS 和启动标识。

AI 读取任何文件正文或日志尾部都使用现有 `pending_approval`：管理员明确确认向当前 AI 模型分享该次路径和参数绑定的内容后，Runtime 才读取；包括 `/home/web` 的站点文件和 `/var/log` 日志，`manual` 与 `auto` 都不能绕过，模型也不能通过参数自授权限。文件目录和扩展名无法证明内容不含秘密，启发式脱敏不承担披露授权。此授权不延伸到下一次调用；目录列表与其他结构化元信息仍按既有只读策略处理。

AI 和 MCP 的文件尾读取先检查完整文件上下文，再返回有界尾部；若不能取得可证明稳定的读取状态，则不向模型返回文件内容。Linux Agent 使用只读文件租约：文件仍被写入、权限不足或文件系统不支持时会拒绝；可关闭写入方或提供稳定副本后重试。非 Linux Agent、旧版 Agent 和不支持该协议的混合版本也会拒绝。普通 File Manager 的人工读取不受此限制。

大文件按记录流式检查，普通访问日志可以保留，敏感记录和可识别的 YAML 数据或私钥块会遮盖；无法安全判定的格式、超长行或超过处理时限会拒绝，可改用较小的稳定纯文本副本。源文件正在读取时若有新写入请求会中断本次投影并释放租约；进程暂停或存储读取阻塞时，无法保证写入方在固定时间内恢复。

所有工具 JSON 响应先解码再递归投影；转义字段名、JSON 字符串中的 JSON、`auth`/`auths` 和环境变量 name/value 都参与脱敏，文本文件内容在解码后处理再序列化。此投影是数据授权之后的补充，任意自定义正文中无标记的秘密不能可靠推断；管理员应只分享本次任务需要的文件。AI 文件内容读取继续禁止 `.env`、SSH 凭据、私钥、证书私钥、Token、进程环境、Docker Swarm 与 KPanel 数据；文件改写/回收额外禁止 KPanel、Docker 内部目录、systemd、SSH、PAM、sudo、cron、系统账号和系统程序目录。Agent 仍会再次执行 File Manager 的路径规范化、符号链接和保护目录检查。

## 后台学习规则

用户明确表达稳定偏好、任务成功完成一个常规写操作，或完成两个及以上工具调用时，当前模型会在 Run 完成后异步判断是否值得跨会话复用；单次普通读取不会额外触发学习请求：

- `memory`：事实或偏好，不超过 500 字。
- `procedure`：适用条件和 1–10 个步骤，只能引用注册工具。

判断结果必须达到 0.82 置信度；瞬时指标、一次性状态、故障输出、密钥、令牌、IP、资源版本、任务 ID、不确定结论以及重复或冲突内容直接跳过。流程只能引用本次真正成功的工具，并再次通过 Tool Registry、确认策略和 dry-run；涉及删除、系统核心、Docker 维护、exec 或交互输入的流程不得自动沉淀。

通过校验的产物自动启用并在同一管理员的后续会话中生效，不在正常聊天中弹窗或要求点击。学习记录仍保存在本机，可在“AI 设置”的后台记忆/后台流程中停用、退休或回滚；系统提示词最多加载最近 12 条记忆和 8 条流程，避免自动学习导致上下文无限增长。任何学习产物都不能改变工具 Schema、鉴权、审计和受保护操作确认策略。

## 回滚

运行数据备份/回滚前先停止 `paneld`，使用一致性 SQLite 备份并把 `ai.db*` 与 `ai-secrets.key` 成对保留；只有数据库或只有密钥不能恢复私有状态。Schema 11 保留旧格式升级读取，但旧二进制不能解密新格式，禁止直接让旧二进制读取升级后的数据库。降级必须停写并恢复升级前成对备份；会丢失备份后新记录，应先明确保留与恢复范围。应用市场更新会保留数据目录并自动恢复旧镜像、Agent、Compose 与 `.env`。移除 AI 功能不需要迁移或改写 `panel-state.json`，也不影响 Agent 宿主机状态。

## 轻量验收

0.42.0 在 154 Debian 13 真机完成发布级 L3、双架构 CGO-free 构建、公开镜像 E2E、隔离 AI 实聊和生产升级。相对发布前主线 0.40.3，同参数 stripped `paneld` 增加 4.06 MiB，两次空闲 RSS 增量为 3.53 MiB 和 3.59 MiB；均低于 30 MiB/25 MiB 目标。两个并行 Mock Run 使用 139.8 MiB/256 MiB，未发生 OOM。

Compose 的 `256M` 内存限制保持不变。完整数据、CI/Release 链接、镜像摘要和回滚证据见 [v0.42.0 发布验收](release-v0.42.0-acceptance.md)。

请求预算同时覆盖可见正文与协议私有状态：上下文读取先在同一 SQLite 快照中计算长度，再复制正文或解密工具状态；可见正文最多 2 MiB，工具私有状态累计最多 4 MiB，并计入上下文压缩估算。超限时仅把完整的旧 Run 归入有界摘要，保留原记录；当前 Run 或仍需使用的旧格式大记录超限会明确失败，不截断隐藏推理、签名或工具参数来继续执行。新工具批次在执行或进入审批前核算该 Run 已有与新增状态，拒绝超限批次后既有结果仍可显示；工具列表也在复制前检查单行和累计预算，防止历史数据绕过限制。

四种协议的原生状态按 JSON 编码后最多 1 MiB；发往 Provider 的完整请求按 JSON 编码后最多 16 MiB，包含控制字符、HTML 字符转义及附件 Base64。单个 SSE JSON 事件、请求编码及读取原生状态另有 16,384 个 JSON Token／64 层结构预算，在展开数组或对象前检查，请求中的原生字段共用额度。编码前完成大小预检，合法的 8 MiB 附件仍可发送；超过预算时提示分批处理，原始会话与附件保留。
