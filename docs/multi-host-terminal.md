# KPanel 多主机终端设计与安全契约

- 状态：已按既有 v2 Noise 与终端请求模型实现；前后端、竞态与双架构自动化验证进行中；完整部署契约及 L3 实机验收待发布前执行
- 页面：`/terminal`
- 支持范围：本机 KPanel、使用新 v2 权限重新配对的远端 KPanel、使用新接入命令注册终端公钥的轻量节点
- 暂不支持：旧 v1 配对、未授予终端权限的旧 v2 配对，以及尚未运行 `terminal-broker` 的旧轻量节点
- 已安装的旧轻量节点只会继续遥测；如需终端，先在节点执行 `k kpanel node uninstall`，在中心删除旧记录，
  再生成新的轻量节点接入命令重新加入。单纯升级二进制不会自动扩展 root 权限。

## 1. 产品交互

用户从左侧“终端”进入后，先看到连接列表：

- 每台主机只显示主机名和一行“节点类型 · 终端状态”：节点类型为“本机”“KPanel”或“轻量节点”，
  终端状态为“已打开”“可连接”“仅监控”或“需重新配对”；不再用“当前 KPanel”代替缺失地址，
  也不把“加密直连”放在可用状态位置；
- 主机地址不占用固定信息行，但仍可搜索，并随主机按钮的完整提示和无障碍名称提供；页面总说明继续明确
  远端终端使用集群加密通道；
- 尚未建立反向终端轮询的轻量节点显示“仅监控”；完成轮询握手后显示“可连接”；旧配对显示“需重新配对”；
- 点击主机行切换到这台主机已打开的终端（优先当前页签，否则最近打开的那个），没有才新开；每个可连接主机的行
  右侧常驻一个"+"（无障碍名称"在 X 上新建终端"），不论该主机是否已有终端，点击都新开一个。同一主机的页签依次标为
  "主机名"、"主机名 2"……，编号在打开时确定，关闭其中一个不会改动其他页签的名字；主机列表显示"已打开 N 个"。
  "+"是主机行内独立于主机按钮的按钮，不嵌在主机按钮里；"仅监控"等不可连接的主机没有"+"；
- 交互终端在所有主机上合计最多 4 个（见第 4 节，批量执行也计入），达到上限时提示"所有主机合计"；关闭页签会同时
  终止对应 PTY；
- 终端工作区通过顶部右侧带图标的下拉菜单选择单屏、左右、上下和四宫格布局。从单屏展开时按顶部标签顺序排列；
  新终端优先追加到后面的空窗格并获得焦点，显式选中空窗格时放入该窗格。布局收窄后，若原活动会话不在可见窗格中，
  则第一个可见窗格成为活动会话，快捷命令随之指向该窗格。切换布局不自动建立连接；空窗格可选择
  主机或新建终端。顶部标签选择已显示会话时聚焦对应窗格，选择隐藏会话时将其放入当前窗格，同一会话只显示一次。
  点击终端或底部预输入框决定当前会话，快捷命令只作用于该会话；选择空窗格时快捷命令不可用。
- 分隔条支持拖动、方向键每次调整 5%、Home/End 调至允许的最小/最大比例、Enter 或双击恢复均分；比例限制在
  25%–75% 内，并为窗格保留至少 280px 宽、150px 高。窗格最大化、返回单屏、
  批量模式往返和窄窗口降级都不销毁终端；工作区不足 640px 宽或 360px 高时只显示当前窗格，恢复尺寸后保留布局与比例。
  关闭终端只有在后端确认成功后才移除，失败保留会话并提供重试。隐藏或零尺寸窗格不发送 PTY 尺寸；重新显示时同步尺寸。
- 主机终端始终在底部显示预输入框；应用、建站、体检和环境任务在脚本等待输入时显示同一套
  预输入框。浏览器本地完成编辑，按 Enter 后整行发送；xterm.js 原生键盘输入仍可用于方向键、
  密码和 TUI，并以 12 ms 短批次合并（低于一帧，快速输入不丢字符），降低高延迟网络中的逐键请求开销；
  主机终端与这四类任务终端的输入都经有序、逐帧确认的流水通道发送，不等上一帧的响应，连续输入和粘贴在
  高延迟网络下明显更快（实测见 [终端与文件传输 v3](terminal-file-transport-v3.md) 第 3 节）；
- 每个终端保留 5000 行浏览器回滚缓冲并显示主题化滚动条；用户位于底部时新输出自动跟随，
  向上查看历史时不强制跳回，标题栏按钮可随时回到最新输出；
- 多主机连接列表使用独立滚动区域，不参与右侧终端的高度计算；主机数量增加时不得挤压终端
  输出区或底部预输入框；
- 连接列表标题与搜索框之间提供普通样式的“批量执行”按钮。进入后，左侧原位置切换为带系统
  图标和主机名称的多选列表，右侧切换为自定义命令输入与逐主机执行情况；按钮不使用强调色、
  胶囊形态或额外动效，也不占用右侧终端区域；
- 批量模式不会销毁已打开的交互终端。返回交互终端时，原页签、输出和焦点仍然保留；搜索只
  影响左侧可见主机，不会取消已经勾选的执行目标；
- 批量执行直接为每台已选主机打开既有认证 PTY，将用户输入的同一条命令发送到各会话并回读
  每台主机的成功、失败、超时与输出。批量队列由 Panel 后台调度，浏览器关闭、刷新、离开终端窗口仅断开查看，
  不取消任务；重新进入批量页恢复活动任务和最近记录。显式“终止执行”取消未启动主机并请求关闭活动会话。
  复用既有终端认证、跨节点 scope 和共享会话限额，不新增 Agent 任意 Shell 接口；命令文本按下一条规则记入共享历史。
  满额仅对明确的 terminal_limit 排队重试；未知的创建/输入结果不重放。关闭确认前不释放名额，失败保留身份，
  Panel 自动重试关闭，重试不占用批量任务的执行入口，也不改写已确认的命令结果；正在执行的批量中，已结束主机的关闭重试同样自动推进，避免余下主机一直等待名额。
  界面只在“执行命令”和“终止执行”之间切换，不提供释放按钮、名额或会话清理提示；终止时同时处理本用户批量任务遗留的临时连接。最多一个活动批量、64 台目标、4 个 worker，任务含排队最长 4 小时。
  按整轮结束后的更新时间保留 24 小时，不按轮数截断，2 MiB 元数据上限不足时拒绝新任务，保存命令名/固定 k 动作摘要（不保存任意参数）、目标、逐主机状态、时间和固定错误码；命令空格前缀排除摘要。
  PTY 原始输出不落盘，仅最近 10 轮每台在内存保留最后 16 KiB（总计最多约 10 MiB），更早记录保留但输出已释放；重启后历史仍可查看，但输出已释放，未完成操作标为中断且不重放。
  Panel/Agent/主机重启不保证继续执行。实现自验与模拟预览不替代隔离真机断网、旧节点和重启验收。
- 终端右侧侧栏分“快捷命令”和“历史命令”两个页签，记住上次所选页签。历史命令是整个 Panel 共用的
  一份列表，不按主机或浏览器分开：按最近使用排序、同一命令只保留一条，每条标注最后执行的主机
  （批量执行标为“批量执行”）和时间，可搜索、单条删除和确认后清空。交互模式点击条目只填入当前终端的
  预输入框供确认，旁边的执行按钮才直接发送；批量模式点击填入批量命令框。预输入框中 ↑/↓ 按最近顺序
  翻阅单行历史，↓ 回到未发送的草稿；触屏设备填入时不自动弹出软键盘；
- 主机终端在提示符下执行的命令自动记入历史：以首次按键时光标左侧的文字作为该行提示符，只有以
  `# $ % ❯ ➜ »` 结尾时才记录；按 Enter 后等 shell 回显换行再读取整行，所以补全、↑ 调出和行内编辑
  按实际执行内容记录，提示符前残留的输出不会被当成命令。脚本菜单、密码提示、数据库/解释器 REPL、
  全屏程序（备用屏）、以空格开头的命令和空行都不记录；续行（PS2）只记录首行。预输入框、快捷命令和
  批量执行发送的命令同样经过这套规则或直接记录。应用、建站、体检、环境任务终端以及容器、文件执行
  终端不记录；
- 输出中的普通文本 `http://`、`https://` 地址可在新页面打开；不接受其他协议；终端输出嵌入的
  OSC 8 任意链接和 OSC 52 剪贴板指令均被拦截。

普通主机终端和桌面命令快捷方式采用内存保留会话：最小化时进程继续运行，刷新页面只断开查看，
重新进入后恢复当前用户的原会话，读取有界内存环形缓冲；超出容量的旧输出明确标记为截断。
沿用 1.26 的窗口关闭交互：关闭普通终端窗口会请求终止该窗口内的会话，关闭命令快捷方式窗口会请求终止对应会话，
关闭普通终端页签也会终止对应会话；不新增“结束会话”按钮。远端未确认时保留窗口、身份和待重试状态。
刷新、页面卸载和最小化不会调用窗口关闭操作，前台与最小化窗口都可在刷新后恢复。保留会话最长 8 小时，
不承诺 Panel/Agent/broker 或主机重启恢复；需要跨重启运行的服务仍使用系统服务或容器。
批量执行由 Panel 后台持有临时会话并持续读取；浏览器不负责其会话关闭。文件执行和容器终端继续使用临时会话。应用脚本窗口复用原后台任务，关闭窗口与结束任务分开。

### 保留会话协议

创建前先做无 PTY 副作用的能力协商：本机复用 Agent 的 `capabilities/input-protocol`，
流式节点复用 `termInputProbe`，v2 节点使用同一 Noise 身份和终端 scope 的 `terminal/capabilities`。
目标须明确声明 `retained:true`；旧能力响应缺少该字段或旧 v2 能力路由返回 404 时，
普通终端按现有逻辑自动使用临时连接，不先向旧节点发送带 `retained` 的创建请求。
没有声明能力的中间版本也使用临时连接，节点更新后恢复后台保留。能力请求失败、鉴权失败或
创建结果不确定仍返回错误，不把通用 502 当作可重放创建的依据。能力响应不授予权限。
旧轻节点轮询协议没有后台能力声明，轮询路径在入队前明确拒绝保留模式，普通终端自动使用临时连接；
后台保留通过已明确声明能力的流式连接提供。

`POST /api/v1/terminal-sessions` 可带 `retained:true`，目标 Agent 或节点必须显式返回保留能力确认；
旧节点拒绝该模式。普通多主机终端仅收到明确的能力拒绝 `terminal_retention_unavailable` 后，
自动尝试一次 `retained:false`，成功后直接进入终端，不追加提示或标识；临时连接失败、网络响应不确定、
通用 `terminal_open_failed`、权限拒绝或达到会话上限时不继续重试。此回退不用于桌面命令快捷方式，不自动重放命令。
`GET /api/v1/terminal-sessions` 仅返回当前登录用户的
保留会话元数据，不返回命令、内部后端 ID 或其他用户会话，也不延长会话寿命。
桌面命令首次启动提交 `shortcutId` 和 `shortcutVersion`，服务端校验当前工作区版本、类型和目标主机，
登记会话后发送已保存的命令；同一用户、同一快捷方式的并发启动与刷新重试返回同一会话。
首次输入结果不确定时标记 `launchUncertain` 并冻结输入，不能自动重放。
重连仍需当前登录、归属校验和远端有效授权；新输入流接管必须序列化并隔离旧流，不能清除不确定写入。
会话映射及输出仅驻留内存，不新增数据库、日志内容落盘或监听端口。

## 2. 链路与信任边界

```text
本机：浏览器 Session + CSRF/Origin → paneld → Agent Unix Socket → 固定登录 Shell PTY

远端：浏览器 Session + CSRF/Origin → 中心 paneld
      → 目标已声明 panel-stream-v3 时：每会话一条 Noise 认证的流式连接（panel-terminal 角色）
        否则：Noise v2 已认证加密请求
      → 目标 paneld → 目标 Agent Unix Socket → 固定登录 Shell PTY

轻量：浏览器 Session + CSRF/Origin → 中心 paneld
       → 流式控制连接在线时：节点回拨的 light-terminal-data 流式连接
         否则：轻量节点主动发起的 HTTPS 长轮询（v2 Noise 加密）
       → root `terminal-broker` → 固定登录 Shell PTY

输出：中心/本机 paneld → 每个浏览器标签页一条 SSE（/api/v1/terminal-stream）
      不可用时回退到 /api/v1/terminal-sessions/{id}/output 长轮询
```

流式连接复用既有 `GET /api/v2/federation/files/stream` 端点与静态密钥，不新增监听端口；
能力协商、回退与连接上限见 [集群监控与联邦协议](cluster-monitoring.md) 的"完整 Panel 流式传输 v3"，
设计与实测对比见 [终端与文件传输 v3](terminal-file-transport-v3.md)。

- 不开放新的 TCP、SSH、WebSocket 或 Agent 公网监听端口；轻量节点也不接受中心入站连接，终端命令只通过其主动 HTTPS 连接返回；
- Panel 继续无特权运行，宿主机 PTY 仅由 root Agent 创建；
- 轻量节点的遥测进程继续使用无登录低权限账户；独立的 root `terminal-broker` 只读取 root-only 的终端 Noise 私钥，复用固定 PTY Manager。遥测 `reporting key` 不进入终端服务，两者之间没有可被低权限进程调用的 root Socket；
- Agent 主服务因文件管理根目录为 `/` 而保持宿主机文件系统可写，Panel 状态目录继续通过
  `ReadOnlyPaths` 独立保护。主机终端仍由 Agent 通过固定参数创建独立 PTY：systemd 使用 transient
  unit，OpenRC 使用 `setsid` 进程组、Agent `CloseAll` 与 Linux parent-death signal 回收；两者以独立生命周期和审计边界提供
  `apk`、`apt`、`dnf` 等系统维护能力；其他 Agent API 仍只能调用各自的
  固定适配器；
- 远端终端只允许已激活且 scope 包含 `cluster.terminal.open` 的 v2 控制端；当前合法 scope 为
  `cluster.summary.read cluster.terminal.open` 或新增文件读取权限后的
  `cluster.summary.read cluster.terminal.open cluster.files.read`；
- 现有 v1 和旧 v2 授权不自动扩权，管理员必须撤销后重新配对；
- 轻量节点终端由独立版本的 root `terminal-broker` 显式提供；服务启动后才通过已认证的 v2 Noise 轮询公布能力，不会因旧节点升级二进制而自动开放入站 Shell。

## 3. 固定 API

浏览器接口：

```text
POST /api/v1/terminal-sessions
GET  /api/v1/terminal-sessions/{id}/output?offset={n}&wait={0..1000}
POST /api/v1/terminal-sessions/{id}/input
POST /api/v1/terminal-sessions/{id}/input-transport
GET  /api/v1/terminal-sessions/{id}/input-stream
POST /api/v1/terminal-sessions/{id}/input-batch
POST /api/v1/terminal-sessions/{id}/resize
POST /api/v1/terminal-sessions/{id}/close
```

终端历史命令（Panel 本机数据，不经 Agent 或联邦链路）：

```text
GET    /api/v1/terminal-history
POST   /api/v1/terminal-history          # 追加：{"items":[{"command","hostId"}]}，按执行顺序
DELETE /api/v1/terminal-history          # 清空；数据损坏时也用于恢复
POST   /api/v1/terminal-history/remove   # 删除一条：{"command"}
```

应用、建站、体检、环境任务终端的输入接口（`kind` 取 `app`、`site`、`diagnostic`、`environment`，只在本机）：

```text
POST /api/v1/job-terminals/{kind}/{id}/input-transport
GET  /api/v1/job-terminals/{kind}/{id}/input-stream
POST /api/v1/job-terminals/{kind}/{id}/input-batch
```

认证、CSRF、帧与窗口与上面的主机终端相同；任务的有序状态由 Agent 持有，差异见
[终端与文件传输 v3](terminal-file-transport-v3.md)。原有各任务的 `…/input` 路由保留给尚未升级的 Agent，
并在流认领后拒绝裸写入。

Panel 间接口：

```text
POST /api/v2/federation/terminal/open
POST /api/v2/federation/terminal/output
POST /api/v2/federation/terminal/input
POST /api/v2/federation/terminal/resize
POST /api/v2/federation/terminal/close
```

轻量节点反向终端使用既有 v2 Federation HTTP 入口的专用反向传输动作：

```text
POST /api/v2/federation/terminal/relay
```

轮询请求和响应均使用既有 v2 `Noise_IK_25519_ChaChaPoly_SHA256` 信封，终端私钥在接入时
单独生成并只保存为 root-only 配置；中心节点公钥和目标节点 ID 由 HTTPS 接入响应固定下来。
反向传输的命令 payload 直接复用既有 `TerminalOpenRequest`、`TerminalInputRequest`、
`TerminalResizeRequest`、`TerminalCloseRequest`，不再叠加第二套终端协议或命令 HMAC。
轮询请求携带当前中心会话 ID 列表和有界事件确认；节点重启或丢失会话后，中心会回收不再出现在
列表中的会话，避免留下不可操作的终端索引。relay 响应还带有中心进程启动 epoch；中心重启
后 epoch 变化，broker 会主动关闭本地旧 PTY，再重新建立会话。旧中心对 v2 relay 返回
404/405/426 时，节点继续保留遥测并延迟重试。

Agent 接口仅位于权限受限的 Unix Socket：

```text
POST /v1/terminals
GET  /v1/terminals/{id}/output
POST /v1/terminals/{id}/input
POST /v1/terminals/{id}/resize
POST /v1/terminals/{id}/close
POST /v1/job-terminals/capabilities/input-protocol
POST /v1/job-terminals/{kind}/{id}/input-sequenced
```

接口不接受浏览器提交的 Shell 路径、启动参数、用户、环境变量或工作目录。Agent 只启动
`/bin/bash -l`，不存在时回退 `/bin/sh -l`，并固定 `TERM=xterm-256color`。systemd 部署环境使用
固定 transient unit 参数；OpenRC 使用由 PTY Manager 跟踪的独立 session/process group，并用
parent-death signal 覆盖 Agent 无法执行优雅清理的退出。应用层统一限制最长运行 8 小时，关闭会话或 Agent 停止时结束会话。

| 已完成输出缓存 | 每个 Manager 最多 64 个、已分配缓冲合计最多 16 MiB；完成后最多保留 5 分钟，读取不续期，超限先淘汰最早完成的输出；未确认清理的进程不参与淘汰 |

| 页面刷新与窗口关闭 | 保留会话刷新时仅断开查看，重开先获取会话列表，列表失败不自动新建；显式关闭窗口/页签请求终止，失败保留窗口供重试；文件/容器等浏览器临时会话卸载发送 keepalive 关闭请求；批量后台会话不随页面卸载关闭 |
| 远端流式终端 | 每会话 1 条连接；输出 3 ms 合并推送；输入/调整尺寸/关闭需确认；断线后按偏移重新附着，6 秒内无法恢复时同一会话继续走 v2 请求；临时会话中心 40 分钟无读取即释放连接；保留会话到 8 小时硬上限 |
| 轻量节点无活动终端轮询 | 25 秒长轮询；有活动会话时 750 ms 轮询（流式控制连接在线时新会话不走轮询） |
| 轻量流式终端 | 每节点最多 4 个并发回拨；临时会话 2 分钟无中心重新附着即关闭 PTY；保留会话受 8 小时硬上限与控制端 epoch 回收约束 |
| 终端历史命令 | 全 Panel 一份，最多 200 条不同命令；单条 8 KiB，单次追加最多 32 条、请求体 320 KiB；存于 `DataDir/terminal-history/history.json`（目录 0700、文件 0600、原子替换）；浏览器在请求进行中合并后续命令，写入失败提示一次后丢弃，不无限重试 |

Panel 公共会话 ID 使用独立 256 位随机值并绑定当前管理员 ID，不向浏览器暴露 Agent 或远端
真实会话 ID。本机会话在 Agent 或 Panel 退出时关闭；远端关闭请求因网络不可达而无法送达时，
由目标 Agent 对临时会话按 30 分钟闲置期回收，对保留会话按 8 小时硬上限回收。审计只保存打开/关闭、目标主机、结果和管理员，
不保存输入、输出、命令历史、环境变量或终端回放。终端历史命令是独立的 Panel 数据：追加不写审计；删除和清空只审计
意图、结果和条数，不含命令文本；历史文件不进入面板备份，回滚或重装不迁移。

## 5. 安全与失败规则

- 显式关闭仅在目标端确认关闭或会话不存在后删除 Panel 索引、记录成功审计并移除页签。Agent/远端错误或
  10 秒关闭超时返回失败审计和 `terminal_close_failed`；保留同一会话身份，用户每次重试最多发出一个关闭请求。
  关闭请求发出后的迟到输出、input/resize 结束状态不得抢先清除关闭身份；临时会话沿用 35 分钟索引过期上限；保留会话在关闭未确认前保留身份。
- 普通交互终端关闭未确认时可由用户确认移除本地页签；此操作不表示远端命令已终止。Panel 保留待清理身份，
  不将其计入交互终端配额，待清理身份全局最多 16 个、每用户最多 4 个；达到上限时不能继续移除。
  新建终端触发有界后台清理，目标确认关闭或不存在后才删除记录；节点不可达时不阻塞其他终端的创建。
  容器终端、快捷命令、网站管理和批量任务不支持此操作。待清理身份与其他 Panel 终端索引一样仅保存在内存中。
  页面刷新时也恢复关闭未确认的临时交互会话，以便用户重试关闭或移除本地页签；不能因此重放命令。
- Agent 先完成进程终止和 PTY 关闭再发布 `closed`；kill/stop 失败可重试，systemd 已回收的 unit 必须经
  `LoadState=not-found` 确认，OpenRC/direct PTY 则以进程组终止结果为准。前端关闭失败显示持续提示和重试按钮，组件卸载仍为捕获错误的 best-effort，
  不等价于真实资源已经回收。普通远端目标需包含此修复才能把 Agent 的已不存在状态规范为加密关闭确认；
  旧远端返回的通用 HTTP 错误保持失败，不推断成功。轻节点 broker 继续复用既有结构化 `closed` 事件。
- 浏览器所有写操作验证 Session、Origin 和 CSRF；跨用户会话查询返回 404；
  历史命令在写入前会遮蔽可识别的密码、Token、Authorization、Cookie 和 URL 敏感参数；自定义格式无法穷举，
  管理员应避免把未标注的秘密直接写入命令。以空格开头的命令不记录，管理员可单条删除或清空。
  提示符识别为启发式，已排除常见密码、菜单与 psql 默认提示符；
  任意自定义提示符不能保证区分 shell 与程序，不将它作为秘密检测。历史文件损坏时停止记录并保留原文件，界面提示后由“清空并恢复”重建，不自动覆盖；
  服务端拒绝控制字符、首尾空白、超长命令和非法主机 ID，整批请求要么全部写入要么全部拒绝；
- Panel 间正文使用现有 Noise IK 身份认证、时间窗和 request ID 防重放，HTTP 链路上不出现
  命令或输出明文；HTTPS 仍执行证书验证，HTTP 字面量 IP 仅承载 Noise 密文；
- 维度、偏移、等待时间、请求体、输入、输出、并发和内存全部有界；
- 终端能力本质上等价于 root SSH。它不是任意 Shell API 的替代品，其他页面仍只能调用固定
  结构化动作，不能复用终端接口拼接后台业务命令；
- 批量执行只存在于终端页面，复用相同的 Session、Origin、CSRF、`cluster.terminal.open` scope、
  会话上限和审计边界；不新增任意 Shell 后端接口，也不宣称 `cluster.system.maintenance` 等并未
  实现的权限；
- 轻量节点终端不等于开放 `sshd`：中心必须先通过接入时绑定的终端 Noise 静态公钥完成 v2
  身份认证；root `terminal-broker` 只在本机 systemd/OpenRC service 中运行，节点不暴露 TCP/SSH/HTTP 监听；
- 网络断开只改变前端连接状态，不把“暂时没读到输出”误判为进程失败；PTY 真实退出才显示结束；
- 远端撤销授权后不能新建终端；既有会话由目标 Agent 的会话上限、闲置时间和进程生命周期回收。

## 6. 验收与回滚

### 网站终端入口

网站页的“终端管理”使用固定 `site-management` 身份打开本机 `k web`。
Panel 只接受这个已登记的本机用途，不接收浏览器提供的命令；启动沿用有界 launch intent、用户绑定、
互斥创建及初始输入确认。刷新或重新打开网站页按原身份附着，不重复执行 `k web`；明确不支持驻留时
复用原启动意图自动打开临时会话，不增加降级提示。普通连接失败或输入确认丢失不会触发新会话或命令重放。
主动关闭需确认终止，失败保留窗口与原会话供重试；页面刷新/离开保留驻留会话，临时会话仍按原规则关闭。

WordPress、PHP、静态站及其他脚本模板共用网站安装后台任务与 `kind=site` 终端。它们已按原任务 ID
恢复输出与交互，关闭建站窗口仅转入后台，保留既有任务超时与日志上限。它们不创建普通 Shell 会话，
恢复不会重新提交建站；无需另建驻留 PTY 或改变任务取消语义。

### 公共查看与控制核心

终端消费者按实际传输路径覆盖，新增入口优先接入已有适配器：

| 消费者 | 公共路径 | 保留的业务责任 |
| --- | --- | --- |
| 本机/远端主机、桌面快捷命令、文件执行、系统包管理、网站管理 | `HostTerminal` → `hostTerminalAdapter` → 公共控制核心和主机输出 pump | 主机授权、启动身份、命令不重复执行、显式关闭 |
| Docker 容器控制台 | 同一主机查看路径，目标由 Agent 容器会话校验 | 容器状态/版本、exec 生命周期、清理确认 |
| 应用安装与脚本、建站、体检、运行环境任务 | `AppInteractiveTerminal` → `jobTerminalAdapter` → 公共控制核心和任务输出 pump | 固定任务动作、任务 ID、窗口关闭不取消后台任务 |
| 后台终端批量执行 | `terminalbatch` → `batchTerminalDriver` → 既有本机/跨节点终端后端；结果经批量记录 API 查看 | 有界并发、准入、取消、清理、未知结果不重放；不经过交互查看器 SSE pump |

两类交互输出 pump 共用突发判断和空读节流：首次输出以及安静一段时间后的输出立即交付，连续突发
仍保留 4 ms 合并和原有字节上限。后端遵守长轮询时不增加等待；忽略长轮询且连续空读时将循环周期
限制为至少 100 ms，取消会立即打断等待。此兼容降级可能增加最多约 100 ms 的后续输出发现延迟，
不应当作正常后端的性能目标。任务流从瞬态失败恢复后，即使没有新字节也通知查看器恢复。
订阅更新先核算完整容量，拒绝超限或重复身份时不取消旧订阅，也不启动部分新 pump。

`terminal_shared_scenarios_test.go` 覆盖共享路径的首块、空读、恢复、取消、突发合并及订阅边界；
`terminal_shared_bench_test.go` 单独测量批量调度到清理完成。微基准只量化相应传输段或模拟执行条件，
不能外推为安装、下载、Docker Engine 操作或浏览器端到端提速；入口创建和业务安全仍由各领域测试覆盖。

`HostTerminal` 与 `AppInteractiveTerminal` 共用 `useTerminalController`，由 `terminalAdapters` 将既有会话和
应用、网站、体检、环境任务接口映射到同一显示、输出订阅、输入队列、重连退避、尺寸确认及暂停恢复机制。
公共核心只附着已有身份，不创建或终止进程；会话包装负责显式关闭和临时会话卸载清理，任务包装卸载仅断开
查看，任务取消继续由业务入口控制。后台任务的固定动作边界和普通 Shell 的授权边界均保持不变。

输出优先复用每标签页 SSE，失败后按已提交字节偏移轮询。相同身份允许多个查看器，共享服务端订阅但各自
维护偏移；新增查看器补读不会重放其他窗口的输出，无法衔接的历史缺口只让该查看器回到轮询。每标签页最多
16 个身份，每身份最多 16 个查看器。隐藏、切换身份或卸载后，旧订阅、旧请求和迟到确认不再影响当前终端。
轮询请求最长 15 秒，超时进入有界退避；401/403 停止自动读取并禁用输入，429 继续短暂退避。

两类终端共用 OSC 8/52 拦截、受检 URL 跳转、可靠输入协议及 12 ms 合并策略。尺寸仅由当前所有者单飞提交，
确认成功后发布，请求失败后最多重试 3 次；未返回的尺寸写入继续等待确认，避免取消请求后远端迟到写入覆盖
更新尺寸。应用任务保留跨窗口请求排序，其他未提供 resize 接口的任务不新增
接口。普通 Shell 的命令呈现不改变命令确认和禁止不确定重放的规则。

### 发布前验证

发布前至少验证：

- 本机 open/output/input/resize/close；用户隔离、CSRF/Origin 和会话上限；

- 轻量节点完整 `open/output/input/resize/close` 生命周期、Noise 密文/身份绑定/重放、旧中心 404 兼容、

- UTF-8 输入、整行预输入、控制键、12 ms 合并、窗口缩放、5000 行滚动、智能跟随、手动回到底部、
  输出截断、断线重连和 URL 安全跳转；
- 普通样式批量按钮的位置与键盘焦点；进入后左侧多选、系统图标和名称，右侧命令输入、逐主机
  状态和输出；返回后交互终端不重建；
- 批量成功、非零退出、终端不可用、会话已满排队、关闭失败重试、4 小时超时、输出截断和页面关闭后继续/恢复；搜索隐藏
  已选主机时仍对该主机执行；瞬态网络抖动在重试上限内时批量结果不判失败；
- 以超过单屏高度的主机和体检命令列表复核独立滚动，确认终端输出和预输入框始终可见；
- 历史命令：真机 bash（含自定义 PS1、补全列表、↑/Ctrl+R、vim/top、sudo 密码、kejilion.sh 菜单、续行）只记录
  实际执行的命令；两个浏览器先后执行后互相可见；删除、清空、损坏文件恢复和 Panel 重启后的保留；
- 从测试 Agent 启动主机终端，验证 transient systemd unit 或 OpenRC 独立进程组、可写系统目录并能运行
  系统维护命令；同时验证应用、建站、体检和环境任务仍只能调用各自的固定适配器；
- 本机 Panel/Agent 退出关闭 PTY；远端关闭成功或链路中断后的闲置回收、过期索引回收均符合约定；
- `amd64`、`arm64`，Chrome/Edge 桌面与移动端布局；
- CPU、内存、连接数和 16 会话上限下的资源预算。

回滚到上一版本不会修改集群状态、网站、Docker 或宿主机配置。新 v2 配对记录中的 scope 会被
旧版本忽略；终端会话仅在内存中，回滚或重启会全部关闭；批量元数据索引由旧版忽略，新版重启仅标记中断，不重放命令。旧版本不读取
`DataDir/terminal-history/`，回滚后历史命令不可见但文件保留；需要彻底删除时先在新版本清空，或手动删除该目录。

Windows 命令行轻量节点候选使用系统自带 PowerShell + ConPTY，直接从现有主机列表打开，沿用会话与批量限额。没有 RDP 选择步骤；平台最低版本、权限、失败和验收范围见 [Windows 节点契约](windows-command-node.md)。
