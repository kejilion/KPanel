- 假设：缺少归档结束契约及唯一安全入口，使历史分支与待发布候选混淆，并让查询失败产生错误收尾状态。

- 证伪条件：下一次稳定发布仍须重新判定全部历史分支，或归档失败仍返回成功。
- 产品原则：不改变业务真源、权限、用户旅程、脚本、镜像内容或产品版本；只处理 Git 引用与工程证据。

## 备选方案与最小改动

只补文案不能修复错误成功和并发删除。全面分支管理平台成本过高，因此复用现有 archive/ 命名、Git 原子
push/expected-SHA lease、既有验收模板与治理测试，替换 release.yml 内联删除。归档指向原 tip，拒绝覆盖
不同 SHA；历史 tag/bundle 兼容，不回填历史记录。授权生产成功与分支收尾分别记录。
