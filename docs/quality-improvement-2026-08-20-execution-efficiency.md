## 原因假设

- 待验证根因：硬规则停留在文档层；发布异常只统计总数，没有以“阶段/权威入口/根因类别”形成稳定
  指纹和复发处置；生产写前仍允许临时拼接跨 Shell 命令和首次发现运行时依赖。
- 可能的替代解释：高频发布和复杂 L3 本身会增加原始异常数；部分网络或上游故障不可由本地预检消除。
- 能证伪本假设的结果：引入检查和复发规则后，管理工作树违规仍无法被检测，或相同可预防指纹继续
  复发且发布用时、误阻断或产品变更失败率明显恶化。
- 是否涉及 `kejilion.sh`、真实系统资源、Panel/Agent 权限边界或兼容契约：不改变上述契约；只约束
  协作和发布控制面。

## 产品原则与核心思想对齐

- 对业务真源和双端互通的影响：无业务行为变化，不建立第二真源。
- 对轻量、低资源、单管理员控制面的影响：新增检查只在任务启动、候选冻结和治理验证时短时运行，
  不增加 KPanel 常驻进程。
- 对安全、稳定、性能、体验、数据/迁移的影响：不降低任何门禁；通过减少生产写后临时修正提高稳定性，
  对产品运行时性能、界面和数据格式无影响。
- 不应引入的复杂度或第二真源：不建设会话台账或常驻协调服务；Git、CI、验收记录继续是真源。

## 最小改动方案

- 预计修改文件或唯一入口：新增 `scripts/check-collaboration-state.mjs` 及测试；其余规范和工作流只引用
  该入口；由现有 `scripts/report-release-metrics.mjs` 校验异常明细 JSON，不增加第二个指标解析器。
- 新增或调整的自动门禁：管理角色必须是主工作树、`main`、clean 且不领先基线；写角色必须使用链接
  task worktree、非 `main`，在启动/验收 checkpoint 可要求 clean；外部 `GIT_*` 不能改变证据来源。
- 异常追溯门禁：`v0.90.2` 起每份新验收记录保留唯一 `kpanel-release-process-incidents` JSON 区块；
  计数为 0/未记录时使用空数组，非 0 时校验固定字段、稳定指纹、总次数及生产写后次数，根因和处置真实性
  仍由非作者复核者读取原始日志判断。
- 跨 Shell 入口：新增 `scripts/run-repo-bash.mjs` 作为解释器适配层；Windows 从当前 Git 安装定位 Git
  for Windows Bash 并清除外部 Git 位置变量，Linux 继续使用系统 Bash。Make 和无 Make 的 Windows
  命令都调用原有 shell 脚本，不复制门禁逻辑。
- 迁移、兼容和失败恢复：管理树落后远端只报告不失败，避免强迫本地 `main` 写入；检测失败只隔离该
  管理树，协调中心仍可从精确 `origin/main` 创建专用 worktree，不清理或覆盖未知改动。
- 防止指标投机或规则自我弱化的约束：不以减少异常计数为目标；不得漏记、合并不同事件、删除测试、
  放宽 fail-closed 或把生产失败改名为流程异常。
- 2026-08-29 复发修正：本地 `verify-change` 在非 CI 环境调用协作检查的 `--role auto`。共享多 worktree
  仓库的主工作树自动应用管理规则并 fail-closed；链接 writer 默认只核对工作树/分支结构，独立验证
  clone 不误判为管理树；调用方传入任务精确基线时再核对祖先关系，避免用已前移的浮动 `origin/main`
  误阻断长期分支。显式写入前检查仍保留为第一道门禁。

### 第二阶段最小改动

- 新增唯一控制侧入口 `scripts/run-release-l3.mjs`：只读核对远端稳定 Tag，拒绝脏候选和 Tag 漂移，
  生成自包含 bundle、固定计划与摘要，并通过 `spawnSync(..., shell: false)` 调用 SSH/SCP，不再由会话
  拼接多层 Shell 字符串。
- 新增唯一远端入口 `scripts/run-release-l3-remote.sh`：计划使用封闭键值协议而非 `source`/`eval`，
  bundle 固定在临时 bare repository 中验证，离线克隆后再调用既有 `scripts/run-release-gate.sh`。
  内层 `make verify-release`、安全扫描、镜像和应用生命周期门禁不变。
- 每次尝试必须使用新 run ID；计划、bundle、脚本、Runner image ID、退出码和日志落入独立证据目录，
  失败证据不可覆盖。重跑仍允许，但能够区分首轮、原因和修复后的新尝试。
- 发布工作流删除 `git fetch origin --tags` 和手写 bundle/远端 wrapper 示例，只引用上述入口；治理测试
  覆盖自包含执行包、脏候选拒绝、Bash 语法、bare-repository verify、退出码保留和禁止 `eval/source`。
- 非目标：不改变业务代码、L0-L3 质量阈值、浏览器验收范围、154/108 边界、生产数据、产品运行监控
  或用户行为埋点；不建设常驻发布服务或第二状态真源。
