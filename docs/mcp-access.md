# MCP 接入与巡检

## 首版范围

在设置中启用 MCP，为每个外部 AI 客户端指定名称、主机和 7/30/90 天有效期，复制一次性连接配置，测试后即可巡检。
功能独立于面板内置 AI，无需设置模型或 API Key。该版本提供本机资源查看与集群摘要；宿主机、Docker、网站、应用的写操作仍由现有管理界面执行。

| 工具 | 能力 | 范围 |
| --- | --- | --- |
| `kpanel_info` | 版本、巡检能力与分页上限 | 当前客户端 |
| `hosts_list` | 已授权主机、连接状态、采集时间 | 显式授权主机 |
| `host_summary` | CPU、内存、磁盘、网络计数和过期标记 | 本机 / 已有集群缓存 |
| `containers_list` | 容器 ID、名称、镜像、运行与健康状态 | 本机 |
| `sites_list` | 域名、类型、启用/健康状态、TLS 到期时间 | 本机 |
| `apps_list` | 已安装应用和运行状态 | 本机 |

远端目前没有完整的容器、网站和应用管理协议，不能通过 Shell 绕过该边界。远端授权客户端发现不到本机资源工具。删除、重新配对或身份改变的主机必须重新授权；新增主机不会继承已有授权。

## 接入方式

MCP 内置于 Panel，使用同一监听端口上的精确 `/mcp` 路径，Streamable HTTP、无会话模式、JSON 响应。
默认关闭，不启动额外服务、端口或后台轮询。协议由固定版本 `github.com/modelcontextprotocol/go-sdk v1.8.0` 处理，工具首次使用时才初始化。

远程连接必须经过真实 TLS，或面板已配置可信代理的 HTTPS 转发。HTTP 仅支持来源与 Host 均为本机回环且无转发头的连接，例如 SSH 隧道。
`SecureCookie` 配置本身不能证明传输安全。反向代理需要转发 `/mcp`；现有安全入口继续保护浏览器登录，MCP 使用独立凭据。

客户端必须支持自定义 `Authorization: Bearer <token>` 请求头。设置页输出通用 `mcpServers` URL/headers 配置；具体客户端外层配置结构可能不同。
首版不提供 OAuth 授权服务器、SSE 旧端点、stdio 进程桥接或客户端安装器；仅支持 OAuth 的客户端尚不能直连。
测试连接只验证当前面板的 HTTP/MCP 协议和凭据，不代表所有外部客户端产品均完成兼容验收。

## 安全与失败行为

- 每客户端随机 256-bit token，只显示一次；磁盘只保存 SHA-256 摘要。凭据不能作为 Panel Session 或 Agent token 使用。
- 授权固定为 `inspect`，绑定 cluster NodeID、host ID、远端身份/创建时间。工具调用复核授权；到期、撤销与全局关闭后的请求被拒绝，撤销期间尚未发送的结果会被丢弃。
- 浏览器管理接口继续要求登录、Origin、CSRF 和资源版本。MCP 不接受 Cookie 代替 Bearer，不接受查询参数 token；存在的 Origin 必须有效。
- 工具只接收结构化固定字段，未注册动作默认不存在；不公开任意 URL、Agent path、Shell、文件、日志、环境变量或原始配置接口。
- 输出通过专用字段投影、文本脱敏与长度限制，主机/资源名称按不可信数据处理；不能保证人为写入名称中的任意秘密都能被启发式识别。
- `stale`、`observedAt` 与 `partial` 显式表达过期或缺失数据。远端巡检消费已有缓存，不增加远端轮询。
- 管理变更与工具访问复用有界审计，记录客户端、工具和主机，不记录 token、输入正文或资源输出；审计不可写时操作失败关闭。
- 授权使用 `mcp-access/access.json`，私有目录/文件、原子写入，损坏或写失败时关闭 MCP 访问。授权状态不在可移植面板备份中；恢复面板身份前清除当前授权，恢复失败也不会重新激活旧凭据。
- 丢失一次性凭据或创建响应不明时，刷新列表核对，撤销对应客户端后新建；不盲目自动重试创建请求。

## 资源预算与生命周期

固定限额：32 客户端，每客户端至多 101 主机（含本机）；授权文件至多 512 KiB；MCP 请求至多 16 KiB、总响应至多 128 KiB、工具数据至多 48 KiB；单页默认 20、上限 50；全局并发 4、单客户端并发 2、每分钟 120 请求；请求与 Agent 调用上下文 10 秒。
本机业务列表仍受既有 Agent 客户端读取上限约束（默认 8 MiB），不是服务端业务数据分页。大规模主机的列表内存和低配主机性能需要候选验收，不能仅凭少量工具数量宣称更省资源。
关闭 MCP 保留客户端配置，重新启用后未过期、未撤销凭据恢复可用；撤销会删除记录，不可恢复。过期客户端可在设置中清理，容量始终有界。

回滚采用原版本程序和既有数据；新增目录不改变老版本账户、集群或 Agent 协议。回滚前先关闭 MCP，旧程序忽略新增目录。
`scriptLinkageState=not-required`：无需发布脚本（不适用），只复用既有只读接口，不修改 `kejilion.sh` 契约。内置脚本固定提交与摘要仍以 `Dockerfile` 为准。

## 竞品复核与取舍

公开资料复核日期：2026-09-19；属于代码/文档分析，未对竞品做部署压测或完整安全验收。

- [1Panel MCP](https://github.com/1Panel-dev/mcp-1panel)：借鉴 Go SDK、独立认证与访问等级；公开 `v1.0.0` 和开发分支的访问限制不能混同。本项目进一步按客户端与具体主机授权，但这不是整体成熟度领先的证明。
- [Portainer MCP 2.45.1](https://github.com/portainer/portainer-mcp/tree/2.45.1)：借鉴服务端实际权限检查、结构化输出裁剪与调用者隔离；不引入其 Python 运行时、大规模 OpenAPI 工具映射或通用 Docker/Kubernetes 代理。
- [宝塔工具参考](https://docs.bt.cn/ai-ops/mcp/tools-reference)：借鉴操作覆盖和使用指引；首版不引入通用 Shell 与高权限工具集合，不据文档推断其部署安全性。
- [官方 Go SDK v1.8.0](https://github.com/modelcontextprotocol/go-sdk/releases/tag/v1.8.0)：复用协议兼容、schema 和传输实现，不自行维护 JSON-RPC 协议栈。

下一阶段在本版验收后增加本机结构化写操作；需要人确认的操作必须由面板保存并消费真实审批记录，客户端布尔值不能充当批准。远端写操作先扩展版本化集群能力协商和固定动作，再开放对应 MCP 工具，不提前展示未实现权限。
