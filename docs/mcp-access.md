# MCP 接入与管理

MCP 是 KPanel 的可选外部 AI 接口，复用现有 Panel、Agent 和集群能力。它不提供模型，不替代 SSH，也不因使用 MCP 协议而天然更安全。已授权的 Docker、系统账户、定时任务或文件修改仍可能具有很高权限；只授予实际需要的主机和业务范围。

## 接入

在「设置 → MCP 接入」启用服务。服务与 Panel 共用监听端口，地址为 `https://面板域名/mcp`。无需额外服务端进程、数据库或端口。

1. 支持 OAuth 的客户端：填写服务地址，在浏览器打开 KPanel 授权页，核对客户端提供的名称和完整回调地址，选择主机、权限和有效期后授权。若尚未登录，先通过您保存的安全入口登录，再返回授权页。
2. 支持 HTTP 请求头的客户端：在设置中创建客户端，选择 Codex、Claude Code、Cursor、VS Code/Copilot、Windsurf/Cascade 或通用 HTTP 格式，合并一次性配置到客户端的个人设置。复制后点击「测试连接」。凭据不会再次显示，不要提交到代码仓库。
3. 仅支持 stdio 的客户端：在 **AI 客户端所在电脑** 安装对应平台的 `kpanel-mcp`，选择 stdio 配置。`command` 可以改为二进制绝对路径；令牌由 `KPANEL_MCP_TOKEN` 环境变量传入，不放在命令行参数中。桥接进程随客户端启停，不需要宿主机 Agent 或 SSH 权限。

可选桥接的本地构建入口是 `make build-mcp-clients`，生成 Linux/macOS/Windows 的 amd64/arm64 二进制。Release 工作流已包含这些附件及校验和；本地候选提交不代表已经发布附件。

远程连接要求实际 TLS，或配置可信代理后的 HTTPS 转发；HTTP 仅允许本机回环。反向代理需转发 `/mcp`；使用 OAuth 还需转发 `/.well-known/oauth-protected-resource`、`/.well-known/oauth-protected-resource/mcp`、`/.well-known/oauth-authorization-server` 和 `/oauth/*`。不要把这些协议入口重定向到交互登录页。浏览器安全入口继续保护登录，MCP 不使用登录 Cookie 代替访问令牌。

原生 OAuth 使用授权码、PKCE S256、精确回调与资源受众绑定、轮换刷新令牌。它支持动态客户端注册；不获取外部客户端元数据文档，不提供隐式授权、密码授权或旧 SSE-only 端点。特定 AI 产品能否使用远程连接器还取决于该产品版本、账号和网络条件。

## 权限与集群

- **基础巡检**：保留原六工具语义，读取已授权主机摘要及本机容器、网站、已安装应用的精简信息。
- **资源查询**：选择系统、Docker/Compose、网站/Web 环境、应用、诊断、文件、备份等范围。文件需另选绝对目录。
- **资源管理**：在查询范围内开放既有结构化操作；默认由管理员在设置页审批。可另选日常启停和固定诊断自动执行，其他修改仍需审批。

授权绑定具体主机身份及操作 schema 摘要；新增主机或升级后新增/变化的操作不会自动加入旧授权。原巡检凭据不会升级成管理凭据。需要扩大权限时撤销并重新创建。

远端完整管理需要两端均支持新协议，且在 **被控节点** 的「允许其他 KPanel 管理本机」明确授权已配对控制端。写入授权意味着信任该控制端执行所选操作，客户端授权和人工审批由控制端负责。仅完成集群配对不会获得管理权限。轻节点和旧版本节点继续提供其已有摘要能力；`host_capabilities` 返回实际可用范围。

## 常用旅程

先调用 `kpanel_info`、`hosts_list`，再对具体主机调用 `host_capabilities`。工具发现会根据当前授权过滤。客户端可以用自然语言提出请求，例如「查看授权主机的运行状态」或「重启这台主机上的 nginx 应用」。实际执行仍由结构化工具参数和服务端授权决定。

写操作应先读取资源的当前版本，再调用对应工具并提供唯一 `requestKey`。返回 `pending` 后在 KPanel 审阅具体主机、动作和参数，点击「批准并执行」。连接中断时复用原 `requestKey`，查询 `operation_status`，不要重新创建一个不同请求。

| 返回状态 | 含义和下一步 |
| --- | --- |
| `pending` / `approved` | 等待审批 / 已批准；必要时用原 operationId 和 digest 调用 `operation_execute` |
| `executing` | 已接纳，正在派发或等待业务响应 |
| `submitted` | 真实后台任务已受理，尚未完成；查询 `operation_status` 或对应业务任务 |
| `succeeded` / `failed` | 已取得业务回执或任务终态；部分文件操作失败也返回 failed，应检查具体结果 |
| `unknown` | 无法确认结果；先核对资源及原任务，不能据此盲目重发 |
| `rejected` / `expired` | 被拒绝或审批过期，原批准不可继续使用 |

应用、网站、Web 环境、诊断的交互任务按其真实 task owner 提供有界输出和适用的输入/取消。取消不代表回滚。系统维护 ID 与原任务保持一致；重启等没有可恢复 task ID 的受理结果会要求核对主机状态，不伪装已经完成。

文件列表使用 Agent 的 `offset`/`limit` 和真实 `nextOffset`；其他支持列表分页的工具使用 `pageOffset`/`pageSize`。文本写入上限为 16 KiB。回收站仅列出和操作原路径位于授权目录内的条目，需传入当前资源版本；不会提供跨目录的整站清空。二进制上传下载、完整文件编辑和交互终端继续使用现有界面，不通过模型上下文传输大文件或任意宿主机 Shell。

备份支持清单、可用模块、导出、任务查询、恢复前预览、恢复与失败恢复。加密备份包上传下载使用现有已登录备份页。恢复 Panel 数据会撤销 MCP、OAuth 和集群管理授权；重连前需在恢复后的 Panel 重新授权。恢复失败也不重新激活旧凭据。

## 边界与资源预算

默认关闭；无额外服务端监听和定时轮询。协议复用固定 Go SDK。请求凭据、主机身份和业务范围在服务端检查；审批只能从登录态、Origin/CSRF 保护的界面提交，模型传入 approved/confirmed 不构成批准。

固定预算：最多 32 个客户端，每客户端最多 101 个主机；普通授权文件 512 KiB。MCP 请求 128 KiB、总响应 128 KiB、单工具数据 48 KiB；单页最多 50 项；全局请求并发 4、单客户端并发 2、每分钟 120 请求。读取上下文 10 秒；写 worker 同时最多 2 个、每个最多 10 分钟，无无界队列。集群操作复用已有加密身份、防重放通道，单条管理载荷 48 KiB。

持久操作最多 64 条，保留期 7 天；执行中或已受理任务不按时间直接丢弃。参数/回执各最多 96 KiB，总明文预算 16 MiB，磁盘使用独立密钥加密；容量满时拒绝接纳新操作，已执行操作有预留回执空间。OAuth 的客户端、授权请求、code、刷新族均有独立数量和有效期上限。

读取结果执行裁剪、敏感字段屏蔽和文本脱敏；这不能保证识别人为写入任意名称或日志的所有秘密。发给外部 AI 的已授权数据仍会进入该客户端及其模型处理链路。审计只记录调用者、工具、主机和结果，不保存原始输入、凭据或资源正文。

关闭 MCP 会拒绝新请求并使尚未执行的批准失效；已接纳业务任务应到其实际任务页面核对。撤销客户端或目标侧授权后，新操作被拒绝；已经交给 Agent 的任务不承诺撤销等同取消。

`scriptLinkageState=not-required`：沿用已有脚本和业务契约，不需要发布脚本。内置脚本仍为 `6ebb945f6d5cb69fdb41e3761de23566acbaf762`，SHA-256 `28cf3934c01fe79a19c51fac520f11a2bdd7656d762f37d6fc4153140a6df549`。回滚前关闭 MCP，再使用原版本程序；新增文件不会成为旧程序的业务真源。
